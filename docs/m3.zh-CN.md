# M3：WebDAV 后端预览

[English](m3.md) · [M2 配置与文件 API](m2.zh-CN.md) · [验收证据](evidence/m3/README.md)

M3 增加独立受监管的 HTTPS WebDAV 进程、各存储域持久化 DAV 属性与锁、协议清单，以及离线元数据备份恢复。当前是面向已测试 Linux/ext4、Windows/NTFS 主机的本地后端预览。FTP/FTPS、SMB、NFS、Docker、磁盘管理、自动更新与 WebPanel 尚未实现。

## 启用和使用

按 M1/M2 指南获取锁定依赖并构建，使用 `python3 scripts/run_m3.py --compiler gcc` 验证。Windows 使用 `python scripts/run_m3.py --compiler msvc`；Clang 使用 `--compiler clang --mode debug --sanitizers`。Linux 独立合规验证需 OpenSSL/Expat 开发包，先运行 `python3 scripts/fetch_litmus.py`，再传入 `--litmus build/litmus/installed/bin/litmus`；脚本锁定了测试工具源码 SHA-256。

测试仅创建临时数据，不安装系统服务、不修改真实磁盘。发布构建的 `--large-mib 257` 用于证明传输文件可超过 256 MiB 工作进程硬分配上限，并非超过主机物理内存。

执行 `taucloud_ctl --state <state> init` 后，停止 supervisor，在 `config.json` 增加 `"dav_port":8444`。端口须至少 1024，且与管理端口不同；缺省或 0 禁用监听。正常启动 supervisor，通过 `/api/v1/protocols` 和 `/api/v1/services` 查看状态。M2 文件数据库会从 schema 1 升级到 2，并保存 `<worker>.pre-v2.db`；升级后不可直接降级运行 M2。

通过 M2 API 创建用户、根和空间，再由管理员向 `POST /api/v1/shares` 提交：

```json
{"id":"documents","space":"alice","exposures":{"webdav":"rw"}}
```

修改共享时提交完整定义并加上 `"update":true`，响应前会推送撤销策略。`"r"` 为只读；空 exposures 对象关闭该共享的所有协议访问。核心 API 与 DAV 可以共同写入，因为它们在同一文件工作进程内执行 DAV 锁检查；其他可写协议组合仍然禁止。配置尚未实现的协议 exposure 不会创建对应服务器。

地址为 `https://127.0.0.1:8444/dav/documents/`。支持 TLS 上的 Basic 用户名/密码及文件范围的 CLI Bearer token，拒绝 Cookie 和浏览器 Origin 请求。客户端须显式信任 `tls-cert.pem`，不应为真实数据关闭证书校验。自动生成的本地证书有效期 30 天。监听仅限回环；远程部署、公有 PKI、反向代理、桌面自动发现不属于当前预览。

```sh
curl --cacert <state>/tls-cert.pem --user alice --upload-file local.txt \
  https://127.0.0.1:8444/dav/documents/local.txt
curl --cacert <state>/tls-cert.pem --user alice -X PROPFIND -H 'Depth: 1' \
  https://127.0.0.1:8444/dav/documents/
```

## 协议行为与边界

已记录的 litmus 0.18 basic/copymove/props/locks/http 共执行 105 项，全部通过后声明 DAV Class 1/2。litmus 对 HTTPS 跳过的 Expect 测试由 Python 验收覆盖，包括鉴权失败和条件失败时不能先发送 `100 Continue`。这不代表所有桌面客户端均兼容；实际客户端结果见[证据表](evidence/m3/README.md)。

支持 OPTIONS、GET、HEAD、PUT、MKCOL、DELETE、COPY、MOVE、PROPFIND、PROPPATCH、LOCK、UNLOCK。死属性持久保存命名空间、XML 内容与属性；属性修改原子执行，受保护属性失败返回 403/424 多状态响应。COPY 复制属性，MOVE 保留属性；集合可递归删除。复制、移动和删除使用持久任务日志，工作进程重启后恢复发布。COPY 限同一共享/空间，每次最多 16 MiB 文件内容；跨共享/卷移动拒绝。

PUT 在接纳正文前完成身份、路径、配额、锁和条件检查，先预留配额，再分块写入暂存文件，完成后发布。支持已知长度和 chunked 正文。断线取消 DAV 上传；清理专用路径可使用过期但签名有效的授权证明，仅关闭该用户的句柄或取消自己的未发布 DAV 任务，不能读取或发布文件。DAV 暂存任务在 15 秒无持久进度后由下一次存储域请求回收，存储域重启后重新挂载时取消。M2 核心 API 的可恢复上传策略保持原有行为。下载同样流式执行，取消后释放句柄。

GET/HEAD 提供 ETag 和 Last-Modified；GET 支持单段与后缀 Range、206/416 和 If-Range。多段 Range 忽略并返回完整表示。If-Match 使用强比较，If-None-Match 使用弱比较，日期支持 IMF-fixdate。仅 HTTP/1.1，每连接一个请求并关闭；不支持压缩或 HTTP/2。拒绝重复头、冲突正文长度、未知传输编码、非法路径、DTD/实体、非法命名空间和过深 XML。

| 资源 | 上限 |
| --- | --- |
| 连接与阻塞执行 | 32 或更低配置值；4 个线程，32 个排队任务 |
| 请求头／流式块 | 16 KiB、64 个字段／64 KiB |
| PUT／XML 正文 | 1 GiB（同时受配额限制）／64 KiB |
| TLS 握手／请求头／I/O 空闲 | 分别 5 秒 |
| XML／属性 | 深度 32、4096 个节点；每次 128 个属性编辑，每对象属性总计 64 KiB |
| PROPFIND | Depth 0/1；缺省或 infinity 返回 `propfind-finite-depth` 403 |
| 递归操作／目录扫描 | 每次 256 个对象；底层目录扫描最多 4096 项 |
| 锁／有效期 | 每空间 256 个；1–3600 秒 |
| 保留任务 | 每空间 4096 个；到达限制需维护与恢复 |

独占/共享写锁支持 Depth 0/infinity、续期、发现、超时与 token/所有者校验。锁跨进程重启保留到绝对到期时间；备份恢复会清除锁。DAV 和核心 API 写入均受保护，包括父集合成员变化及目标覆盖。操作系统管理员或外部写入可以绕过服务锁与配额；仍适用 M2 的可信本机账户、单卷存储根边界。

名称采用 UTF-8 NFC，并拒绝 Unicode case-fold 冲突；非 NFC 输入直接拒绝，不静默改名。仍拒绝编码分隔符、穿越、NUL/控制字节、Windows 设备名、尾随点/空格、备用数据流及 `.tc-` 名称。单组件最多 120 个 UTF-8 字节，路径最多 1024 字节。这是跨平台子集，并非全部 ext4/NTFS 名称。文件访问相对已固定根句柄执行，不跟随链接/reparse point，并通过原生对象 ID 检测替换。

## API、CLI 与恢复

`GET /api/v1/protocols` 返回实现状态、启用状态、回环监听、TLS 和 DAV classes；`/capabilities` 报告 M3 与 `portable-utf8-nfc-v1`。用户、组、成员关系、根、空间、共享和授权继续使用对应 GET/POST 资源接口。监控为 GET `/monitoring`，服务为 GET `/services` 与 POST `/services/restart`。文件任务与取消使用 POST `/files/jobs`、`/files/cancel_job`，携带 space/path。所有接口可由 `taucloud_ctl --state <state> call --path /api/v1/...` 调用，POST 加 `--method POST`，JSON 从 stdin 读取。详见 [OpenAPI](openapi.json)。监听端口通过停止后编辑配置并重启修改，不提供运行时 API 开关。

元数据备份/恢复是离线本地所有者操作。先停止整个 supervisor；备份持有 supervisor 与所有工作进程所有权锁，拒绝运行中的服务和未完成文件任务。先完成/取消上传并处理不确定任务。

```sh
taucloud_ctl --state <state> stop
taucloud_ctl --state <state> backup --output <新的备份目录>
taucloud_ctl --state <不存在的新状态目录> restore --input <备份目录>
```

备份使用 SQLite snapshot、版本化清单与 SHA-256 校验，包含用户和密码校验值、授权、空间/共享、文件对象 ID、已完成任务、审计与 DAV 属性。备份目录仅所有者可访问，但**未加密**，应存入独立加密且访问受限的备份介质。校验和用于发现损坏，不防恶意篡改；只恢复可信备份。

它不是文件数据备份：不复制文件正文、暂存文件、TLS 私钥、IPC 密钥、CLI token 或有效会话。恢复先在新的私有同级临时目录验证，成功后发布到不存在的状态目录，不覆盖已有状态。它生成新的 TLS/IPC 身份、撤销会话、清除 DAV 锁。客户端须重新登录并信任新证书，或在停止状态下配置另行管理的 TLS 身份。

当前仅支持恢复到**原生卷、根与对象 ID 未变的原始数据**。文件数据须与离线元数据快照一致；应另外保留原盘或原生文件系统快照。将文件复制到替换磁盘会改变对象 ID，因此会被拒绝；跨主机/对象 ID 重映射及文件数据恢复导入器尚未实现。不可让旧状态和恢复状态同时访问同一根。完成恢复演练前保留原状态及协调一致的文件数据备份。

实现决策见 [ADR 0006](decisions/0006-webdav.zh-CN.md)。本地 HTTP 适配器直接使用锁定 PACE 的 TLS 流式原语，不修改 vendor 源码。新增 pugixml 1.15、utf8proc 2.11.3（MIT），版本和源码摘要记录于 `dependencies.lock.json`。标准与测试参考：[RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html)、[RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html)、[litmus](https://notroj.github.io/litmus/)。
