# 0005 — M2 有界文件配置档

[English](0005-m2-file-profile.md)

状态：已实现，2026-10-29。补充决策 0002/0003，不宣称后续协议合规。

M2 使用既有 PACE HTTPS 与有界阻塞桥，提供每块 128 KiB 的核心 API，不依赖尚待完成的 WebDAV 流式集成。每个原生卷分配一个文件进程，独占 SQLite、句柄、锁表和配额，初期提供四个域。共享别名共用基础权限与计费对象；管理角色不隐含文件权限。策略变更推送排空及确认，失联时由最长两秒的签名租约兜底。

初始命名规则在两种宿主均明确拒绝非 ASCII 名称和大小写冲突。使用根目录相对原生句柄，拒绝重解析点、符号链接、硬链接别名，并限制每卷一个注册根，避免命名空间暗中冲突。不接管已有内容的目录。Unicode 规范化、更多存储域、已有目录接管、目录变更与跨卷复制删除任务，需要后续显式扩展和测试。

整文件发布使用持久化意图与原生原子重命名，覆盖发布前后两个崩溃点的身份核对。随机写记录不确定结果，不在原生写入与 SQLite 之间虚构恰好一次语义。配额明确为服务层逻辑计费，外部宿主写入不受其强制约束。Windows 文件数据 flush 不代表目录突然断电持久性。

磁盘标识只有真实采集到才提供；健康信息区分不可用、无权限、过时和有效测量，设备名不冒充稳定 ID。监控 RPC 截止时间限制调用者等待，卡住的原生调用由工作进程监督隔离。

验收覆盖两种原生宿主、双用户隔离、撤权、文件进程崩溃、磁盘满与短写注入、64 位偏移，以及大于工作进程硬内存分配预算的文件。该实验用于证明有界传输，不要求制造大于开发工作站全部物理 RAM 的文件。报告记录文件大小和确切限制机制，并明确未宣称后者实验。

实现约定见 [M2 指南](../m2.zh-CN.md)，验证见[验收证据](../evidence/m2/README.zh-CN.md)。该版本仍是使用单个可信 OS 账号的本地后端预览，不包含恶意同账号进程沙箱，也未启用外部文件协议。
