# ADR 0004 — Native storage, verified updates and SMB feasibility

[简体中文](0004-storage-updates-smb.zh-CN.md)

Status: accepted. On 2026-10-29 the user removed the port-445 M0 gate; functional interoperability evidence suffices.

## Disk and RAID administration

Choose Linux kernel MD through typed `mdadm` operations and Windows Storage Spaces through typed PowerShell/CIM adapters. Start with two-member mirrors, not parity RAID or hardware controller management. Provider versions must be recorded with the disposable M8b test image; M0 does not install providers or operate disks.

The test fixture is a separate disposable VM with three newly created 2-GiB data disks (two members plus replacement), a separate OS/state disk and a snapshot. Linux may additionally use three loop devices backed exclusively by newly created sparse test files; Windows uses test-only VHDX files attached to that VM. Allocation/attachment requires a fixture manifest naming only those files and stable native disk IDs. Never infer disposable status from a drive letter, device enumeration index or an empty partition table. Test native mirror creation, one-member loss, replacement, rebuild, check, restart reconciliation and teardown before representative hardware validation.

Preview returns provider/version, topology revision/hash, stable device IDs, intended layout, erasure ranges, affected shares/jobs/containers, expected downtime and irreversible steps. Confirmation binds administrator identity, the entire plan digest, a one-use nonce and a five-minute expiry. Re-enumerate topology immediately before a serialized mutation; changed identities, new consumers or OS/state disks invalidate approval. The privileged helper receives an allowlisted typed operation with those exact IDs, not user-supplied shell text. Before mutation quiesce affected owners and acquire a maintenance lock shared with updates. Persist native operation/job identity before submission where possible; after timeout/restart query the provider, never blindly repeat create/format. Cancellation stops future steps and reports already irreversible work. Recovery states include needs-reconciliation, degraded and administrator-required.

## Update contract and experiment

`updates.py` generates disposable Ed25519 keys, signs manifests, verifies against an independently provisioned public key, checks payload digest/component/version/sequence/path and IPC range, and stages side-by-side versions. SQLite FULL transactions hold the active-version pointer and transition journal; files are flushed before the pointer changes. A process exits without cleanup at five transition boundaries; restart reconciles to the old or verified new version. Corrupt signatures/payloads, unsafe paths, incompatible IPC, failed health and unsafe rollback after a new write epoch are tested. Version negotiation is also exercised by separate IPC worker processes accepting v1/v2 and rejecting v3.

The prototype's payload and health check are fixtures, not executable installation. Public-key rotation, anti-rollback counters across installations, helper handoff, schema migration, supervisor reparenting and OS-level power-loss persistence belong to M8c. Never infer those from process termination tests. A real update must drain, fence the old storage owner, acquire exclusive ownership for the new generation and authenticate readiness before commit. If new-schema/new-data writes occurred, automatic metadata rollback is prohibited; report recovery-required and preserve both versions and backups. No general “zero downtime” promise is made.

## SMB experiment and credential boundary

`smb.py` verifies the published MS-NLMP NTOWFv2, proof and session-key vectors, plus SMB 2.1 signed CREATE validation. NT-hash enrollment uses OpenSSL's legacy MD4 only in the Linux fixture and CNG on Windows. Management password verifiers are deliberately different; they cannot answer an NTLM challenge. Production SMB enrollment must be explicit, held by the identity service, encrypted at rest using the host secret store, audited and independently revocable. NT hashes are password-equivalent secrets and must not enter logs or ordinary control-database backups.

`smb_interop.py` is an original, loopback-only protocol slice: SMB 2.1 negotiate requiring signing, bounded SPNEGO/NTLMv2 session setup, one fixture share, signed open/close and tamper rejection. Independent clients provide wire interoperability; the fixture server imports no client-library implementation. It is not the future C++/PACE server and is not general SMB support: MIC/channel binding, credential vaults, durable handles, locks, compound operations, enumeration and ordinary file operations remain gated by M5. Never expose this experiment to a network or real accounts. Test credentials are Microsoft's public example values.

Windows observation: native SMB occupies TCP 445 through PID 4 and a wildcard listener. The read-only host probe attempts an exclusive bind and checks a disposable alternative loopback listener; it never disables a service, changes firewall rules or removes shares. Native SMB does not allow its TCP listener to move to another port. Windows 11 24H2+ clients can explicitly map alternative TCP ports, but this does not establish universal client compatibility. Therefore ordinary-port deployment requires a dedicated disposable Windows host/VM with an administrator-approved service configuration and an actual native-client test. That experiment is not performed on the user’s existing host and, by explicit user decision, is not an M0 gate. First usable backend scope stays M3 WebDAV; Windows native SMB support remains conditional on this gate.
