# ADR 0008 — SMB 2.1 权威边界与凭据保护

下述原始“不支持阻塞锁队列”限制已由 Full SMB/NFS 扩展更新：现已实现有界异步等待、取消和生命周期清理，当前行为与固定提交证据见 M5 指南。其他历史范围排除不构成省略完整兼容性工作的许可。

[English](0008-smb-profile.md)

状态：已实现为有界后端预览，完整客户端矩阵验收仍待完成。

SMB 引入长期打开的句柄、共享模式、字节锁和等同密码能力的 NTLM 材料。隔离的 PACE 进程仅持有协议会话；身份服务负责 NTLMv2/MIC 和 AES-GCM 保险库；现有文件工作进程统一负责访问、共享、锁与删除状态。协议进程只取得短期内部会话和签名密钥。管理密码的 Argon2id 校验值不能转换为 NT hash，因此必须单独明确登记。

强制签名及 MIC，不协商降级方言，不授予缓存或 durable handle。OpenSSL 提供密码学原语，不放宽 TLS 算法策略。Linux 用服务账户边界保护保险库密钥，Windows 使用用户 DPAPI。元数据恢复故意清除 SMB 登记，避免跨宿主/账户迁移等同密码的材料。

以原生对象身份持久化删除意图，协议恢复清除易失打开状态。复合请求执行前验证全部签名，每次文件操作重新授权。对未支持的 ACL 修改明确失败，不伪造持久 Windows 安全语义。仅实现认证后的 `srvsvc` NDR32 共享枚举，所有结果再次通过文件授权。

代价是明确限定的兼容范围：回环及替代端口、无 SMB 加密、无任意桌面元数据保留、无阻塞锁队列、不移动含打开后代的目录、无通用管理 RPC。独立客户端及宿主结果见 [M5 指南](../m5.zh-CN.md)和[验证记录](../evidence/m5/README.md)，不宣称等同 Samba 或 Windows 文件服务器。
