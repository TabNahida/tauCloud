# M2 身份、策略与文件核心

[English](m2.md) · [API 定义](openapi.json) · [验收记录](evidence/m2/README.zh-CN.md)

M2 实现用户与组、私人及团队空间、共享策略、四个独立存储域进程、持久化文件操作和原生监控。本地 HTTPS API 与 C++ CLI 已能实际传输文件。WebDAV、FTP、SMB、NFS 服务器仍属于后续里程碑，能力接口不会宣称这些协议可用。M0 验收不依赖 445 端口。

## 构建与使用

依赖获取、初始化、管理员引导与登录沿用 [M1](m1.zh-CN.md)。M1 身份库从 schema 2 迁移至 3，迁移前以 SQLite 备份到 `identity.pre-v3.db`；supervisor 在持有所有者锁时补齐新文件进程的 IPC 密钥。需要同时更新所有服务二进制，不支持混用 M1/M2。xmake 的 `--m1=y` 选项构建包含 M2 的累计后端。

```sh
python3 scripts/fetch_pace.py
python3 scripts/fetch_pace.py --dependency recipes
python3 scripts/run_m2.py --compiler gcc --large-mib 257
python3 scripts/run_m2.py --compiler clang --sanitizers
```

Windows 使用 `python scripts/run_m2.py --compiler msvc --large-mib 257`，或通过 `scripts/windows_m2.ps1` 在独立 NTFS 临时目录中使用参考工具链。运行器包含 M1 回归。大文件测试把工作进程的内存分配限制为 256 MiB；Linux 硬限制不能与 ASan 的影子映射同时使用。测试使用临时目录和任意回环端口，不注册服务。磁盘满故障钩子仅编入测试程序，不进入服务二进制。

管理员以 `--scope admin` 登录后，注册现有绝对路径根目录，再创建新空间。沿用 M1 中的 `BIN`、`STATE` 变量：

```sh
printf '%s' '{"id":"data","path":"/absolute/existing/root"}' | "$BIN/taucloud_ctl" --state "$STATE" call --method POST --path /api/v1/storage-roots --request-id register-root-0001
printf '%s' '{"id":"private","root":"data","path":"private","owner":"admin","quota":1073741824}' | "$BIN/taucloud_ctl" --state "$STATE" call --method POST --path /api/v1/spaces --request-id create-space-0001
"$BIN/taucloud_ctl" --state "$STATE" put --space private --path example.bin --file /absolute/input.bin --request-id upload-example-0001
"$BIN/taucloud_ctl" --state "$STATE" get --space private --path example.bin --file /absolute/new-output.bin
"$BIN/taucloud_ctl" --state "$STATE" call --method GET --path /api/v1/monitoring
```

Windows 根路径使用 `C:\\taucloud-data` 这样的原生盘符路径。创建用户时将密码放入标准输入 JSON，通过 `POST /users` 提交，不写入命令行参数。普通用户写文件时以 `--scope files` 登录；默认仍是 `read`。通用 `call` 从标准输入读取 POST JSON；字段与错误见 OpenAPI。

## 授权与存储域

管理角色 `admin/member` 与文件权限独立，管理员不会自动获得其他用户文件的访问权。空间只能有一个用户所有者或组所有者；所有者及所属组成员默认读写，可额外授予用户或组 `r/rw`。空权限表示移除该授权，权限按并集计算，不是拒绝型 ACL。禁用用户或修改其管理角色会清除会话；修改成员关系或文件授权会撤销旧文件授权。

身份进程独占策略表，每次变更记录请求幂等键、操作者审计与递增策略版本。提交后向四个文件进程推送撤权，每个 ACK 等待最多 250 ms。文件进程在串行操作完成后清除句柄和锁再确认。未确认显示 `pending`；签名授权最长两秒，过期后拒绝新操作。已经提交给内核的调用不能因租约过期而回滚；只有完成排空的 ACK 才证明旧操作全部结束。重试已提交的策略请求会再次推送撤权。

根目录绑定原生对象与卷身份。首个配置档限制为**每卷一个根、最多四卷**，分配至 `file`、`file_1`、`file_2`、`file_3`。拒绝嵌套空间所有权、状态目录重叠、整卷根目录、根替换、挂载/重解析点/符号链接穿越及普通文件硬链接。空间目录必须新建，不能直接接管已有内容。共享别名沿用基础空间的 ACL、对象身份和配额，只可收窄到子目录及协议暴露范围，不能扩大权限。同一空间所有别名及直接核心访问只能有一种可写协议；配置某协议的暴露策略不会启动尚未实现的协议服务器。

Linux 使用根句柄下的 `openat2`，禁止符号链接、magic link 与跨挂载回退；对象身份包含设备、inode 和创建时间，文件系统必须提供 `statx` birth time。Windows 使用相对目录句柄的 `NtCreateFile`、`NtSetInformationFile`，拒绝重解析点，并保留不允许删除共享的祖先目录句柄；仅支持本地盘符路径及原生文件 ID，不支持 UNC 根。

管理空间内的命名规则是 **portable-ascii-v1**：可打印 ASCII、保留大小写但拒绝大小写别名、每段不超过 120 字节、路径不超过 1024 字节。Unicode 名称明确返回 `unsupported_name`，不进行隐式规范化或有损转换。拒绝 DOS 设备名、备用数据流、尾部点/空格、路径穿越及 `.tc-` 保留名称。

安全边界仍是专用 OS 账号和私有状态目录；进程隔离用于限制故障，不能隔离能读取共享 IPC 密钥的恶意同账号进程。外部宿主写入不属于锁和配额的统一管理范围，不应同时用其他工具操作受管文件。路径校验不能把可信 OS 账号变成对抗性沙箱。

## 文件与恢复语义

| 领域 | 实现行为 |
| --- | --- |
| I/O | 阻塞原生操作在有界 RPC 工作线程中执行。每次读写最多 128 KiB，支持 64 位偏移，短读写返回实际字节数。HTTPS 使用连续、有界的 JSON/hex 块，不宣称 WebDAV 流式能力。IPC 帧与文件 HTTP 请求体最大 512 KiB，其他请求体及头仍为 8 KiB。API 阻塞桥为 4 线程、32 任务、16 MiB 预留。 |
| 句柄与锁 | 每域最多 128 个不透明句柄、256 个字节区间写锁，绑定用户、空间、路径和进程代次。对象 ID 跨重命名与重启保持；重启后旧句柄及锁失效。锁阻止其他句柄的重叠写，读仍允许。删除和暂存替换要求先关闭句柄；重命名更新打开句柄的路径。暂不支持目录重命名、目录删除。 |
| 配额 | 按逻辑长度及未完成上传的全额预留计费，别名不重复收费。替换期间同时计入旧文件与新预留；随机扩展先检查额度，串行权威进程记录不确定写入并在恢复时核对实际长度。稀疏洞也计入逻辑长度。报告 `service_enforced`，外部写入可能绕过，不宣称内核强制配额。 |
| 整文件上传 | `begin → chunk → commit`，隐藏暂存、每块显式 flush、顺序偏移；重放块须与已记录字节一致。持久化进度支持重启续传，`cancel_job` 删除确认归属的暂存文件并释放预留。CLI 有界计算源文件 SHA-256，幂等续传拒绝不同源内容。 |
| 发布 | 原生原子重命名前持久化提交意图；重启按暂存与目标的原生身份核对，覆盖发布前后两个崩溃点。文件重命名、删除任务同样可恢复；完成的请求重放原结果，冲突键被拒绝。 |
| 随机写 | 原生写入前记录意图，成功后将元数据、结果、审计一并提交。`flush:true` 显式要求持久化文件数据。不确定结果返回 `uncertain_write`，不盲目重写；需先检查、核对，再创建新的写意图。 |
| 跨空间移动 | 显式拒绝；跨域可能返回 `wrong_domain`，同域不同空间返回 `cross_volume_move_requires_copy`。不伪装成原子跨卷移动，也不隐式执行复制后删除；独立的复制、校验、删除任务留待后续。 |
| 模糊崩溃状态 | 暂存长度或身份不符转为不确定；无归属的 `.tc-stage-*` 使核对以 `orphan_stage` 停止。创建空间前记录意图；若在对象身份落库前崩溃则返回 `uncertain_provision`，不擅自接管目录。应保留状态、停机检查，当前不提供自动破坏性修复。 |
| Flush 边界 | Linux 刷新文件及相关目录；Windows 刷新文件数据，但目录 flush 并非普遍可用。因此验证进程崩溃恢复，不宣称突然断电下的目录持久性。 |

各文件进程独占 `file*.db`，启用 WAL、FULL synchronous 与启动完整性检查。任务记录操作者、状态、进度、预留；写入、发布、删除及取消在所属文件库中留下审计。`/audit` 暴露身份策略审计；文件审计目前保留在所属数据库。任务查询按操作者与授权子树过滤。SQLite 恢复不能替代文件数据备份。

初始目录规模限制：1024 条策略对象、1024 用户、10000 个策略请求键、每空间 4096 任务、每域 100000 随机写请求键、每空间扫描 10000 项、每目录 4096 项。达到上限后明确拒绝，不提供分页或历史回收。该预览不适合无限规模生产文件系统，长期部署前需制定元数据与审计归档策略。

## 原生监控

`GET /monitoring` 要求管理角色。CPU tick、内存、网络接口字节计数、文件系统容量与时间戳来自原生 API 或 `/proc`、`sysfs`，速率需由两次采样计算。Linux 在可用时提供文件系统 UUID、磁盘 WWID/序列号及 hwmon 温度；Windows 区分卷 GUID 和物理盘序列号，并在驱动允许时查询原生故障预测。设备序号和挂载名不被当作稳定磁盘身份。

采集器限制设备/接口数量并检查 RPC 截止时间，区分 `available/unavailable/permission_denied/stale`；温度不代表整体健康结论。硬件、驱动、权限和 WSL 虚拟磁盘可能导致健康数据不可用。客户端最长等待四秒；原生调用位于受监督的监控进程内，内核驱动卡住可能需要隔离重启，而非协作式取消。不宣称完整 SMART 支持，不执行提权、磁盘变更或 RAID 管理。
