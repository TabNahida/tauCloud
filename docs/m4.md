# M4 — FTP and explicit FTPS backend preview

[简体中文](m4.zh-CN.md) · [Setup](m1.md) · [Shared file core](m2.md) · [Evidence](evidence/m4/README.md)

M4 adds `taucloud_ftp`, an independently supervised FTP/FTPS process using PACE TCP/coroutines and OpenSSL. Identity, grants, native files, locks, quota, jobs and recovery remain owned by the existing services. This preview binds only to IPv4 loopback on Linux/ext4 and Windows/NTFS. FileZilla interoperability remains an open acceptance item; see the exact client results in the evidence.

## Enable and connect

Stop the supervisor and add these optional fields to the initialized state's `config.json`:

```json
{"ftp_port":2121,"ftp_passive_first":50000,"ftp_passive_last":50031,"ftp_plaintext":false}
```

Merge these fields into the existing configuration. Omitted/zero `ftp_port` disables the listener. Control and passive ports must be 1024–65535, distinct from management/WebDAV ports; the passive range is inclusive, ordered and at most 128 ports. The default range is 50000–50031. Restart the supervisor; existing state gains the FTP IPC role key automatically. No database schema change is required. `/api/v1/protocols` reports the listener, passive range, plaintext setting and required data TLS session reuse. `/capabilities` reports M4.

Create a share through the authenticated management API/CLI:

```json
{"id":"documents","space":"alice","exposures":{"ftp":"rw"}}
```

The FTP namespace is `/documents/...`; `/` lists only authorized FTP exposures. Existing private/team ownership, grants and portable UTF-8 NFC paths apply. `r` is read-only. Updating a share requires its complete definition with `update:true`. FTP remains excluded from mixed writable protocol combinations. Use a separate space from an existing writable DAV/core exposure, or explicitly replace that exposure. Read-only siblings are permitted.

Use explicit TLS, passive mode, binary file transfers and the enrolled local username/password. Trust `<state>/tls-cert.pem` explicitly. A client must resume the control connection's TLS session on every protected data connection. For the tested OpenSSL curl:

```sh
curl --ssl-reqd --cacert <state>/tls-cert.pem --user alice \
  --upload-file local.txt ftp://127.0.0.1:2121/documents/local.txt
curl --ssl-reqd --cacert <state>/tls-cert.pem --user alice \
  ftp://127.0.0.1:2121/documents/local.txt
```

Plaintext login/data requires `ftp_plaintext:true` and restart. TLS clients must still use `PBSZ 0` and `PROT P`; `PROT C` and `CCC` are denied even when plaintext is enabled. Anonymous, active mode/FXP, implicit FTPS, remote/NAT deployment and system port 21 are outside this profile.

## Wire behavior

Implemented commands include AUTH TLS, USER/PASS, PBSZ/PROT, FEAT, SYST, OPTS UTF8/MLST, PWD, CWD/CDUP, TYPE I/L 8/A N, MODE S, STRU F, EPSV (IPv4/ALL), PASV, MLST/MLSD, LIST/NLST, SIZE, MDTM, RETR/STOR, REST, MKD/RMD, DELE, RNFR/RNTO, NOOP, ABOR and QUIT. Common X-prefixed directory aliases are accepted. TYPE A is accepted for listings; ASCII file conversion, EBCDIC, non-stream modes, APPE, STOU and other unsupported commands are rejected rather than silently transferring incorrect bytes. SIZE and file transfers require binary mode. RMD requires an empty directory; share roots cannot be renamed or removed; rename stays within one share and does not overwrite.

FEAT and MLST use multiline replies. MLST facts are type, file size and UTC modification time; OPTS selects facts. LIST is a compatibility presentation with synthetic ownership/permissions and a placeholder date; MLSD is the metadata interface. UTF-8 is always enabled, with the M3 portable-name restrictions. FTP paths are raw UTF-8, not URL-percent-decoded. `..` navigates the virtual namespace but cannot pass above `/`; every resolved share/path is separately authorized.

TLS 1.2 and 1.3 are supported. Each control connection owns a separate OpenSSL context, session cache, session-id context and ticket keys. Data sockets must match its peer address **and** successfully resume within that context. A fresh TLS session or a ticket belonging to a different control connection is rejected before file data is admitted. The adapter uses memory BIOs over PACE; it does not modify the pinned PACE sources. Crypto and TLS records remain OpenSSL's responsibility.

ABOR is supported in-band, including over TLS; Telnet urgent-data synchronization is not implemented. During a transfer, only ABOR, NOOP and QUIT are accepted. A successful abort replies 426 for the transfer and 226 for ABOR; an idle ABOR returns 225. Abort cannot undo an already published commit. Closing a control connection cancels its active transfer.

## Uploads, resume and recovery

STOR writes a private stage, flushes chunks and atomically publishes after successful EOF and current authorization. FTPS requires authenticated TLS `close_notify`; an abrupt socket close discards the stage. After valid EOF, reciprocal TLS shutdown is best effort because curl may already have closed TCP. This does not relax incoming truncation checks. Plain FTP stream EOF has no authenticated length: a clean TCP FIN is indistinguishable from intentional completion. Use FTPS for truncation protection.

REST supports binary byte offsets. RETR starts at the requested offset. REST + STOR copies the existing prefix into a new stage and replaces the suffix with received bytes, truncating the previous suffix. It requires an existing file and an offset no larger than its size. The captured ETag is rechecked before publication; changed sources cannot be silently resumed. An interrupted stage is discarded; reconnect can resume from an already published file, not recover an invisible partial FTP upload. Core API durable upload jobs retain their separate M2 semantics.

Unknown-length STOR reserves up to the smaller of 1 GiB and currently available quota, including the resume prefix. Seal reduces that reservation to actual size; commit/cancel releases it. This conservative policy may limit concurrent uploads. Each chunk renews short file grants; revocation is pushed to the file authority. Expired signed grants can only clean up the matching actor/path/protocol's handle or unpublished job, never read/write/commit.

On worker restart, the FTP ownership lock fences the old process before authenticated recovery removes FTP handles and unpublished FTP stages in each file worker. Core handles/jobs and sibling protocol processes survive. Domain restart also cancels FTP stages, while durable committing jobs use the existing publication journal. Abandoned stages expire after 15 seconds without stored progress and are reclaimed on subsequent file requests. Persistent DAV locks continue to prevent FTP mutations after an exposure change; FTP has no command to bypass those locks.

Successful password checks use a bounded internal file-scope session cache, validated on reuse and commands; QUIT removes connection state without revoking other connections using the same credentials. Disable/revocation invalidates cached sessions. The original identity login limits remain 5/account/minute and 30 globally/minute; worker restarts may therefore require waiting for the login window.

| Bound | Limit |
| --- | --- |
| Connections / executor | min(configured, 32) / 4 threads, queue 32 |
| Command / control wait | 2048 bytes / 300 seconds |
| Passive listeners | one per connection, configured range at most 128 ports |
| Passive accept / TLS handshake / data I/O | 5 seconds each |
| Upload chunk assembly | 64 KiB within 5 seconds |
| File chunk / upload | 64 KiB / 1 GiB including resume prefix, further quota-limited |
| Directory listing / tree rename | inherited DAV limit: 256 objects, bounded IPC |
| Internal credential session cache | 256 entries, identity session expiry/revocation applies |

This is a bounded local profile, not a general Internet FTP daemon or a claim of complete RFC coverage. Protocol references: [RFC 959](https://www.rfc-editor.org/rfc/rfc959), [RFC 2428](https://www.rfc-editor.org/rfc/rfc2428), [RFC 3659](https://www.rfc-editor.org/rfc/rfc3659), [RFC 4217](https://www.rfc-editor.org/rfc/rfc4217).

## Reproduce validation

```sh
python3 scripts/run_m4.py --compiler gcc --large-mib 257
python3 scripts/run_m4.py --compiler clang --mode debug --sanitizers
```

On Windows use `python scripts/run_m4.py --compiler msvc --large-mib 257` in a native NTFS checkout. `scripts/windows_m4.ps1` creates one from the WSL checkout. Linux can add `--litmus build/litmus/installed/bin/litmus` for M3 regression. The runner includes M1–M4 native and integration tests. All datasets/listeners are disposable; it installs no persistent service and does not modify real disks or certificate stores. Release large transfers exceed the 256 MiB worker allocation ceiling, not host physical RAM. CI is provided separately from the recorded local runs.
