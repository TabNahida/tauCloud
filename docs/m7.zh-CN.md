## 配置

`nfs_lease_seconds` 可设为 5–3600 秒，默认 60。NFSv4 对外报告的 lease 和客户端/会话续期使用同一时长。重启时缩短配置不会缩短旧状态的恢复 grace，连续重启也保留旧窗口，直到恢复状态过期。NLM grace 独立不变。此配置本身不会启用 delegation 发放；进度见 [delegation 实现](nfs-delegations.md)。

`config.json` 的 `nfs_port` 默认为 0（关闭），启用时选择 1024–65535 中未占用且不与其他服务、FTP 被动端口范围重叠的端口。只绑定 `127.0.0.1`。NFS、MOUNT 和只读 rpcbind/portmapper 共用此 TCP 端口，不设置系统 rpcbind、不修改防火墙、不要求 2049/111。

先通过现有管理 API 创建空间、用户、组和成员关系，再创建 `exposures:{"nfs":"rw"}` 的共享。`POST /api/v1/nfs-exports` 示例：

```json
{
  "id":"nfs",
  "trust":"loopback-auth-sys",
  "anonymous":"guest",
  "uids":{"1000":"alice"},
  "gids":{"1000":"unix-users"},
  "enabled":true
}
```

`id` 必须匹配具有 NFS exposure 的共享；`alice`、`guest` 和 `unix-users` 必须已存在，Alice 必须属于该组。UID 0 及其附加组强制映射到匿名用户；其他 UID 的主 GID 和所有附加 GID 都必须映射到该用户所属的组。未知映射拒绝；匿名用户没有空间权限时 root 访问也会被拒绝。更新需带 `update:true` 和完整记录，`enabled:false` 会拒绝现有句柄的新授权。仍执行整个空间的跨协议单写者规则。

AUTH_SYS 是可信本机客户端提供的、可伪造的数字声明，不是 tauCloud 密码认证。Linux 已接入真实 MIT GSSAPI，实现 Kerberos/RPCSEC_GSS 认证、完整性、隐私、重放窗口和服务端 principal 映射；配置与剩余验收见 [Kerberos 文档](nfs-kerberos.md)。Windows 接收端、原生客户端及更广泛的安全协商仍待完成，不会将 GSS 请求按 AUTH_SYS 接受或静默降级。

## 已接通的功能

- 有界 TCP RPC 分片/XDR、认证分派、监督进程和权限 IPC。
- 50 字节 MAC 句柄，持久导出/对象 UUID 和原生代次证据；跨工作进程重启及外部重命名保持身份，删除重建不会复用旧句柄。
- v4.1 客户端/会话生命周期、连接绑定、slot 重放、OPEN 升降级、share-deny、LOCK/LOCKT/LOCKU、CLOSE；部分解锁拆分范围，持久 OPEN/锁所有者及重启 grace/reclaim。
- v3 常用文件读写、SETATTR、目录枚举、guarded/unchecked/exclusive CREATE、MKDIR、REMOVE/RMDIR、可覆盖已关闭目标的 RENAME、FS 信息和 COMMIT；部分 MOUNT v3 和只读 GETPORT/GETADDR。
- AUTH_SYS 会话可承载同一可信主机上的多个映射用户；OPEN/锁保留各自主体，重放摘要包含调用主体，不能借用别人的状态或缓存响应。
- mode、数字 UID/GID 由同一持久共享描述符派生，在不同导出别名间保持一致；chmod 真正改变文件访问权限，不改变主机 UID/SID。设置属主仅接受调用者的映射 UID/组并执行 root squash。时间戳经固定原生句柄写入，Windows 精度为 100 纳秒。
- 所有 WRITE 均处理短写，真实 flush 后才确认 FILE_SYNC；UNSTABLE 请求也提升为 FILE_SYNC。COMMIT 真实 flush，重启更换 verifier；v3 变更响应持久化，不确定结果不冒充成功。

单次读写 64 KiB；RPC 消息上限 256 KiB/64 个非空分片；16 个连接；v4.1 协商消息/缓存 128 KiB、32 个会话、每会话最多 8 个 slot、每复合请求 16 项。租约和恢复 grace 为 60 秒，会话可跨多个导出、同一 owner/file 只接受一个 open；每条缓存复合回复最多记录 64 个导出权限，伪根单页最多解析 32 个导出。枚举最多 1024 项及 200 KiB 元数据，句柄重定位最多访问 4096 个节点，名称空间核对最多 10000 项且受授权期限约束。v3 重放表最多 10000 条，文件域操作日志最多 100000 条，容量耗尽后明确拒绝，不自动淘汰重放保护。

伪根目录支持分页 READDIR、LOOKUP/LOOKUPP 和 SECINFO，按与文件访问相同的身份映射、root squash、启用状态和空间权限过滤导出。根目录 change 属性随策略版本推进，分页 verifier 绑定调用主体和名称空间版本。READDIR 将整个结果计入 maxcount，首项放不下返回 TOOSMALL，拒绝保留 cookie，verifier 变化返回 NOT_SAME。依据：[RFC 8881 READDIR](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.23)。

单会话可同时打开多个导出。缓存回复按实际访问过的每个导出重新检查读写权限和授权范围；撤销或重定向共享时返回 DELAY，不重执行原来的变更。导出可见性变化也会阻止旧目录缓存回复。新的 slot 序列可继续访问其他仍有权限的导出。该撤销策略仍属于当前受限配置，不代表完整会话合规。新增 `tests/nfs_namespace_integration.py` 已纳入 GCC/Clang/MSVC 回归，Linux 原生客户端验收增加伪根挂载及同时打开两个导出。

### CREATE_SESSION 通道协商

前向和回调通道的消息大小上限不超过客户端提供值；回调通道的操作数和并发请求数保持客户端原值，符合 [RFC 8881 §18.36.3](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.36.3)。这些上限本身不代表已授予回调通道；连接绑定和路径探测见下文。CREATE_SESSION 重放返回原会话和原协商值。独立的小/大上限、重放和会话使用检查通过 Clang ASan/UBSan；原版 `create_session` 选择得到 28 项通过、3 项 delegation 依赖失败（DELEG5/6/7），均保留在[证据](evidence/pre-m8/nfs-session-negotiation-local.json)中。本次修正的三平台远程验收待完成。

## 尚未完成的部分

必需操作符合性和完整客户端矩阵仍待完成。v4 会话不持久化，重启拒绝旧 session/stateid；匹配的客户端、主体和所有者只能在 grace 中、RECLAIM_COMPLETE 之前恢复已记录状态。覆盖/删除仍有活动 NFS OPEN 的目标现已保留原生句柄，支持旧对象 I/O、配额计费和 NFS 工作进程重启 reclaim；已加入文件域/全部服务重启后的未链接对象持久恢复，Linux 恢复测试通过，Windows 待验收；完整缓存一致性及大规模负载仍需继续验证。硬链接、符号链接、v3 UDP、v2/v4.0/v4.2、pNFS/RDMA 不在当前范围。

REMOVE 和原子 RENAME 覆盖现在会保留仍被 NFS OPEN 使用的原生文件句柄（每文件域最多 128 个），旧句柄访问旧对象，路径访问替换后的对象。未链接但仍打开的数据继续计入配额，最后关闭或租约过期后释放，后台定期清理不依赖客户端发包。保留对象同时写入持久日志并建立 `.tc-nfs-*` 私有链接，所有客户端协议均隐藏这些名称，普通用户硬链接仍被拒绝。日志先于链接创建；恢复时区分尚未删除原名与已完成删除/替换，最后清理也有可重入日志。已通过 Linux 文件域强杀、全服务重启及匹配 OPEN reclaim 测试；Windows 恢复及测试清理也已通过。

BACKCHANNEL_CTL 接受有界 AUTH_NONE/AUTH_SYS 回调配置，但不授予回调通道；未知 GSS 句柄返回 NOENT。已协商 SP4_NONE 时 SET_SSV 返回 INVAL，v4.1 禁止的旧 v4.0 操作返回 NOTSUPP。

NLM/NSM 补齐：实现 NLMv4 同步 TEST/LOCK/CANCEL/UNLOCK、共享/独占范围、部分解锁、死锁检查及真实 TCP GRANTED 回调；拒绝升级回调时恢复原共享锁。锁按原生对象与 v4 协调，v3 数据 I/O 仍遵循 advisory 语义。持久化授权范围和未 reclaim 范围，重启通知本地主机并执行 60 秒 grace，连续两次崩溃不丢失尚未恢复的范围。NSMv1 提供 STAT/MON/UNMON/UNMON_ALL/NOTIFY，拒绝 SIMU_CRASH。UDP 只接收 NSM 和只读发现，不处理 NFS 文件请求。回调只允许到 127.0.0.1 的固定程序，4 KiB 上限和 750 ms 超时；不支持旧版 NLM、MSG/RES、DOS SHARE/UNSHARE 和非监视锁。新增 nfs_address 仅允许 127.0.0.1 或 127.0.0.2；nfs_peer_rpcbind_port 默认 111，用于本地伴随服务发现。Linux 原生阻塞锁与重启 reclaim 已单独通过；macOS/Windows 的 nolock 结果不计入锁恢复验收。

Windows 目录时间戳修复：原 ReOpenFile 属性句柄被系统拒绝，现从已固定父目录句柄相对打开最后一个目录分量，核对原生对象身份后设置时间戳。原目录句柄继续禁止删除，未引入绝对路径回退。`e3deb24` 已通过核心、创建属性及 Windows 原生 NFS 验收。

扩展元数据补齐：NFSv3 的 ctime 不再错误复用 mtime；模式、所有权和时间属性变更按原生对象持久化元数据时间，各导出别名及 v4 time_metadata 使用一致结果，读取不推进变更时间。见[本地检查](evidence/pre-m8/metadata-expansion-local.json)。

NFSv3 `used` 和 NFSv4 `space_used` 已改为报告原生已分配字节，与逻辑文件长度及服务配额分别计算。测试对空文件、小文件、稀疏/扩展文件和截断文件，独立读取 Linux `st_blocks` 或 Windows `FileStandardInfo` 并与协议响应比较。完整安全及其他操作兼容性仍见 TODO 未完成项。

## TCP 回调通道传输

现已支持在已建立的 TCP 连接上双向收发 RPC，由单一有界写队列串行发送普通响应和回调帧。CREATE_SESSION 可为客户端提供的 AUTH_NONE/AUTH_SYS 凭据协商回调绑定；BIND_CONN_TO_SESSION 支持前向、回调和双向角色，拒绝无效方向和已有绑定的角色变更。CB_NULL 使用客户端指定的程序号和回调凭据；响应必须匹配 XID 与连接，重复、过期、畸形或来自其他连接的响应不能验证通道。探测五秒超时，BACKCHANNEL_CTL 使旧 CB_NULL 探测失效，重绑定可重新探测。SEQUENCE 在客户端没有已验证的路径时报告 CB_PATH_DOWN，断连和会话销毁会清除状态。

回调 RPC 版本采用 [RFC 5662 的 NFS4_CALLBACK XDR](https://www.rfc-editor.org/rfc/rfc5662.html#section-2) 定义的 **1**。RFC 8881 §18.36.3 正文写为 4，与线上 XDR 和原版 pynfs 不一致；版本 4 的原始失败和修正结果均保留。这份初始证据覆盖传输与 CB_NULL 探测；后续回调序列实现见下文。delegation/recall 仍未完成。Linux RPCSEC_GSS 回调现已实现，真实 KDC 本地测试以及 `70838b7` 的 GCC/Clang 远程八组测试通过；MSVC 仅覆盖共享 AUTH_SYS 回归（[详情](nfs-kerberos.md#authenticated-backchannel)）。独立生命周期测试及原版 CSESS20/CSESS21 已通过本地 Clang ASan/UBSan，CB_NULL 传输层现已通过三平台远程验收（[本地证据](evidence/pre-m8/nfs-backchannel-local.json)、[远程证据](evidence/pre-m8/smb-nfs-1e92b0d-remote.json)）。

### 回调序列与重放

CB_NULL 成功后，服务端发送仅含 CB_SEQUENCE 的 CB_COMPOUND；只有完整有效的回复才能验证回调路径。每个会话使用一个槽，客户端即使提供 UINT32_MAX 个槽也不会导致大量分配。推进序号和续租前，验证会话、序号、槽、标签、操作数、状态及完整记录长度。客户端可以扩大或缩小槽上限，服务端仍使用槽零。请求与回复大小限制包含 RPC 头及所选回调凭据。

超时、回调程序或凭据变更以及连接丢失后，未确认请求保留原 CB_COMPOUND 内容和序号；其他已绑定连接等待槽释放，并可承接重放。未匹配的 XID、其他连接和已销毁会话的响应不能完成当前请求。存在未确认回调且所有回调连接均断开时，报告 CB_PATH_DOWN_SESSION；重新绑定清除此标志，但 CB_PATH_DOWN 要等回调序列验证成功才清除。

独立 TCP 客户端覆盖损坏回复、重放、断连、会话重建、流控和资源上限。本地 Clang ASan/UBSan 与原版 pynfs 回调测试见[序列验收证据](evidence/pre-m8/nfs-cb-sequence-local.json)。CB_SEQUENCE 探测及断连重放修正在 `c425fc6` 通过三平台定向验收（[证据](evidence/pre-m8/nfs-cb-retry-remote.json)）。CB_NOTIFY_LOCK 见下文；CB_RECALL、delegation 权限协调和 RPCSEC_GSS 回调仍未完成。

回调重放的后续修正：此前仅保留相同序号仍不够；[RFC 8881 §2.10.6.2](https://www.rfc-editor.org/rfc/rfc8881.html#section-2.10.6.2) 要求原连接断开后才能重发。现在超时或畸形回复会请求关闭连接，并等待运行时确认断连，随后才能在其他绑定连接重放。BIND/BACKCHANNEL_CTL 不会提前释放在途请求；旧配置下的有效回复只完成其槽，不能验证新配置或恢复已清除的凭据。原始序列证据保留，当前行为以[重放修正证据](evidence/pre-m8/nfs-cb-retry-local.json)为准。

`1e92b0d` 的 CB_NULL 生命周期、通道协商、SMB 通知撤权及无加密算法协商已通过 GCC、Clang ASan/UBSan 和 MSVC 定向验收（[远程证据](evidence/pre-m8/smb-nfs-1e92b0d-remote.json)）；此结果不覆盖后续新增的 CB_SEQUENCE 或上述重放修正。

### 阻塞锁可用性通知

OPEN 现在返回 OPEN4_RESULT_MAY_NOTIFY_LOCK。READW_LT/WRITEW_LT 因冲突被拒绝时，可记录按客户端、主体、文件及锁所有者区分的等待提示；随后的非阻塞尝试会取消提示。维护过程检查 NFSv4/NLM 锁冲突、等待者 OPEN、当前 ACL 和导出授权，满足条件后发送包含准确文件句柄和锁所有者的 CB_NOTIFY_LOCK。关闭 OPEN、客户端过期或权限撤销会清除未发送的提示；重新授权不会恢复已撤销的等待记录。

通知与 CB_SEQUENCE 共用单槽，携带被拒绝 LOCK 的会话、槽和序号引用。回复丢失或畸形时，必须确认原连接断开后才能逐字节重放。客户端返回 NOTSUPP 或 RETRY_UNCACHED_REP 等有效操作结果会完成该提示并推进序号，但不会授予或预留锁；客户端仍须重新执行 LOCK，也可能输给其他竞争者。

等待记录上限为全局 128 个、每客户端 16 个，每轮最多进行八次新的授权检查。发送遵守回调操作数及完整 RPC 大小限制；不具备可用回调或缓冲区不足的客户端继续轮询 LOCK。这是可选、非持久化的提示，并非 FIFO 获锁保证。

[本地证据](evidence/pre-m8/nfs-notify-lock-local.json) 包含独立 TCP 故障注入、真实 60 秒租约过期、原有槽与锁恢复回归，以及使用未修改 pynfs RPC/NFS 客户端的通知场景。后者是调用上游客户端的新测试，不能代表上游全部 callback 测试已通过。`3d65a90` 的 GCC、Clang ASan/UBSan、MSVC 三平台均通过 9 组独立测试，两个 Linux 编译器另通过未修改 pynfs 客户端场景（[远程证据](evidence/pre-m8/nfs-notify-lock-3d65-remote.json)）。
