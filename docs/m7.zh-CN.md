M7a/M7b 已在现有 ADR 0010 的受限配置内验收：普通文件/目录、回环 AUTH_SYS、明确 UID/GID 映射与 root squash。145 个适用上游用例通过，121 个排除项保留；必需操作行为见[覆盖表](nfs-operation-coverage.md)。Linux 内核 v3/v4.1、macOS 15.7.9 v3、Windows Server 2025 Client for NFS v3 均完成原生文件往返。Linux 还通过实际阻塞锁、GRANTED 回调、服务重启后内核 reclaim，以及恢复旧 mtime 的等长外部修改缓存重验证。macOS/Windows 使用 nolock。这不等于完整 RFC 8881 合规，仍保留 `full_conformance:false`。固定提交见[验收记录](evidence/pre-m8/README.md)。

## 配置

`config.json` 的 `nfs_port` 默认为 0（关闭），启用时选择 1024–65535 中未占用且不与其他服务、FTP 被动端口范围重叠的端口。只绑定 `127.0.0.1`。NFS、MOUNT 和只读 rpcbind/portmapper 共用此 TCP 端口，不设置系统 rpcbind、不修改防火墙、不要求 2049/111。

先通过现有管理 API 创建空间、用户、组和成员关系，再创建 `exposures:{"nfs":"rw"}` 的共享。`POST /api/v1/nfs-exports` 示例：

```json
{
  "id":"nfs",
  "trust":"loopback-auth-sys",
  "anonymous":"guest",
  "uids":{"1000":"alice"},
  "gids":{"1000":"unix-users"},
  "enabled":true
}
```

`id` 必须匹配具有 NFS exposure 的共享；`alice`、`guest` 和 `unix-users` 必须已存在，Alice 必须属于该组。UID 0 及其附加组强制映射到匿名用户；其他 UID 的主 GID 和所有附加 GID 都必须映射到该用户所属的组。未知映射拒绝；匿名用户没有空间权限时 root 访问也会被拒绝。更新需带 `update:true` 和完整记录，`enabled:false` 会拒绝现有句柄的新授权。仍执行整个空间的跨协议单写者规则。

AUTH_SYS 是可信本机客户端提供的、可伪造的数字声明，不是 tauCloud 密码认证。Kerberos/RPCSEC_GSS 另行实现；不会将 GSS 请求按 AUTH_SYS 接受或静默降级。

## 已接通的功能

- 有界 TCP RPC 分片/XDR、认证分派、监督进程和权限 IPC。
- 50 字节 MAC 句柄，持久导出/对象 UUID 和原生代次证据；跨工作进程重启及外部重命名保持身份，删除重建不会复用旧句柄。
- v4.1 客户端/会话生命周期、连接绑定、slot 重放、OPEN 升降级、share-deny、LOCK/LOCKT/LOCKU、CLOSE；部分解锁拆分范围，持久 OPEN/锁所有者及重启 grace/reclaim。
- v3 常用文件读写、SETATTR、目录枚举、guarded/unchecked/exclusive CREATE、MKDIR、REMOVE/RMDIR、可覆盖已关闭目标的 RENAME、FS 信息和 COMMIT；部分 MOUNT v3 和只读 GETPORT/GETADDR。
- AUTH_SYS 会话可承载同一可信主机上的多个映射用户；OPEN/锁保留各自主体，重放摘要包含调用主体，不能借用别人的状态或缓存响应。
- mode、数字 UID/GID 按原生对象代次持久化，在不同导出别名间保持一致；仍由应用 ACL 决定权限，不改变主机 UID/SID。设置属主仅接受调用者的映射 UID/组并执行 root squash。时间戳经固定原生句柄写入，Windows 精度为 100 纳秒。
- 所有 WRITE 均处理短写，真实 flush 后才确认 FILE_SYNC；UNSTABLE 请求也提升为 FILE_SYNC。COMMIT 真实 flush，重启更换 verifier；v3 变更响应持久化，不确定结果不冒充成功。

单次读写 64 KiB；RPC 消息上限 256 KiB/64 个非空分片；16 个连接；v4.1 协商消息/缓存 128 KiB、32 个会话、每会话最多 8 个 slot、每复合请求 16 项。租约和恢复 grace 为 60 秒，会话可跨多个导出、同一 owner/file 只接受一个 open；每条缓存复合回复最多记录 64 个导出权限，伪根单页最多解析 32 个导出。枚举最多 1024 项及 200 KiB 元数据，句柄重定位最多访问 4096 个节点，名称空间核对最多 10000 项且受授权期限约束。v3 重放表最多 10000 条，文件域操作日志最多 100000 条，容量耗尽后明确拒绝，不自动淘汰重放保护。

伪根目录支持分页 READDIR、LOOKUP/LOOKUPP 和 SECINFO，按与文件访问相同的身份映射、root squash、启用状态和空间权限过滤导出。根目录 change 属性随策略版本推进，分页 verifier 绑定调用主体和名称空间版本。READDIR 将整个结果计入 maxcount，首项放不下返回 TOOSMALL，拒绝保留 cookie，verifier 变化返回 NOT_SAME。依据：[RFC 8881 READDIR](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.23)。

单会话可同时打开多个导出。缓存回复按实际访问过的每个导出重新检查读写权限和授权范围；撤销或重定向共享时返回 DELAY，不重执行原来的变更。导出可见性变化也会阻止旧目录缓存回复。新的 slot 序列可继续访问其他仍有权限的导出。该撤销策略仍属于当前受限配置，不代表完整会话合规。新增 `tests/nfs_namespace_integration.py` 已纳入 GCC/Clang/MSVC 回归，Linux 原生客户端验收增加伪根挂载及同时打开两个导出。

## 尚未完成的部分

必需操作符合性和完整客户端矩阵仍待完成。v4 会话不持久化，重启拒绝旧 session/stateid；匹配的客户端、主体和所有者只能在 grace 中、RECLAIM_COMPLETE 之前恢复已记录状态。覆盖/删除仍有活动 NFS OPEN 的目标现已保留原生句柄，支持旧对象 I/O、配额计费和 NFS 工作进程重启 reclaim；已加入文件域/全部服务重启后的未链接对象持久恢复，Linux 恢复测试通过，Windows 待验收；完整缓存一致性及大规模负载仍需继续验证。硬链接、符号链接、v3 UDP、v2/v4.0/v4.2、pNFS/RDMA 不在当前范围。

Linux 要求 exportfs token 和出生身份；Windows 实验范围为 NTFS。元数据备份剔除 NFS 导出登记并不复制句柄密钥、映射、重放或 OPEN 恢复状态；恢复后重新登记，旧句柄失效。Windows 名称空间的断电持久性沿用 M2 的目录 flush 限制；本次 FILE_SYNC 验证不能扩大为新建文件名突然断电仍存在的保证。详细设计见 [ADR 0010](decisions/0010-nfs-preview.zh-CN.md)。

## 验证

```sh
python3 -m venv .deps/nfs-venv
.deps/nfs-venv/bin/pip install -r tests/smb-requirements.txt -r tests/nfs-requirements.txt
.deps/nfs-venv/bin/python scripts/run_m7.py --compiler gcc
.deps/nfs-venv/bin/python scripts/run_m7.py --compiler clang --mode debug --sanitizers
```

Windows 使用 `scripts/windows_m7.ps1` 在临时 NTFS 副本上原生构建。测试固定 linux-nfs/pynfs 源码版本和树摘要，使用其生成的 v3/v4.1 编解码器经 TCP 验证，再跑 M1–M7 回归。上游测试工具不链接到服务端。

`scripts/prepare_pynfs.py` 准备未经修改的上游 runner，`tests/pynfs_acceptance.py` 运行明确选择的测试并保留失败记录。`tests/nfs_state_integration.py` 检查跨主体隔离、竞争锁和重启恢复；`tests/nfs_attributes_integration.py` 检查原生时间戳及导出别名持久化。GitHub Actions 在一次性环境中使用特权 mount/umount 验证 Linux 内核客户端；普通服务和编解码器测试仍不需要特权端口。选定测试通过不等于完整协议兼容。

补齐进展：change 属性改为按原生 ctime/ChangeTime、大小、mtime 和投影元数据计算的持久化变更序号，忽略 atime；已验证等长写入后恢复 mtime、别名、只读及重启行为。名称空间操作返回真实的非原子 change_info。EXCLUSIVE4_1 提供可设置属性位图；UNCHECKED 对现有文件的零长度截断先检查共享冲突，并返回实际设置的属性。完整缓存一致性、NLM 原生锁恢复和完整客户端矩阵仍未验收。

本轮补齐 MOUNT 的 MNT/DUMP/UMNT/UMNTALL/EXPORT 和 rpcbind 的 DUMP、GETVERSADDR；导出及挂载记录按调用者权限过滤，匿名发现使用 root squash 后的视图。

REMOVE 和原子 RENAME 覆盖现在会保留仍被 NFS OPEN 使用的原生文件句柄（每文件域最多 128 个），旧句柄访问旧对象，路径访问替换后的对象。未链接但仍打开的数据继续计入配额，最后关闭或租约过期后释放，后台定期清理不依赖客户端发包。保留对象同时写入持久日志并建立 `.tc-nfs-*` 私有链接，所有客户端协议均隐藏这些名称，普通用户硬链接仍被拒绝。日志先于链接创建；恢复时区分尚未删除原名与已完成删除/替换，最后清理也有可重入日志。已通过 Linux 文件域强杀、全服务重启及匹配 OPEN reclaim 测试；Windows 恢复及测试清理也已通过。

BACKCHANNEL_CTL 接受有界 AUTH_NONE/AUTH_SYS 回调配置，但不授予回调通道；未知 GSS 句柄返回 NOENT。已协商 SP4_NONE 时 SET_SSV 返回 INVAL，v4.1 禁止的旧 v4.0 操作返回 NOTSUPP。

NLM/NSM 补齐：实现 NLMv4 同步 TEST/LOCK/CANCEL/UNLOCK、共享/独占范围、部分解锁、死锁检查及真实 TCP GRANTED 回调；拒绝升级回调时恢复原共享锁。锁按原生对象与 v4 协调，v3 数据 I/O 仍遵循 advisory 语义。持久化授权范围和未 reclaim 范围，重启通知本地主机并执行 60 秒 grace，连续两次崩溃不丢失尚未恢复的范围。NSMv1 提供 STAT/MON/UNMON/UNMON_ALL/NOTIFY，拒绝 SIMU_CRASH。UDP 只接收 NSM 和只读发现，不处理 NFS 文件请求。回调只允许到 127.0.0.1 的固定程序，4 KiB 上限和 750 ms 超时；不支持旧版 NLM、MSG/RES、DOS SHARE/UNSHARE 和非监视锁。新增 nfs_address 仅允许 127.0.0.1 或 127.0.0.2；nfs_peer_rpcbind_port 默认 111，用于本地伴随服务发现。Linux 原生阻塞锁与重启 reclaim 已单独通过；macOS/Windows 的 nolock 结果不计入锁恢复验收。

Windows 目录时间戳修复：原 ReOpenFile 属性句柄被系统拒绝，现从已固定父目录句柄相对打开最后一个目录分量，核对原生对象身份后设置时间戳。原目录句柄继续禁止删除，未引入绝对路径回退。`e3deb24` 已通过核心、创建属性及 Windows 原生 NFS 验收。

扩展元数据补齐：NFSv3 的 ctime 不再错误复用 mtime；模式、所有权和时间属性变更按原生对象持久化元数据时间，各导出别名及 v4 time_metadata 使用一致结果，读取不推进变更时间。见[本地检查](evidence/pre-m8/metadata-expansion-local.json)。
