# M4 — FTP 与显式 FTPS 后端预览

[English](m4.md) · [基础设置](m1.zh-CN.md) · [文件服务](m2.zh-CN.md) · [验收证据](evidence/m4/README.md)

M4 新增独立受监督进程 `taucloud_ftp`，使用 PACE TCP/协程和 OpenSSL。身份、权限、原生文件、锁、配额、任务和恢复仍由已有服务负责。当前为 Linux/ext4、Windows/NTFS 的 IPv4 回环预览；FileZilla 互操作仍是未完成的验收项，具体客户端结果见证据。

## 启用与连接

停止监督器，在已初始化的 `config.json` 中合并以下可选字段，然后重启：

```json
{"ftp_port":2121,"ftp_passive_first":50000,"ftp_passive_last":50031,"ftp_plaintext":false}
```

省略或设置 `ftp_port:0` 会禁用监听。端口范围为 1024–65535；控制和被动端口不得与管理/WebDAV 端口重叠。被动范围包含两端，最多 128 个端口，默认 50000–50031。旧状态会自动补充 FTP IPC 密钥，无数据库版本迁移。`/api/v1/protocols` 返回端口、被动范围、明文开关、强制数据 TLS 会话复用信息；`/capabilities` 报告 M4。

使用已认证的管理 API/CLI 创建共享：

```json
{"id":"documents","space":"alice","exposures":{"ftp":"rw"}}
```

FTP 路径为 `/documents/...`，根目录只列出有权限的 FTP 共享。沿用私有/团队空间、授权与 UTF-8 NFC 路径规则。`r` 为只读；更新需提交完整定义和 `update:true`。FTP 不在已验证的混合写协议组合内：应使用独立空间，或明确替换现有 DAV/core 写入暴露。允许其他协议只读。

客户端使用显式 TLS、被动模式、二进制传输和本地账户。显式信任 `<state>/tls-cert.pem`，每个数据连接必须复用对应控制连接的 TLS 会话。已测试的 OpenSSL curl 用法：

```sh
curl --ssl-reqd --cacert <state>/tls-cert.pem --user alice \
  --upload-file local.txt ftp://127.0.0.1:2121/documents/local.txt
curl --ssl-reqd --cacert <state>/tls-cert.pem --user alice \
  ftp://127.0.0.1:2121/documents/local.txt
```

明文登录/传输只有显式设置 `ftp_plaintext:true` 并重启后才允许。TLS 客户端仍必须使用 `PBSZ 0`、`PROT P`；即使开启明文也拒绝 `PROT C` 和 `CCC` 降级。匿名、主动模式/FXP、隐式 FTPS、远程/NAT 部署和系统 21 端口不在当前范围内。

## 协议与边界

实现 AUTH TLS、USER/PASS、PBSZ/PROT、FEAT、SYST、OPTS UTF8/MLST、PWD、CWD/CDUP、TYPE I/L 8/A N、MODE S、STRU F、EPSV（IPv4/ALL）、PASV、MLST/MLSD、LIST/NLST、SIZE、MDTM、RETR/STOR、REST、MKD/RMD、DELE、RNFR/RNTO、NOOP、ABOR、QUIT，以及常见 X 前缀目录命令别名。

TYPE A 仅用于目录列表；文件传输和 SIZE 必须为二进制模式。ASCII 文件转换、EBCDIC、非流模式、APPE、STOU 和其他未实现命令会明确拒绝。RMD 只删除空目录，不能删除/重命名共享根，重命名限同一共享且不覆盖。MLST 支持 type、文件 size 和 UTC modify，OPTS 可选择字段；LIST 的所有者/权限和占位日期是兼容展示，应使用 MLSD 获取元数据。FTP 路径使用原始 UTF-8，不做 URL 百分号解码；`..` 只能在虚拟根内导航，解析后仍单独鉴权。

TLS 1.2/1.3 都适用。每条控制连接拥有独立 OpenSSL 上下文、会话缓存、会话 ID 上下文和 ticket 密钥。数据连接必须来源 IP 一致，且在该上下文内成功恢复会话；全新 TLS 会话或其他控制连接的 ticket 会在读写文件数据前被拒绝。本地适配器通过 memory BIO 接入 PACE，不修改锁定的 PACE 源码，密码与 TLS 记录处理由 OpenSSL 完成。

支持带内 ABOR（包括 TLS 内），不实现 Telnet 紧急数据同步。传输期间只接受 ABOR、NOOP、QUIT。取消返回传输 426 与 ABOR 226；空闲时 ABOR 返回 225。取消不能撤销已经发布的提交；关闭控制连接会取消其活动传输。

## 上传、续传与恢复

STOR 暂存、逐块刷新，成功结束并重新鉴权后原子发布。FTPS 必须收到经过认证的 TLS `close_notify`；直接断开 socket 会丢弃暂存数据。合法 EOF 之后的反向 TLS 关闭为尽力而为，因为 curl 此时可能已经关闭 TCP；这不会放宽输入截断检查。明文 FTP 无法区分正常 TCP FIN 是主动完成还是提前结束，应使用 FTPS 获得截断保护。

REST 为二进制字节偏移。RETR 从偏移处下载；REST + STOR 将已有文件前缀复制到新暂存文件，再用收到的数据替换后缀并截断旧后缀。要求已有文件且偏移不超过文件大小，提交前复核捕获的 ETag，防止源文件变化后的错误续传。中断的 FTP 暂存上传会丢弃；重连可基于已经发布的文件续传，不能恢复不可见的 FTP 半成品。core API 的持久上传任务保持 M2 语义。

未知长度上传预留「1 GiB 与当前可用配额的较小值」，包含续传前缀；seal 将预留缩减至实际大小，提交/取消释放预留。这种保守策略会限制并发上传。每块操作续期短时文件授权，撤权推送到文件服务。过期签名授权仅能清理匹配用户、路径、协议的句柄或未发布任务，不能读写或提交。

FTP 重启先取得进程锁，确认旧进程被隔离，再要求文件服务回收 FTP 句柄与未发布暂存文件；core 句柄/任务和其他协议进程继续存在。文件域重启也清理 FTP 暂存；正在提交的任务沿用发布日志恢复。无进度的暂存任务 15 秒后在后续文件请求中回收。切换暴露后，持久 DAV 锁仍可阻止 FTP 写入，FTP 无绕过锁的命令。

成功的密码验证结果通过有界内部文件会话缓存复用，每次复用和命令仍验证状态。QUIT 只清理连接，不撤销相同凭据的其他连接；禁用账户/撤权会使缓存失效。原登录限制仍为每账户每分钟 5 次、全局 30 次，进程重启后可能需要等待窗口。

| 限制项 | 上限 |
| --- | --- |
| 连接 / 阻塞执行器 | 配置值与 32 取小 / 4 线程、队列 32 |
| 命令 / 控制等待 | 2048 字节 / 300 秒 |
| 被动监听 | 每连接一个，端口范围最多 128 |
| accept / TLS 握手 / 数据 I/O | 各 5 秒 |
| 上传块组装 | 64 KiB，5 秒内完成 |
| 文件块 / 单次上传 | 64 KiB / 含续传前缀最多 1 GiB，受配额进一步限制 |
| 目录列表 / 树重命名 | 沿用 DAV 256 对象与有界 IPC |
| 内部会话缓存 | 256 条，受身份服务过期和撤权控制 |

这是有界本地预览，不是通用公网 FTP 服务或完整 RFC 符合性声明。协议依据：[RFC 959](https://www.rfc-editor.org/rfc/rfc959)、[RFC 2428](https://www.rfc-editor.org/rfc/rfc2428)、[RFC 3659](https://www.rfc-editor.org/rfc/rfc3659)、[RFC 4217](https://www.rfc-editor.org/rfc/rfc4217)。

## 复现验证

```sh
python3 scripts/run_m4.py --compiler gcc --large-mib 257
python3 scripts/run_m4.py --compiler clang --mode debug --sanitizers
```

Windows 在原生 NTFS 检出中执行 `python scripts/run_m4.py --compiler msvc --large-mib 257`；`scripts/windows_m4.ps1` 可从 WSL 源码建立临时检出。Linux 可加 `--litmus build/litmus/installed/bin/litmus` 回归 M3。运行器包含 M1–M4 原生与集成测试。数据集与监听均为临时，不注册服务，不操作真实磁盘或系统证书库。发布构建的 257 MiB 传输大于 256 MiB 进程硬分配预算，不代表大于宿主机物理内存。CI 配置和本地运行证据分别报告。
