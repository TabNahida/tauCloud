# M6 — SMB3 后端预览

M6 在 [M5 文件与凭据能力](m5.zh-CN.md)之上增加 SMB 3.0、3.0.2、3.1.1。继续使用独立 SMB 进程、统一文件权威、权限授权、配额、共享模式、字节锁和删除恢复；从 M5 升级无需数据库迁移或重新登记凭据。通过配置的回环 `smb_port` 提供服务，功能验收使用非 445 临时端口。

## 安全协商

| 方言 | 签名 | 加密 | 协商完整性 |
| --- | --- | --- | --- |
| 2.1 兼容 | HMAC-SHA256 | 不支持 | 旧版能力，不具备 SMB3 预认证完整性 |
| 3.0 | AES-128-CMAC | AES-128-CCM | 签名的 validate-negotiate |
| 3.0.2 | AES-128-CMAC | AES-128-CCM | 签名的 validate-negotiate |
| 3.1.1 现代默认 | AES-128-GMAC/CMAC 或 HMAC-SHA256 | AES-128/256-GCM/CCM，优先 AES-128-GCM | SHA-512 预认证链 |

选择客户端与服务端共同支持的最高方言；默认 3.1.1 不代表禁止显式旧版连接。未实现 SMB1/2.0.2。认证后的明文请求必须签名，加密请求的响应同样加密。服务端目前**不会强制所有共享或会话加密**；需要保密的客户端应设置 `require_encryption=True` 并约束最低方言。仅协商到 SMB3 不代表数据已加密。

3.1.1 必须提供 SHA-512 预认证能力。加密独立协商：缺少加密上下文时响应也不包含该上下文；客户端提供的列表没有共同 AES-128/256-GCM/CCM 算法时，返回单个值为零的 cipher ID。这两种情况仍允许认证后的签名会话，但拒绝未协商的加密传输，不隐式选择加密算法或旧方言。签名按 GMAC、CMAC、HMAC-SHA256 顺序选择共同能力；缺少签名上下文或无共同算法时使用规范要求的 CMAC。空列表或畸形列表拒绝。GMAC nonce 包含 MessageId、方向和 CANCEL 标志，同步及异步响应均使用所选算法。缺少预认证上下文或重复的单例上下文（类型 1、2、3、7、8）拒绝；NETNAME、未实现的传输及未知上下文在边界检查后忽略，允许重复。截断、重叠和过多上下文拒绝。压缩等扩展不宣告支持。3.0/3.0.2 需要客户端宣告加密能力才能使用 CCM。参见 [MS-SMB2 协商处理](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b39f253e-4963-40df-8dff-2f9040ebbeb1)。

预认证链覆盖原始 NEGOTIATE 请求/响应和 SESSION_SETUP 消息，直到最后一个认证请求；成功认证响应使用派生密钥签名，但不纳入派生密钥的输入链。SP800-108 HMAC-SHA256 分别派生签名及两个方向的加密密钥。NTLMv2 MIC 与 M5 凭据保险库仍然使用。失败认证关闭连接，避免继续使用不完整的认证链。

3.0/3.0.2 的 validate-negotiate 必须与最初的客户端方言列表、能力、GUID、安全模式完全一致，否则关闭连接。3.1.1 使用预认证链，不接受该 IOCTL。客户端仍须约束最低方言；服务端不能区分合法选择兼容模式和客户端没有要求现代安全策略。

## 边界及恢复

CCM/GCM 验证认证标签、完整变换头和消息体后才执行任何命令。加密变换头中的会话 ID、长度、nonce、标签被篡改，以及嵌套加密/压缩等非法输入均会断开连接。复合请求在执行第一项之前验证所有片段；MessageId 信用窗口拒绝重复和旧请求。服务端记录已接收 nonce，即使使用新 MessageId 也不允许复用。发送 nonce 由随机前缀和递增计数构成。每个会话每个方向最多 65,536 个加密帧，到界限后需重新连接；没有自动换钥，以此限制重放记录的内存及 nonce 生命周期。

继续采用 M5 限制：最多 1 MiB 明文和额外 52 字节加密头、16 项复合命令、64 KiB 单次读写、32 个连接、每连接最多 16 个会话、60 秒空闲超时。断开或进程崩溃会释放普通句柄/锁，文件权威恢复已提交删除意图。重连必须重新认证并打开文件，新会话使用新密钥。没有透明故障切换承诺。

| 单独评估的能力 | 当前处理 |
| --- | --- |
| durable/persistent handles | 不授予，durable reconnect 显式拒绝 |
| leases/oplocks/目录缓存 | 已支持原生排斥保护的 EXCLUSIVE 与 Level II 数据 oplock、降级和读缓存撤销；BATCH、其余转换语义、leases 和目录缓存仍未完成（[详情](native-cache-coherence.md)） |
| CHANGE_NOTIFY | 原生异步目录通知，支持签名/加密响应；[边界及待完成验收](smb-notifications.md) |
| 多通道/会话绑定 | 不宣告，绑定拒绝 |
| 持久 ACL | 已实现基础 owner/group/DACL；[剩余兼容性](file-security.md) |
| DFS、RDMA、压缩、POSIX | 未实现 |

## 使用与验收

配置、用户和凭据登记沿用 [M5 指南](m5.zh-CN.md)。`GET /api/v1/protocols` 返回方言列表、算法和加密策略。独立 Python 客户端调用 `Connection.connect()` 可选择 3.1.1，随后 `Session(..., require_encryption=True, auth_protocol='ntlm')` 要求数据加密。

```sh
.deps/smbprotocol-venv/bin/python scripts/run_m6.py --compiler gcc --large-mib 17
.deps/smbprotocol-venv/bin/python scripts/run_m6.py --compiler clang --mode debug --sanitizers
```

Windows 使用 `scripts/windows_m6.ps1` 在临时 NTFS 副本中原生编译、测试。脚本包含 M1–M6 回归；可用 `--litmus` 加上 M3 WebDAV 测试。完整测试结果及环境见[验证记录](evidence/m6/README.md)。Explorer、系统内核 SMB 客户端、macOS、Samba torture 完整矩阵与大容量压力测试尚未验收，不能由 Python 客户端结果推断。协议依据见[英文指南](m6.md)。

SMB 3.1.1 已扩展 AES-256-CCM（3）和 AES-256-GCM（4），支持只提供单种 AES-256 算法的客户端。服务端顺序仍为 AES-128-GCM、AES-128-CCM、AES-256-GCM、AES-256-CCM；3.0/3.0.2 仍使用 AES-128-CCM。CCM/GCM 分别使用 11/12 字节 nonce，保留双向不同密钥和重放/计数限制。

签名继续使用 16 字节 SessionKey；AES-256 收发密钥必须由完整认证密钥 FullSessionKey、方向标签和预认证摘要派生 32 字节，不能先截断 Kerberos 的 32 字节密钥。NTLM 的 16 字节认证密钥也可派生 AES-256 密钥，但算法选择不会增加认证密钥的熵。续期保留原有密钥和 nonce 历史。

独立固定向量验证 KDF 和四种 AEAD 算法，逐字节篡改均应拒绝。独立客户端强制 AES-256-CCM/GCM，覆盖加密读写、续期、原始 transform 解密、篡改和重放。真实 MIT Kerberos/SPNEGO 另行验证完整 32 字节输入密钥；GCC/Clang ASan+UBSan/MSVC 定向验收在 `682b007` 全部通过（[证据](evidence/pre-m8/smb-security-682b007-remote.json)）。随后新增的无共同加密算法协商通过本地 1,137 项核心检查和 23 组独立客户端测试，其 GCC/Clang ASan+UBSan/MSVC 定向验收在 `1e92b0d` 全部通过（[证据](evidence/pre-m8/smb-nfs-1e92b0d-remote.json)）。

同一连接现在支持独立的认证交换、预认证哈希、签名/加密密钥、重放 nonce、共享树、文件句柄及异步请求；信用窗口和 AsyncId 仍属于连接。新认证失败不影响其他会话。`PreviousSessionId` 只有在新认证成功且规范用户名相同时才清理旧会话，并使用旧密钥完成待发通知、释放旧句柄和身份令牌，保留其他会话及原连接。双向同时重连通过交接协作调度锁避免循环等待；未完成的新认证十秒后回收，断线清理所有会话。独立测试覆盖四种方言、句柄/CANCEL 隔离、等待锁、重命名、错误密钥、重连竞态与容量回收。这尚未实现多通道绑定或 durable handles（[本地证据](evidence/pre-m8/smb-multisession-local.json)）。
`dbf71ea` 的 GCC、Clang ASan/UBSan、MSVC 九组多会话专项通过，但完整作业在旧 M6 测试失败：该测试错误地要求替换会话后旧 TCP 连接必须断开。修正后要求旧会话返回 USER_SESSION_DELETED，并验证原连接上的连接级 ECHO 仍成功。本地 23 组 M6 测试通过，失败及清理失败也会写入 JSON；[远程失败证据](evidence/pre-m8/smb-multisession-dbf-remote.json)保留，尚需远程重验。
