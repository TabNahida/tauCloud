# M0 feasibility implementation

[简体中文](m0.zh-CN.md) · [Checklist](../TODO.md) · [Roadmap](roadmap.md)

M0 now has executable experiments, dependency/toolchain pins, resource budgets and bilingual decisions. **M0 is accepted under the user’s 2026-10-29 functional criterion:** alternative-port interoperability proves the experimental functions; port 445 is a deployment constraint. These experiments do not constitute a runnable NAS or supported SMB/WebDAV service.

## Run from a clean checkout

Install the reference tools in [the version manifest](../toolchains.lock.json): Python, Git, xmake and the selected C++ compiler. OpenSSL 3 CLI is needed by the update fixture (the Windows runner also recognizes Git for Windows' OpenSSL). No Node/frontend tooling or privileged disk operations are required.

```sh
python3 scripts/fetch_pace.py
python3 scripts/run_m0.py --compiler gcc
python3 scripts/run_m0.py --compiler clang --sanitizers
```

An offline Git object database can be supplied with `python3 scripts/fetch_pace.py --git-source /path/to/PACE`. It is used only to export the locked commit, never as a source working tree. Builds recheck exported-source integrity. `--m0=n` excludes the experiments; `--sanitizers=y` enables Linux ASan/UBSan. Do not run simultaneous xmake configurations in the same checkout.

For independent SMB interoperability on Linux:

```sh
python3 -m venv .deps/smb-venv
.deps/smb-venv/bin/python -m pip install -r experiments/m0/interop-requirements.txt
python3 scripts/run_m0.py --compiler gcc --smb-python .deps/smb-venv/bin/python
```

A second client can be installed in a separate environment from `experiments/m0/smbprotocol-requirements.txt`; select it with `--smb-client smbprotocol`. Requirements pin transitive versions but are not a complete hashed offline package mirror.

On Windows, first acquire PACE in a Windows checkout with `python scripts/fetch_pace.py`. Then run from PowerShell:

```powershell
./scripts/windows_m0.ps1 -WithSmb
```

The Windows wrapper copies only the experiment sources and verified PACE export into a fresh temporary directory on the host, creates the optional client environment there, runs MSVC and NTFS/named-pipe experiments, copies the report back to `build/m0/windows-msvc.json`, then removes its own temporary directory. `-Source` accepts an existing checkout, including a WSL UNC source. Omit `-WithSmb` for the dependency-free-client subset; skipped interoperability is reported explicitly. It never changes SMB services, firewall rules, disk layouts or existing shares.

## Evidence and scope

Saved reviewable results are in [`docs/evidence`](evidence/README.md). Each run records host/Python/compiler tooling, commands, outputs, elapsed time and a digest of the experiment sources. A nonzero probe status fails the runner. Historical reports retain their original `incomplete` status. The explicit user decision on 2026-10-29 supersedes the port-445 gate; it does not change any measured result.

| Experiment | What it establishes | What it does not establish |
| --- | --- | --- |
| PACE acquisition | Locked committed content; network/offline exports agree; dirty adjacent files ignored | Fully hermetic OS/tool/package supply chain |
| C++ runtime | Bounded jobs/bytes through completion, owner affinity, rejection, cancellation, expiry, exception and abandoned-context cleanup | Force-cancellable kernel I/O or production process budgets |
| C++ filesystem | ext4/NTFS root-relative opens, link/traversal rejection, live IDs, rename/delete while open, flush calls, case observation | Power-loss safety, persistent NFS handles, full Windows nested traversal |
| Recovery | Real kill/restart, separate adopter, exclusive domain owner, sibling continuity, scoped/expiring grants, version/generation rejection | Production service ACLs, multiplexed IPC or durable supervisor state |
| Updates | Ed25519 trust separation, side-by-side staging, FULL SQLite journal, five abrupt exit points, guarded rollback | Executable installer, schema migration or power-failure simulation |
| SMB vectors / interoperability | NTLMv2 enrollment/key vectors; original loopback fixture with independent signed-open/tamper tests | General SMB server, native client matrix, MIC/channel binding or safe external exposure |
| Windows host | Exact OS and fixture filesystem, port-445 conflict detection, alternative loopback listener | Standard-port coexistence or remote firewall/client reachability |

`filesystem.cpp` uses newly created directories under the native temporary directory. Windows therefore tests NTFS instead of the source checkout's WSL filesystem. To test a different Linux filesystem, set `TMPDIR` to a disposable directory on that filesystem and record the mount. Native storage APIs are exercised only against these files. The RAID fixture design is documented, not executed against host disks.

Independent-client negotiate/authenticate/signed-open and tamper-rejection evidence on alternative loopback ports closes M0. Standard-port coexistence and native-client deployment remain later SMB release concerns; M3 WebDAV remains the first usable file backend.
