# Shared file security descriptors

The Full SMB/NFS expansion adds a file-authority DACL, in addition to existing space/share authorization. A successful application grant is necessary but no longer sufficient to read or modify a restricted object. This implementation is service-enforced on both Linux and Windows; it does not alter host NTFS/POSIX ownership. Direct host access remains outside this boundary.

## Implemented behavior

SMB QUERY_INFO/SET_INFO security information supports owner, primary group and persistent DACLs. READ_CONTROL, WRITE_DAC and WRITE_OWNER are checked on the open. Owners receive the standard implicit READ_CONTROL/WRITE_DAC rights unless an effective OWNER RIGHTS ACE overrides them. NULL/absent and empty DACLs remain distinct. Simple allow/deny ACEs are evaluated in their original order, with generic rights mapped to file rights. MAXIMUM_ALLOWED and MxAc intersect DACL access, application authorization and readonly restrictions. Existing SMB opens retain the rights granted when opened; application policy revocation still closes/revokes them. When a request discovers an invalid authentication session, every authority open and lock in that SMB session is drained before pending-lock failure replies are sent; reconnect does not depend on old-transport teardown.

Parent FILE_DELETE_CHILD can grant DELETE; parent FILE_LIST_DIRECTORY can grant FILE_READ_ATTRIBUTES. New object creation requires the parent's ADD_FILE/ADD_SUBDIRECTORY right and grants the creating open its requested access. The inherited descriptor controls subsequent opens. Object/container, inherit-only and no-propagate flags, CREATOR OWNER/GROUP replacement and legacy versus automatic inherited flags are supported. SET changes the selected descriptor fields without silently replacing an existing child's descriptor. CREATE SecD supports explicit/protected initial DACLs, with ownership and size validation before creating the file. Descriptor/ACE offsets, bounds, revisions and aggregate size are validated; unknown ACE families are not interpreted as allows.

Descriptors are keyed by the native object incarnation, so rename and process restart preserve them, while a replacement object receives new security. File database schema 6 adds `security_descriptors`; upgrading schema 5 first writes `file*.pre-v6.db`. Current file schema 7 adds per-open SMB close intents; metadata backup accepts schemas through 7 and refuses unresolved deletion. As with other native-identity metadata, copying file bytes onto new native objects does not recreate their security descriptors.

Each local username and group has a deterministic service SID: `S-1-5-21` followed by four little-endian words from the first 16 SHA-256 bytes of `tauCloud/user/<name>` or `tauCloud/group/<name>`. These are service principals, not the host service account or Active Directory mappings. Identity signs the current account/group membership into each short-lived grant. Everyone and Authenticated Users match authenticated service callers. By default a user can set an owner only to their own SID and a group only to a current service group (or retain the existing group). Administrator API status does not imply SeRestorePrivilege or SeSecurityPrivilege. An open requesting ACCESS_SYSTEM_SECURITY fails with STATUS_PRIVILEGE_NOT_HELD so native ACL tools can retry a DACL-only operation; query/set SACL on an ordinary open still fails access checks.

Legacy objects without a stored descriptor preserve the earlier space/share policy through an Everyone full-access default DACL; their default owner is the space owner. New objects use the creating user's SID and the space's primary group. Restricting a parent's DACL affects subsequently created children; it is not a recursive permission rewrite of legacy objects.

NFSv3 READ/WRITE and namespace changes, NFSv4 OPEN and ACCESS, and the core/WebDAV/FTP file paths check the same descriptor. NFS chmod/ownership changes require the corresponding descriptor rights. ACCESS reports the intersection with the export policy. NFS change counters include descriptor changes. Staged core/DAV/FTP replacements retain the destination descriptor, and permission is checked again before publication. Copies check each source and overwritten descendant; new copies inherit destination security, including through private staging parents. DAV LOCK on an unmapped URL checks parent ADD_FILE and saves the inherited descriptor for the newly created resource. NFS mode/UID/GID now derive from the same descriptor rather than independent cosmetic metadata; the NFS rules below describe the implemented subset.

An SMB share may enable `access_based_enumeration:true` in its complete create/update definition. TREE_CONNECT advertises the flag, and directory snapshots omit entries whose DACL does not grant READ_DATA/LIST_DIRECTORY, READ_EA, READ_ATTRIBUTES and READ_CONTROL. The default remains false. This filters enumeration only; direct opens always use access checks.

## Security QUERY_INFO

Security `QUERY_INFO` treats its flags independently from `SET_INFO`: unknown bits, including the two DACL protection modifiers together, are ignored. Owner/group/DACL selectors still require READ_CONTROL; SACL remains denied and recognized but unimplemented label/resource/scope/backup selectors return NOT_SUPPORTED. An empty effective selector returns the 20-byte self-relative header, without exposing descriptor sections or requiring READ_CONTROL. Returned control bits describe only requested sections. Unused query input-buffer fields are ignored.

An undersized security query returns the exact required descriptor size. SMB 3.1.1 wraps that size in a single error context (ErrorId zero); earlier dialects return the four-byte size directly. Both synchronous completion and a related query resumed after an asynchronous CREATE preserve this body. `tests/smb_security_query.py` covers 20 signed/encrypted groups across 2.1/3.0/3.0.2/3.1.1; see [local evidence](evidence/pre-m8/smb-security-query-local.json). The corrected query removed the initial descriptor-query failure in original Samba reauth3–5. The subsequent anonymous-context implementation passes reauth2/3; correct classic-oplock handling for SET_SECURITY then lets reauth4 pass. Reauth5 still fails later operations (see [cache evidence](evidence/pre-m8/smb-security-oplocks-local.json)). This does not establish full ACL or session conformance.

## Scoped ownership authority

Administrators can explicitly assign SMB ownership authority per user and space through `POST /api/v1/smb-owner-authority`:

```json
{"id":"restore-alice","username":"alice","space":"team","mode":"restore"}
```

`mode` is `none`, `take` or `restore`; updates include `update:true` and all fields. The user/space pair is unique. Listing and writing require administrator authority, changes are audited, and the normal policy revocation path drains existing handles. The authority is signed into SMB grants only; it neither enables a share nor grants application write access. Administrator status alone never supplies this authority.

`take` grants WRITE_OWNER despite a denying DACL, including MAXIMUM_ALLOWED, but ownership can still be assigned only to the caller. `restore` permits arbitrary validated owner/group SIDs in SET_INFO and CREATE SecD. SET_INFO still requires WRITE_OWNER on the handle; restoration overrides that DACL right only for opens carrying FILE_OPEN_FOR_BACKUP_INTENT. Ordinary opens and MxAc retain their DACL access. Creation resolves CREATOR OWNER/GROUP inheritance against the restored identities, including ownership-only SecD descriptors.

These are scoped ownership permissions, not a complete implementation of Windows SeBackupPrivilege/SeRestorePrivilege: neither grants data access, WRITE_DAC or SACL access, nor bypasses readonly shares or another space. Full backup/restore and audit privileges remain open. Selected NULL owner/group fields fail before changing any descriptor field. Ownership changes use the existing shared set-ID clearing rules.

## NFS mode and ACL synchronization

NFSv3/v4 `mode` changes update the shared ordered DACL. All 4096 defined twelve-bit modes roundtrip, including owner/group restrictions that differ from Everyone. Named grants are capped by group mode and inherit-only ACEs are retained. An ACL-only update derives mode from OWNER@/GROUP@/EVERYONE@; a combined update applies mode before ACL. Legacy objects without descriptors retain their previous effective access; their reported mode now reflects that access, not an old unenforced projection.

NFSv4 exposes `acl` and `aclsupport` (ALLOW/DENY), including GETATTR, VERIFY/NVERIFY, READDIR, SETATTR and creation. READ_ACL/WRITE_ACL are checked separately from data and timestamp permissions. READDIR returns RDATTR_ERROR for inaccessible requested ACLs when asked. Invalid principals/ACLs are rejected before creation or truncation. Limits are 1024 ACEs and 64 KiB attribute/descriptor payloads. Audit/alarm and separate dacl/sacl attributes remain unsupported.

OWNER@, GROUP@ and EVERYONE@ map to shared service trustees. Named users/groups use `<service-name>@taucloud` resolved through export UID/GID mappings; an unmapped SMB trustee roundtrips as `sid-<binary-SID-hex>@taucloud`. Special identifiers ignore IDENTIFIER_GROUP. The `acl` attribute clears INHERITED_ACE as required by RFC 8881, while internal inheritance still records the SMB flag. GROUP@ follows primary-group changes and child inheritance. This is not domain/Kerberos identity resolution.

Signed AUTH_SYS grants contain only verified supplied primary/supplementary groups; omitted memberships cannot silently grant rights and root squash strips groups. New objects take the authenticated mapped UID/GID; existing numeric aliases are preserved where their mapping still matches the descriptor. NFS reads/OPEN/ACCESS allow execution-authorized ordinary file reads per RFC 8881 section 6.3.1.1, without widening the SMB descriptor. The complete NFS ownership/domain model remains open.

The three special mode bits persist in the same descriptor. NFSv4 `mode_set_masked` changes only requested bits; high-only masks leave the DACL byte-for-byte unchanged, while low-bit masks synchronize it. It is write-only and SETATTR-only, cannot accompany `mode`, and rejects undefined bits even outside the mask. VERIFY/NVERIFY validate mode values within the complete typed attribute sequence.

A setgid directory passes its group to new objects and its setgid bit to new directories. Explicit NFS setgid requires the caller's verified group membership; inheriting it does not. Setting setuid additionally requires the caller to own the object, even if WRITE_ACL was delegated. Sticky directories allow removal/rename/replacement only by the parent or target owner, in addition to normal access checks. The shared authority enforces this for NFS, SMB disposition/delete-on-close/rename and core/DAV/FTP namespace operations. Already accepted SMB delete intent retains its authorization until reaping.

Data writes/truncation and file ownership changes clear setuid/setgid; staged uploads clear the copied bits before publication. This applies across NFS, SMB, core and DAV/FTP writers. Clearing occurs before potentially partial data mutations, so failed storage writes cannot leave modified set-ID content. These are service permissions and client-visible execution metadata; the service does not chmod/chown host files or execute client files. Out-of-band host access remains outside this boundary.

## Validation and remaining work

`tests/smb_security_integration.py` uses independent smbprotocol/pyspnego and pinned pynfs wire codecs. It covers migration, malformed descriptors, access masks, ownership boundaries, group revocation, inheritance, SecD, rename/restart, new-incarnation isolation and cross-protocol denial, including NFS writes after changing the active writer protocol, staged DAV copying/replacement and LOCK-created resource inheritance. It runs in the M7 runner and the GCC/Clang ASan+UBSan/MSVC Actions matrix.

Native Windows Server 2025 acceptance uses the encrypted SMB redirector with PowerShell Get-Acl/Set-Acl: SID/DACL roundtrip, denying writes while preserving reads, restoring the descriptor and deleting the file. These are ordinary DACL operations, not SACL or privileged-owner acceptance.

The unmodified Samba `smb2.acls` suite now passes all 14 cases locally when the fixture explicitly assigns restoration authority, including SDFLAGSVSCHOWN. The original unprivileged 13-case selection remains a separate regression; the earlier privileged-owner failure is preserved in its historical evidence. `tests/smb_owner_integration.py` independently checks assignment authorization, take/restore boundaries, backup intent, arbitrary SID validation, creation inheritance, revocation and restart. Both profiles and the ownership checks are wired into Actions; remote acceptance of this change is pending. See [local evidence](evidence/pre-m8/smb-owner-local.json).

Full SMB/NFS remains open. Remaining security work includes complete backup/restore privileges, SACL/audit/mandatory-label and conditional/object ACEs, domain principal/name lookup, Windows Kerberos/RPCSEC_GSS acceptors, full NFS ownership/domain mapping and complete ACL interoperability, comprehensive native Windows security-editor acceptance and expanded upstream tests. Other protocol gates (streams, links, leases, durable/replay/multichannel, delegation and callbacks) remain in TODO.
