# M7 — Experimental NFS backend

This is a **partial M7 implementation**, not completion of the M7a/v4.1 or M7b/v3 compatibility gates. The pre-M8 work adds share reservations, byte locks and restart reclaim, independent upstream tests and native Linux and macOS NFSv3 client checks. Mandatory-operation coverage, NLM/NSM and the full operating-system client matrix remain unfinished. The API retains `M7-preview` and `full_conformance: false`. See the [pre-M8 acceptance record](evidence/pre-m8/README.md) for current results; the original M7 evidence remains historical.

## Configuration and authorization

`nfs_port` defaults to `0` (disabled). Choose an unused port from 1024–65535; it must not overlap HTTPS, DAV, FTP, SMB or the active FTP passive range. Binding remains `127.0.0.1`. NFS, MOUNT and read-only portmapper/rpcbind requests use this same TCP port. Standard-port exposure, UDP and system rpcbind integration are not configured.

Use the existing admin HTTPS API to create a space, an NFS share and explicit identity mappings. The usual bearer token, CSRF/origin rules and Idempotency-Key apply. Example request bodies:

```json
{"id":"nfs","space":"alice","exposures":{"nfs":"rw"}}
```

Then `POST /api/v1/nfs-exports`:

```json
{
  "id":"nfs",
  "trust":"loopback-auth-sys",
  "anonymous":"guest",
  "uids":{"1000":"alice"},
  "gids":{"1000":"unix-users"},
  "enabled":true
}
```

`guest`, `alice`, the `unix-users` group and Alice's membership must already exist. Root squash is mandatory; UID 0 is mapped to `guest` without trusting its supplied groups. Every non-root primary/supplementary GID must map to a group of the selected user; unknown values are denied. `guest` needs explicit space rights to access anything. Granting no rights is a useful deny-root configuration. For updates send `update:true` and the complete export body. `enabled:false` denies new grants to existing handles. Existing mixed-writer exclusion still applies across the whole space.

AUTH_SYS is forgeable client-supplied identity on a trusted local connection. It does not authenticate a tauCloud password. RPCSEC_GSS/Kerberos is a separate future profile. The service does not accept GSS as AUTH_SYS or silently downgrade it.

## Implemented paths and limits

| Area | Experimental implementation |
| --- | --- |
| Transport | TCP record marking, at most 64 nonempty fragments and 256 KiB per record; strict bounded XDR; 16 connections; executor 2 workers/16 queued tasks |
| File authority | Confined native I/O through authenticated IPC, fresh export grants, quota, shared protocol guards, persistent mutation intents/results |
| Handles | 50-byte MAC-protected export/object UUIDs; native incarnation evidence; persistent per-domain mapping; rename relocation and stale detection |
| v4.1 | Client/session lifecycle and connection binding, slot replay, OPEN upgrades/downgrades, share reservations, LOCK/LOCKT/LOCKU, CLOSE, owner-bound OPEN/lock reclaim, selected file/attribute operations |
| Session limits | 32 sessions, up to 8 slots/session, 16 operations/compound, 128 KiB negotiated messages/cache, 60-second lease/grace; multiple exports/session, one open/owner/file |
| v3 | GETATTR/SETATTR, LOOKUP, ACCESS, READ/WRITE, guarded/unchecked/exclusive CREATE, MKDIR, REMOVE/RMDIR, RENAME with closed-destination replacement, READDIR/PLUS, filesystem information and COMMIT |
| v3 companion services | Selected MOUNT v3 operations and read-only GETPORT/GETADDR; **no NLM/NSM**, no rpcbind mutation or CALLIT |
| Writes | 64 KiB per operation; full short-write loop and native flush before FILE_SYNC, including requests for UNSTABLE; real COMMIT; new reboot verifier |
| Replay | Exact v4 slot replies and false-retry rejection; up to 10,000 durable v3 mutation replies; domain mutation history bounded at 100,000; uncertain/cache-full fails closed |
| Enumeration | At most 1,024 returned entries and 200 KiB internal metadata; relocation search 4,096 visited nodes; namespace reconciliation up to 10,000 entries, also bounded by the authorization deadline |

OPEN/share ownership and exact lock ranges are persisted before success. Partial unlock splits ranges; competing owners and conflicting I/O are rejected. After restart, matching client/principal/open/lock owners reclaim during grace, before RECLAIM_COMPLETE. Sessions/slots remain nonpersistent. AUTH_SYS sessions can multiplex mapped users from one trusted host, while each open/lock retains its principal and slot replay hashes include caller identity. A session may hold OPENs in multiple exports. Each cached reply records up to 64 distinct export grants and rechecks their read/write authority and scope before replay; a revoked or retargeted export fences that reply with DELAY without repeating mutations. New slot sequences accessing unaffected exports continue normally.

Only directories and regular files with portable NFC names are in scope. Hardlinks, symlinks/reparse points and cross-volume traversal remain unavailable. Mode and numeric ownership are durable NFS projections keyed by native incarnation, shared across export aliases; they do not replace application ACLs or change host UID/SID ownership. Ownership setters accept the mapped caller's UID/groups, with root squash. Access/modify timestamps update the pinned native object (100 ns precision on Windows). Replacing closed destinations is supported; deleting/replacing a destination with active NFS opens returns FILE_OPEN. Persistent change counters combine native ctime/ChangeTime, size, mtime and projected metadata, exclude atime, and survive aliases and restarts. Namespace operations return real non-atomic change_info. EXCLUSIVE4_1 advertises supported creation attributes; UNCHECKED existing-file truncation runs after share checks and returns the actual attribute mask. Complete unlink-open, full cache/client consistency, large-tree/load and power-loss gates remain open.

Linux stable identity requires native exportfs tokens and birth evidence; Windows preview eligibility is NTFS. Metadata-only backups strip NFS export enrollments and omit handle keys/mappings, replay caches and OPEN recovery state. Restore requires re-enrollment and invalidates pre-restore handles. Windows namespace flush keeps the limitation documented in M2; FILE_SYNC evidence here covers file data, not an untested promise about sudden-power-loss survival of newly created names. See [ADR 0010](decisions/0010-nfs-preview.md).

The v4.1 pseudo-root now supports paged READDIR, LOOKUP/LOOKUPP and SECINFO. Export names are filtered with the same UID/GID, root-squash, enabled-user and space-rights rules as file access. Root change attributes advance with the policy revision; pagination verifiers bind the caller and namespace revision. A page resolves at most 32 export roots. READDIR accounts for the complete result within maxcount, returns TOOSMALL when no entry fits, rejects reserved cookies, and returns NOT_SAME for a changed verifier. Cached namespace replies are fenced when visible exports change.

Protocol basis: [RFC 8881 READDIR](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.23). The selected replay-revocation policy above remains part of this restricted profile, not a claim of complete session conformance.

## Reproduction and evidence

```sh
python3 -m venv .deps/nfs-venv
.deps/nfs-venv/bin/pip install -r tests/smb-requirements.txt -r tests/nfs-requirements.txt
.deps/nfs-venv/bin/python scripts/run_m7.py --compiler gcc
.deps/nfs-venv/bin/python scripts/run_m7.py --compiler clang --mode debug --sanitizers
```

The runner verifies pinned linux-nfs/pynfs sources, generates codecs into `build/nfs-client`, and runs M1–M7 regression. `scripts/prepare_pynfs.py` additionally prepares the unmodified upstream runner; `tests/pynfs_acceptance.py` runs explicit upstream test selections and retains failures. `tests/nfs_state_integration.py` covers competing principals/locks and restart reclaim; `tests/nfs_attributes_integration.py` covers native timestamps and alias persistence. `tests/nfs_namespace_integration.py`, included in the GCC/Clang/MSVC runner, covers pseudo-root pagination, multiple exports and revoked/retargeted cached authority. The Linux native-client job additionally mounts the pseudo-root and opens files simultaneously in two exports. Upstream GPL tooling is not linked into the server. GitHub Actions runs native Linux kernel mounts on disposable data using privileged mount/umount; ordinary server/codecs tests need no privileged ports. Selected passing cases do not establish full conformance.
