# M7 — Experimental NFS backend

**2026-11-04 update: shared DACLs now enforce NFS mode and simple NFSv4 ACLs, with verified AUTH_SYS groups and cross-protocol access checks. Full security conformance remains open; see [shared file security](file-security.md).**

**Scope update (2026-10-31): the user requires full SMB/NFS standards compatibility before further M8 development. The limited-profile results below remain valid evidence, but do not close that expanded milestone. See [TODO](../TODO.md).**

M7a and M7b now pass within the existing ADR 0010 confined regular-file/directory, loopback AUTH_SYS profile. Required operation behavior is mapped in [the coverage report](nfs-operation-coverage.md); 145 selected upstream cases pass with 121 exclusions retained. Linux kernel v3/v4.1, macOS 15.7.9 v3 and Windows Server 2025 Client for NFS v3 roundtrips pass. Linux also proves native blocking NLM locks, callback grant and reboot reclaim, and v4.1 close-to-open revalidation after equal-size/restored-mtime external writes. macOS and Windows use `nolock`. This is limited compatibility, not full RFC 8881 conformance; `full_conformance: false` remains correct. See [fixed-commit acceptance](evidence/pre-m8/README.md).

## Configuration and authorization

`nfs_port` defaults to `0` (disabled). Choose an unused port from 1024–65535; it must not overlap HTTPS, DAV, FTP, SMB or the active FTP passive range. `nfs_address` defaults to `127.0.0.1`; the only other accepted address is `127.0.0.2`, for isolated native-client testing. NFS, MOUNT and read-only portmapper/rpcbind requests use this same TCP port. MOUNT implements MNT/DUMP/UMNT/UMNTALL/EXPORT, with principal-scoped mount records and policy-filtered export discovery. Anonymous discovery uses the root-squashed view. rpcbind supplies GETPORT/GETADDR, DUMP and v4 GETVERSADDR for implemented TCP programs and NSM over UDP. The same UDP port admits only read-only discovery and NSM, never NFS file operations. Standard-port exposure is not configured automatically.

Use the existing admin HTTPS API to create a space, an NFS share and explicit identity mappings. The usual bearer token, CSRF/origin rules and Idempotency-Key apply. Example request bodies:

```json
{"id":"nfs","space":"alice","exposures":{"nfs":"rw"}}
```

Then `POST /api/v1/nfs-exports`:

```json
{
  "id":"nfs",
  "trust":"loopback-auth-sys",
  "anonymous":"guest",
  "uids":{"1000":"alice"},
  "gids":{"1000":"unix-users"},
  "enabled":true
}
```

`guest`, `alice`, the `unix-users` group and Alice's membership must already exist. Root squash is mandatory; UID 0 is mapped to `guest` without trusting its supplied groups. Every non-root primary/supplementary GID must map to a group of the selected user; unknown values are denied. `guest` needs explicit space rights to access anything. Granting no rights is a useful deny-root configuration. For updates send `update:true` and the complete export body. `enabled:false` denies new grants to existing handles. Existing mixed-writer exclusion still applies across the whole space.

AUTH_SYS is forgeable client-supplied identity on a trusted local connection. It does not authenticate a tauCloud password. Linux RPCSEC_GSS/Kerberos is now a separate authenticated profile with real GSSAPI integrity/privacy and principal mapping; see [configuration and remaining gates](nfs-kerberos.md). The service does not accept GSS as AUTH_SYS or silently downgrade it.

## Implemented paths and limits

| Area | Experimental implementation |
| --- | --- |
| Transport | TCP record marking, at most 64 nonempty fragments and 256 KiB per record; strict bounded XDR; 16 connections; executor 2 workers/16 queued tasks |
| File authority | Confined native I/O through authenticated IPC, fresh export grants, quota, shared protocol guards, persistent mutation intents/results |
| Handles | 50-byte MAC-protected export/object UUIDs; native incarnation evidence; persistent per-domain mapping; rename relocation and stale detection |
| v4.1 | Client/session lifecycle and connection binding, slot replay, OPEN upgrades/downgrades, share reservations, LOCK/LOCKT/LOCKU, CLOSE, owner-bound OPEN/lock reclaim, selected file/attribute operations |
| Session limits | 32 sessions, up to 8 slots/session, 16 operations/compound, 128 KiB negotiated messages/cache, 60-second lease/grace; multiple exports/session, one open/owner/file |
| v3 | GETATTR/SETATTR, LOOKUP, ACCESS, READ/WRITE, guarded/unchecked/exclusive CREATE, MKDIR, REMOVE/RMDIR, RENAME with closed-destination replacement, READDIR/PLUS, filesystem information and COMMIT |
| v3 companion services | MOUNT v3 discovery/mount records and read-only GETPORT/GETADDR/DUMP/GETVERSADDR; NLMv4 synchronous locks and NSMv1 recovery; no rpcbind mutation or CALLIT |
| Writes | 64 KiB per operation; full short-write loop and native flush before FILE_SYNC, including requests for UNSTABLE; real COMMIT; new reboot verifier |
| Replay | Exact v4 slot replies and false-retry rejection; up to 10,000 durable v3 mutation replies; domain mutation history bounded at 100,000; uncertain/cache-full fails closed |
| Enumeration | At most 1,024 returned entries and 200 KiB internal metadata; relocation search 4,096 visited nodes; namespace reconciliation up to 10,000 entries, also bounded by the authorization deadline |

OPEN/share ownership and exact lock ranges are persisted before success. Partial unlock splits ranges; competing owners and conflicting I/O are rejected. After restart, matching client/principal/open/lock owners reclaim during grace, before RECLAIM_COMPLETE. Sessions/slots remain nonpersistent. CREATE_SESSION/BIND_CONN_TO_SESSION can now bind TCP backchannels with AUTH_NONE/AUTH_SYS CB_NULL probes; BACKCHANNEL_CTL updates the callback program/security and replaces CB_NULL probes; in-flight CB_COMPOUND requests retain their slot until completion or confirmed disconnection. Unknown GSS handles still return NOENT. SET_SSV returns INVAL for negotiated SP4_NONE, and obsolete v4.0 operations return NOTSUPP. AUTH_SYS sessions can multiplex mapped users from one trusted host, while each open/lock retains its principal and slot replay hashes include caller identity. A session may hold OPENs in multiple exports. Each cached reply records up to 64 distinct export grants and rechecks their read/write authority and scope before replay; a revoked or retargeted export fences that reply with DELAY without repeating mutations. New slot sequences accessing unaffected exports continue normally.

Only directories and regular files with portable NFC names are in scope. Hardlinks, symlinks/reparse points and cross-volume traversal remain unavailable. Mode and numeric ownership derive from the shared persistent descriptor, keyed by native incarnation across export aliases. Chmod changes shared access checks; host UID/SID ownership is unchanged. Ownership setters accept the mapped caller's UID/groups, with root squash. Access/modify timestamps update the pinned native object (100 ns precision on Windows). REMOVE and atomic RENAME replacement retain the exact native descriptor for active NFS opens, bounded to 128 retained objects per file domain. Old handles continue accessing the old object while the namespace exposes the replacement. Retained bytes remain charged once per object until the last OPEN closes or expires; a periodic lease sweep also runs without client traffic. Persistent change counters combine native ctime/ChangeTime, size, mtime and projected metadata, exclude atime, and survive aliases and restarts. Namespace operations return real non-atomic change_info. EXCLUSIVE4_1 advertises supported creation attributes; UNCHECKED existing-file truncation runs after share checks and returns the actual attribute mask. Retained objects now have journaled private links in the reserved `.tc-nfs-*` namespace, invisible to all client protocols. Original paths still change atomically; ordinary user hardlinks remain rejected. The journal is written before link creation, and recovery distinguishes an interrupted preparation from a completed unlink/replacement. Final reaping is itself journaled. Native identity and quota survive NFS-worker and file-domain crashes and all-service restart, with matching OPEN reclaim. Linux and Windows restart/interrupted-journal assertions and corrected SQLite cleanup pass. Full cache/client consistency, large-tree/load and power-loss gates remain open.

Linux stable identity requires native exportfs tokens and birth evidence; Windows preview eligibility is NTFS. Metadata-only backups strip NFS export enrollments and omit handle keys/mappings, replay caches and OPEN recovery state. Restore requires re-enrollment and invalidates pre-restore handles. Windows namespace flush keeps the limitation documented in M2; FILE_SYNC evidence here covers file data, not an untested promise about sudden-power-loss survival of newly created names. See [ADR 0010](decisions/0010-nfs-preview.md).

The v4.1 pseudo-root now supports paged READDIR, LOOKUP/LOOKUPP and SECINFO. Export names are filtered with the same UID/GID, root-squash, enabled-user and space-rights rules as file access. Root change attributes advance with the policy revision; pagination verifiers bind the caller and namespace revision. A page resolves at most 32 export roots. READDIR accounts for the complete result within maxcount, returns TOOSMALL when no entry fits, rejects reserved cookies, and returns NOT_SAME for a changed verifier. Cached namespace replies are fenced when visible exports change.

Protocol basis: [RFC 8881 READDIR](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.23). The selected replay-revocation policy above remains part of this restricted profile, not a claim of complete session conformance.


### CREATE_SESSION channel negotiation

Fore and back channel message limits never exceed the client's offers. The backchannel operation and concurrent-request counts remain exactly as offered, as required by [RFC 8881 §18.36.3](https://www.rfc-editor.org/rfc/rfc8881.html#section-18.36.3); these limits alone do not grant a backchannel. Binding and path validation are described below. CREATE_SESSION retries return the original session and negotiated values. Independent small/large-limit, replay and usable-session checks pass under Clang ASan/UBSan. The unmodified `create_session` selection yields 28 passing cases and three delegation-dependent failures (DELEG5/6/7), retained in [evidence](evidence/pre-m8/nfs-session-negotiation-local.json). Three-platform acceptance passes at `1e92b0d` ([remote evidence](evidence/pre-m8/smb-nfs-1e92b0d-remote.json)).

## NLM/NSM recovery profile

NLMv4 TEST/LOCK/CANCEL/UNLOCK uses bounded 64-bit ranges, shared/exclusive ownership, partial unlock, deadlock detection and blocking GRANTED callbacks. Locks coordinate with v4 byte locks by native object identity. NFSv3 I/O remains advisory because its requests do not carry a lock owner. Fresh application authority is checked on acquisition and conflicts; an original owner may release locks after revocation. A rejected blocking conversion restores its prior lock ranges.

Grants and remaining reclaim ranges are journaled before success. A restart advances the persistent NSM state, notifies the local client and applies a 60-second grace. Only previously recorded owner/file/ranges can reclaim; a second crash during partial reclaim preserves the remaining ranges. Client reboot notifications release the old incarnation's locks; stale notifications cannot revoke newer locks.

NSMv1 STAT/MON/UNMON/UNMON_ALL/NOTIFY is available over TCP and bounded UDP. SIMU_CRASH is unavailable. Callbacks resolve only the fixed NLM/NSM programs through `127.0.0.1` rpcbind (`nfs_peer_rpcbind_port`, default 111), always target that trusted local host and use 750 ms deadlines and 4 KiB payloads. Limits are 128 owners, 1,024 ranges per owner, 128 blocked requests and 64 peers/monitors. The profile does not implement NLM v1–3, MSG/RES calls, DOS SHARE/UNSHARE or non-monitored locks. It does not permit arbitrary callback destinations or expose a general RPC proxy. Native Linux kernel callback/reclaim acceptance passes at `3e019a8`; the kernel sends zero NSM state on server-reboot reclaim, so matching persisted ownership/ranges retain their known peer state. macOS/Windows `nolock` results do not count as lock recovery evidence.

## TCP backchannel transport

NFS RPC CALLs and REPLYs can now share an established TCP connection. A single bounded writer serializes ordinary responses and reverse RPC frames. CREATE_SESSION can negotiate the backchannel flag for offered AUTH_NONE/AUTH_SYS credentials; BIND_CONN_TO_SESSION supports fore, back and both roles and rejects invalid direction values or changes to an existing binding. A CB_NULL probe uses the client-selected program and the exact selected callback credential. Replies are matched by XID and transport; unknown, duplicate, stale, malformed or cross-connection replies cannot validate a path. Probes expire after five seconds. BACKCHANNEL_CTL invalidates older CB_NULL probes, and successful rebinding can reprobe a failed path. SEQUENCE reports CB_PATH_DOWN until at least one path for the client is verified; disconnect and session destruction remove that authority.

Callback RPC version is **1**, as defined by the [RFC 5662 NFS4_CALLBACK XDR](https://www.rfc-editor.org/rfc/rfc5662.html#section-2). RFC 8881 §18.36.3 prose says 4, but that contradicts the wire XDR and the unmodified pynfs callback program. The original version-4 failure and corrected version-1 results are preserved. The initial transport/probe evidence below predates the sequenced callbacks described next; delegation/recall and RPCSEC_GSS callbacks remain unfinished. Independent lifecycle checks and original pynfs CSESS20/CSESS21 pass locally under Clang ASan/UBSan ([local evidence](evidence/pre-m8/nfs-backchannel-local.json)); the transport lifecycle now passes all three remote platforms, with original pynfs checks on both Linux compilers ([remote evidence](evidence/pre-m8/smb-nfs-1e92b0d-remote.json)).

### Sequenced backchannel probes

After CB_NULL succeeds, the server sends a CB_COMPOUND containing a solo CB_SEQUENCE. Only a complete valid reply makes that transport operational. A single slot per session bounds memory and concurrency regardless of the client's slot offer. Session ID, sequence, slot, tag, result count, status and exact record length are checked before advancing the sequence or renewing the lease. Slot maxima may grow beyond the initial offer or shrink; the server continues using slot zero, which fits every advertised maximum. Request/response limits include the RPC header and selected callback credential.

An unanswered request retains its exact CB_COMPOUND body and sequence across timeout, program/security replacement and connection loss. Per [RFC 8881 §2.10.6.2](https://www.rfc-editor.org/rfc/rfc8881.html#section-2.10.6.2), it cannot be retried while its original transport remains connected. A timeout or malformed result requests transport closure; the slot remains occupied until the runtime confirms disconnection. Only then can another bound transport carry the retry. BIND/BACKCHANNEL_CTL cannot bypass this barrier. A valid reply to the original program/security configuration can complete its slot, but cannot validate a newer callback configuration. Unknown XIDs, replies on a different connection and replies from destroyed sessions cannot complete it. Losing every backchannel while a request remains unresolved sets CB_PATH_DOWN_SESSION; a new binding clears that flag, while CB_PATH_DOWN remains until sequenced path validation succeeds. These rules follow [RFC 8881 §20.9](https://www.rfc-editor.org/rfc/rfc8881.html#section-20.9) and [slot flow control](https://www.rfc-editor.org/rfc/rfc8881.html#section-2.10.6.1).

The independent TCP client checks corruption, replay, transport loss, session recreation, flow control and resource bounds. Initial sequencing evidence is retained [here](evidence/pre-m8/nfs-cb-sequence-local.json); its live-transport retry behavior was incorrect and is superseded by the [disconnect-before-retry correction](evidence/pre-m8/nfs-cb-retry-local.json). The corrected independent tests also cover credential removal and an asynchronously requested-but-unconfirmed close. Solo CB_SEQUENCE probes and their disconnect-before-retry correction pass the targeted three-platform run at `c425fc6` ([remote evidence](evidence/pre-m8/nfs-cb-retry-remote.json)). CB_NOTIFY_LOCK is described below; CB_RECALL, delegation authority and RPCSEC_GSS callbacks remain unfinished.

### Blocking lock availability notifications

OPEN now advertises OPEN4_RESULT_MAY_NOTIFY_LOCK. A denied READW_LT/WRITEW_LT request can register a bounded hint keyed by client, principal, file and lock owner. A later nonblocking attempt cancels that hint. Maintenance checks the competing NFSv4/NLM locks, the waiting OPEN, current ACLs and fresh export authority before sending CB_NOTIFY_LOCK with the exact filehandle and lock owner. Closed OPENs and expired clients lose unsent hints; revoked rights drop the hint instead of postponing it until permissions return.

The callback contains CB_SEQUENCE followed by CB_NOTIFY_LOCK and a referring-call entry identifying the denied LOCK's session/slot/sequence. Only one request occupies a session's callback slot, and the full body survives uncertain completion and transport replacement. Malformed results and missing replies require confirmed transport disconnection before retry. A valid optional-operation error, including NOTSUPP or RETRY_UNCACHED_REP, completes that hint and consumes its sequence without granting any lock. The client still has to issue LOCK and can lose a subsequent race with another client, as required by [RFC 8881 §20.11](https://www.rfc-editor.org/rfc/rfc8881.html#section-20.11).

Waiting hints are limited to 128 globally and 16 per client; maintenance performs at most eight fresh-authority attempts per pass. Operation count and complete RPC request/response size limits are respected. Clients with no usable backchannel, small buffers or one-operation backchannels continue using ordinary LOCK polling. These hints are optional and nonpersistent; this is not a promise of FIFO lock allocation.

[Local evidence](evidence/pre-m8/nfs-notify-lock-local.json) includes independent TCP fault injection, real 60-second lease expiry, existing slot/recovery regressions and a scenario using the pinned, unmodified pynfs RPC/NFS client stack. The pynfs scenario is new test code using the upstream client, not a claim that the complete upstream callback suite passes. Three-platform acceptance for this new operation is pending.
