# NFSv4.1 operation coverage

This is an implementation and test map for the regular-file/directory AUTH_SYS profile. It is not a declaration of complete RFC 8881 conformance. The [RFC operation table](https://www.rfc-editor.org/rfc/rfc8881.html#section-17) is the source of the required/optional distinction. Linux RPCSEC_GSS authentication/integrity/privacy is now implemented and independently tested (see [Kerberos](nfs-kerberos.md)); TCP backchannel binding, AUTH_NONE/AUTH_SYS CB_NULL and CB_COMPOUND/CB_SEQUENCE probes and CB_NOTIFY_LOCK hints with slot replay are implemented; Linux GSS protection of those callbacks is implemented with real-KDC local acceptance; remote acceptance is pending. SSV, other callback operations, Windows GSS, delegation and pNFS layouts remain unfinished.

Recommended SECINFO_NO_NAME is implemented and covered by SECNN cases. Optional GET_DIR_DELEGATION returns GDD4_UNAVAIL without promising a callback. LINK, READLINK, OPENATTR, DELEGPURGE, DELEGRETURN, GETDEVICEINFO, GETDEVICELIST, LAYOUTCOMMIT, LAYOUTGET, LAYOUTRETURN and WANT_DELEGATION are recognized and return NOTSUPP under this profile. `tests/nfs_discovery_integration.py` verifies their operation numbers and stops the compound at the unsupported operation. Optional special-file creation returns BADTYPE.

The obsolete v4.0 operations OPEN_CONFIRM, RENEW, SETCLIENTID, SETCLIENTID_CONFIRM and RELEASE_LOCKOWNER are decoded and return NOTSUPP. Unknown operation numbers return OP_ILLEGAL. No unsupported operation is reported as a successful implementation.

The upstream regular-file/directory invocation is `all nodeleg noblock nochar nofifo nosocket nosymlink noRNM20`: the recorded result is 145 passed, 121 not selected, zero failed. The omitted cases remain visible in the report. RNM20 requires hardlinks; RNM21 replacement and trunking cases are included. Native kernel close-to-open cache revalidation, native NLM reboot recovery and Windows Client for NFS results are separately required; operation coverage alone cannot establish those results.

Simple NFSv4 ACL attribute and mode synchronization are implemented in `src/file_nfs_security.inc` and `src/security.cpp`; independent coverage is in `tests/nfs_acl_integration.py`. The twelve mode bits, SETATTR-only mode_set_masked, group inheritance, sticky namespace protection and set-ID clearing are implemented with tests in `tests/nfs_mode_integration.py`. Audit/alarm, separate dacl/sacl attributes and complete ownership/domain semantics remain open; see [shared security](file-security.md).

Solo CB_SEQUENCE callback sequencing, exact retry, transport failover, session teardown and dynamic slot maxima are covered by `tests/nfs_backchannel_integration.py` ([local evidence](evidence/pre-m8/nfs-cb-sequence-local.json)); this does not yet exercise delegation/recall authority.

CB_NOTIFY_LOCK now follows denied READW_LT/WRITEW_LT requests, with fresh authority, explicit owner/file identification, referring calls, bounded single-slot dispatch and exact disconnect-gated retry. Independent tests include nonblocking cancellation, CLOSE/revocation/lease-expiry cleanup and advisory-only behavior; a separate test uses the unmodified pynfs client stack ([evidence](evidence/pre-m8/nfs-notify-lock-local.json)). Other callback operations and delegation authority remain unfinished.

## Upstream placeholder GSS handles

The earlier 145-case AUTH_SYS result predates GSS callback validation. Original `CSESS16` and `CSESS16a` offer the literal, unestablished `Handle from server` and expect successful CREATE_SESSION. RFC 8881 §18.36.3 requires NOENT when that handle does not exist. Both cases now fail with precisely NOENT; their [original failures](evidence/pre-m8/pynfs-gss-placeholder-handles.json) and [log](evidence/pre-m8/pynfs-gss-placeholder-handles.log) remain visible and are not counted as passes. The control/regular acceptance selection separates these two cases (`noCSESS16 noCSESS16a` in the regular selector); all other selection constraints remain unchanged. `pynfs_gss_handle_diagnostic.py` runs both originals and fails on any result other than those exact two conflicts. The remaining regular-profile remote run is pending.

Independent real-KDC tests supply valid handles in mixed AUTH_NONE/AUTH_SYS/GSS arrays and verify actual signed/encrypted callbacks for all three services. They separately assert NOENT for mixed arrays containing an unknown GSS handle, preserving the existing session/program. See [GSS callback evidence](evidence/pre-m8/nfs-gss-backchannel-local.json).
