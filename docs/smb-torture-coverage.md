# Samba torture applicability

The client is unmodified Samba 4.19.5 from Ubuntu 24.04. Its SMB2 inventory contains 576 cases. The executable regression selection lives in `tests/samba-profile.json`; `tests/samba_torture.py` runs it when no selectors are supplied. A client exit code of zero without a success record is not accepted. Skipped cases and mixed pass/skip groups are not passes.

The selected contract is the existing [ADR 0008](decisions/0008-smb-profile.md) with [M6 security extensions](m6.md): ordinary confined files/directories, 64 KiB operations, 1024-entry directory snapshots, no ADS/ACL/attribute persistence, caching, durable opens, multichannel or queued blocking locks. The selection does not establish general Windows-server or Samba equivalence.

| Area | Covered selection / reason for remaining exclusions |
| --- | --- |
| Read and file position | EOF, position, directory rejection and access rights pass. bug14607 requires Samba-specific injected I/O behavior and is skipped by the original client. |
| Locks | Valid/invalid requests, shared/exclusive I/O, automatic release, zero ranges/reads, stacked locks, multiple unlock, contention, context, overlap, upper ranges and truncate pass. Async/CANCEL cases need the explicitly excluded blocking queue; replay cases need durable/multichannel support; rw-none and CTDB cases target other server configurations. |
| CREATE | Concurrent file/directory creation, byte locks, leading slash, impersonation and directory allocation pass. Generic/blob/open/delete fixtures also request persistent DOS attributes, allocation contexts, EAs or ACLs. ACL variants, temporary directory attributes, NTFS quota pseudo-files and long-path cases exceed the declared profile. Benchmarks are separate load gates. |
| Rename / sharing / deny | Entire rename, sharemode and deny groups pass, including MS Word's sequence, parent-directory sharing and rename/close races. |
| Compound | Related 1/2/5/6/8/9, unrelated, invalid 1–4, create/write/close, find related/unrelated and flush/close/flush pass. Related 3/4/7 use object-ID IOCTL/security metadata; padding uses ADS; interim/break cases require oplocks. Async read/read and write/write require the second request to remain cancellable (injected slow I/O); a synchronous successful reply cannot meet that test fixture assumption. |
| Directories | find, fixed and file-index cases pass. file-index explicitly permits servers that do not resume by an index. one/modify use the complex persistent-attribute fixture. many/sorted/1kfiles_rename send a 1 MiB output limit despite 64 KiB negotiation; compound_find_close creates 5000 entries and requests 8 MiB. large-files uses components beyond the portable-name bound. |
| File IDs | unique and unique-dir pass. QFid/InternalInformation identity and repeated-open/volume consistency have independent smbprotocol coverage. The full fileid/fileid-dir cases then create ADS and remain excluded. |
| Session and connection | two_logoff, malformed NTLM reauthentication, signing-required, connect, tcon and all credit cases pass. Reconnect/reauth/binding fixtures require BATCH oplocks, multichannel or 2.0.2; expiry needs Kerberos. Algorithm-specific fixtures first require signing-negotiation contexts/algorithms outside the fixed CMAC profile; the independent M6 suite covers advertised CMAC/CCM/GCM and downgrade/tamper behavior. session-id truncates the 64-bit session ID into a uint32 before restoring it; the independent hostile-wire test preserves the full ID and checks continued valid-session operation. |
| Information / attributes | granted-access passes. Other broad getinfo/setinfo/maximum_allowed/mkdir fixtures request unsupported persistent attributes, security metadata, short names, ADS or additional filesystem information classes. Basic metadata, EOF, rename and disposition have independent wire/core tests. The scans are discovery tools, not success/failure conformance assertions. |
| Names and I/O bounds | Naked combining mark and wide-a pass; non-NFC names and lone surrogates are rejected by the portable naming contract. rw1/rw2 exceed negotiated MaxWriteSize. rw.invalid additionally assumes an NTFS-specific maximum file size; the server enforces its configured quota. The zero-byte WRITE-at-large-offset bug found there is fixed and covered by core checks. |
| Unsupported optional features | ACL/EA/DOS attributes and timestamp preservation, streams, name mangling, notifications, leases/oplocks, durable/replay/multichannel, timewarp, offloaded copy, sparse/compressed files, block cloning, trimming and network-interface discovery are not granted. Their respective groups do not become successful tests by being excluded. change_notify_disabled specifically requires Samba's NOT_IMPLEMENTED result; this server returns NOT_SUPPORTED. |
| Environment-specific tools | hold/check-sharemode and hold-oplock are interactive coordination tools; samba3misc requires a separate local server filesystem path; maxfid/bench/soak tests exceed the advertised bounded-resource contract and are separate load work. Security-descriptor/Windows-attribute helper tests target capabilities not exposed here. |

[Local reports](evidence/pre-m8/smb-nfs-contract-local.json) retain both diagnostic failures and subsequent corrections. The initial combined selection passes 56 selectors / 72 cases; file-index, directory allocation and the two flush compound cases add four cases. Fixed-commit remote evidence must accompany any client-matrix acceptance. Kernel CIFS lacking NTLM MIC remains explicitly incompatible; its rejection test is not a successful mount.
