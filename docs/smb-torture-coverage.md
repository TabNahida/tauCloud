# Samba torture applicability

The client is unmodified Samba 4.19.5 from Ubuntu 24.04. Its SMB2 inventory contains 576 cases. The executable regression selection lives in `tests/samba-profile.json`; `tests/samba_torture.py` runs it when no selectors are supplied. A client exit code of zero without a success record is not accepted. Skipped cases and mixed pass/skip groups are not passes.

The newer [complete oplock diagnostic](evidence/pre-m8/smb-batch-full-oplock.log)
passes 35 of 42 cases without skips. The seven remaining failures are retained:
exclusive6, batch19/20, batch22a/22b, batch26 and stream1. Exclusive6 and
batch19/20's parent-DELETE status
expectation matches older Windows behavior, whereas the current implementation
uses modern destination-directory sharing (product note 185 below). That
difference does not establish its later oplock assertions or close the overall
gate. BATCH grants/recall/cached closes now work, including attribute-only and
read-only opens. Same-transport BATCH timeout recovery, alternate streams,
SMB leases and NFS delegation integration remain unfinished.

The selected contract is the existing [ADR 0008](decisions/0008-smb-profile.md) with [M6 security extensions](m6.md): ordinary confined files/directories, 64 KiB operations, 1024-entry directory snapshots, persistent DOS attributes/EAs and queued blocking locks, persistent simple Windows DACLs, but no ADS, caching, durable opens or multichannel. The selection does not establish general Windows-server or Samba equivalence.

The modern rename rule opens only the destination directory with ADD_FILE/ADD_SUBDIRECTORY and READ|WRITE|DELETE sharing. An exclusive source-parent open does not itself prohibit moving a child out; a destination parent that denies write sharing still blocks the operation. Independent encrypted-client tests cover 32 parent-access/sharing/type combinations and cross-directory moves. See [MS-FSA rename](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/87f86c9b-6c2a-4803-84b7-131a74a434fa) and [product note 185](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/4e3695bd-7574-4f24-a223-b4679c065b63). The old full-group passing evidence reflects the previous implementation; it is not evidence of current modern conformance.

[Local reports](evidence/pre-m8/smb-nfs-contract-local.json) retain both diagnostic failures and subsequent corrections. The initial combined selection passes 56 selectors / 72 cases; file-index, directory allocation and the two flush compound cases add four cases. Fixed-commit remote evidence must accompany any client-matrix acceptance. Kernel CIFS lacking NTLM MIC remains explicitly incompatible; its rejection test is not a successful mount.

At `fc28c4c`, the expanded executable selection passes 62 selectors / 78 cases locally, including CREATE open and readonly-delete. [Evidence](evidence/pre-m8/create-final-fc28c4c-local.json) retains every selected result. The additional blob diagnostic is still a failure at timewarp and is excluded from that passing count.

The blocking-lock increment adds `smb2.lock.async`, `smb2.lock.cancel`, `smb2.lock.cancel-tdis` and `smb2.lock.cancel-logoff` to the 66-selector selection. An initial diagnostic exposed a missing final-response header length and the distinct close-versus-CANCEL status; both are corrected. The complete `smb2.lock` diagnostic still includes unsupported resiliency/durable replay and environment-specific skips, which remain recorded rather than counted as passes.

The Full SMB/NFS ACL expansion adds 13 unmodified ACL cases, including generic rights, inheritance, owner rights, access-based enumeration and maximal access. The complete 14-case `smb2.acls` diagnostic retains SDFLAGSVSCHOWN as a failure because privileged assignment to Everyone is not supported. See [shared security](file-security.md); no full-suite pass is claimed.

The notification increment adds native events, asynchronous cancellation, FIFO opens and metadata notifications. Independent clients cover all four dialects. Nine unmodified close, logoff, tdis1, file, handle-permissions and rmdir1–4 cases pass locally and join the executable selection; the original full suite and buffer-count failures remain recorded. See [notification evidence](evidence/pre-m8/smb-notify-local.json).

The ownership-restoration extension passes the full 14-case ACL suite locally and on remote GCC at `179e060`. Scoped authority tests pass GCC/Clang/MSVC. The Clang full-suite run disconnects during SDFLAGSVSCHOWN and remains failed; later cases fail to connect. [Remote evidence](evidence/pre-m8/smb-security-179e060-remote.json) preserves this distinction.

The recursive notification increment closes the premature delete-on-close rejection, installs service-created subtree watches between operations and corrects cross-parent move actions. The original `smb2.notify.rec` now passes locally and joins the regression manifest. `valid-req` and `mask` remain failed with their original logs retained; this is not a full notification suite pass ([evidence](evidence/pre-m8/smb-notify-recursive-local.json)).

Rename now sets ARCHIVE immediately for data files and defers unfrozen ChangeTime until the originating open closes. Any close of the file flushes its pending attribute notification; directories do not gain ARCHIVE. Persistent markers retain native incarnation and recover after SMB process loss or service restart; offline backup rejects unfinished markers. Seven independent client groups and unmodified Samba `notify.mask-change` / `notify.rec` pass locally, alongside existing attributes, notification and delete-on-close regressions ([evidence](evidence/pre-m8/smb-rename-metadata-local.json)). The new code still requires cross-platform acceptance. This closes the earlier `mask-change` timeout, not the full notification or Full SMB/NFS gate.

The internal-enumeration correction closes the original `notify.mask` failure, and that complete selector joins regression. `valid-req` retains its exact initial event-count failure; [evidence](evidence/pre-m8/smb-notify-access-local.json) preserves both results.

Completing ready notifications at SMB frame boundaries now passes the original `valid-req`, including initial-event batching, changing per-request output size and sticky first-open capacity. It joins the regression selection. The dedicated test preserves a later WRITE for the next buffered notification on all four dialects ([evidence](evidence/pre-m8/smb-notify-boundary-local.json)).

The complete unmodified notification diagnostic now finishes with 21 successes and two failures: `session-reconnect` and `tree`. Every original assertion remains in [evidence](evidence/pre-m8/smb-notify-boundary-local.json). The 21 successful selectors are included in regression; this is explicitly not a full-suite pass.

The session-table extension passes original `notify.session-reconnect` and preserves `session.two_logoff`. Earlier original `session.reconnect1/2` and `session.reauth1`–`reauth6` diagnostics failed at their initial BATCH-oplock assertion ([earlier evidence](evidence/pre-m8/smb-multisession-local.json)). BATCH and cached delete-on-close now let original reconnect1/2 and reauth1/6 pass; two_logoff still passes. Reauth4/5 and the rest of the full session suite remain open. Anonymous reauthentication subsequently lets reauth2/3 pass; reauth4 still fails at SET_INFO with INVALID_NETWORK_RESPONSE and reauth5 at unlink of a nonexistent target with OBJECT_NAME_NOT_FOUND ([renewal evidence](evidence/pre-m8/smb-anonymous-local.json)). The [BATCH evidence](evidence/pre-m8/smb-batch-local.json) retains both the early full 66-case diagnostic and isolated selector results, including later connection-reset failures in the full process; these are not substituted with the five passing selectors.

The dot-path and removed-subtree-watch increment passes the complete original `smb2.notify` suite locally: **23 successes, zero failures/errors/skips**. The independent path, 110-cycle/440-event watch-reuse and original notification regressions also pass under Clang ASan/UBSan. The targeted workflow now runs the entire original suite. This remains local increment evidence, not full SMB/NFS or stable cross-platform conformance: the earlier GCC backend `mask-change` failure (two events delivered to one pending request) remains under investigation. See [implementation](smb-paths.md), [local evidence](evidence/pre-m8/smb-paths-local.json) and [remote failure](evidence/pre-m8/smb-notify-a508-backend-failure.json).

It passes all 23 original notification cases and eight repeated `mask-change` invocations, each with its own log; earlier failures remain in evidence. Reciprocal writer and subscriber-loss checks also pass. [Final local evidence](evidence/pre-m8/smb-notify-peers-local.json) is separate from still-pending remote acceptance. Broader BATCH-oplock-dependent session tests remain failed and are not included in these successes.
