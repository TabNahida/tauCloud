# M1 后端基础

[English](m1.md) · [OpenAPI](openapi.json) · [配置 Schema](../packaging/config.schema.json)

M1 提供可运行的本地管理后端：监督者、HTTPS API、身份数据库和 CLI。文件、协议、监控、更新、存储管理及 helper 均有独立进程并参与监督；这些进程的后续业务能力明确报告不可用，不宣称已经支持文件共享协议。M0 已按功能证据验收，445 端口不是 M1 前置条件。

## 构建与运行

需要 Python 3、Git、xmake 3.1.1 和 C++20 编译器。`dependencies.lock.json` 固定依赖版本、配方提交及导出源码摘要。工程只使用已校验的本地配方，不自动更新其他项目的全局仓库。

```sh
python3 scripts/fetch_pace.py
python3 scripts/fetch_pace.py --dependency recipes
python3 scripts/run_m1.py --compiler gcc
# Linux Clang + ASan/UBSan：
python3 scripts/run_m1.py --compiler clang --sanitizers
```

Windows 使用 `python` 和 `--compiler msvc`。`scripts/windows_m1.ps1` 把源代码和依赖复制到临时 NTFS 目录，使用 M0 固定的 VS 2026 工具链。CI 另外使用 `windows-2025` 提供的 MSVC；并不声称该工具链与参考宿主完全相同。前台验收不需要 Node、前端构建、管理员权限或真实磁盘设备。

手动启动（Windows 可执行文件附加 `.exe`）：

```sh
BIN=build/linux/x86_64/debug
STATE=/tmp/taucloud-demo
"$BIN/taucloud_ctl" --state "$STATE" init --port 8443
"$BIN/taucloud_supervisor" --state "$STATE"
```

另一个终端使用标准输入传入密码，不把密码放到命令行参数：

```sh
read -rs -p 'Admin password: ' TAUCLOUD_PASSWORD
printf '%s\n' "$TAUCLOUD_PASSWORD" | "$BIN/taucloud_ctl" --state "$STATE" bootstrap --username admin --password-stdin
printf '%s\n' "$TAUCLOUD_PASSWORD" | "$BIN/taucloud_ctl" --state "$STATE" login --username admin --password-stdin --scope admin
unset TAUCLOUD_PASSWORD
"$BIN/taucloud_ctl" --state "$STATE" whoami
"$BIN/taucloud_ctl" --state "$STATE" capabilities
"$BIN/taucloud_ctl" --state "$STATE" services
"$BIN/taucloud_ctl" --state "$STATE" restart --role file --request-id manual-restart-0001
"$BIN/taucloud_ctl" --state "$STATE" logout
"$BIN/taucloud_ctl" --state "$STATE" stop
```

初始化创建私有状态目录、IPC 密钥、10 分钟有效的一次性引导令牌和 30 天有效的本地 TLS 证书。密码长度为 12–1024 字节。CLI 默认申请 `read` 权限，管理操作显式申请 `admin`。令牌保存在受保护的 `cli-session.json`，不会打印。`status`、`stop` 和首次管理员引导要求本地状态目录权限，走认证 IPC；其他命令走校验证书及主机名的 HTTPS。M1 没有跳过 TLS 验证的选项、远程监听、默认账户或密码恢复命令。证书到期前停机替换证书与私钥，并更新客户端信任；尚未使用的引导令牌过期时，应重新初始化新的状态目录。

## 已实现契约

| 方面 | M1 行为 |
| --- | --- |
| 进程所有权 | 每个角色一个原生排他锁。监督者退出不连带杀死子进程；接管验证可执行文件、PID、创建标识、认证端点及代际。Linux 通过 pidfd 发送终止信号，Windows 在进程句柄上核对创建时间。 |
| 恢复 | 独立重启、200 毫秒至 5 秒指数退避，默认 60 秒内最多 5 次异常退出。先持久化重启意图，再执行动作。相同幂等键对应相同目标代际；冲突角色被拒绝。异常死亡会更换代际。 |
| 数据所有权 | 身份服务独占 `identity.db`，监督者独占 `supervisor.json`，工作进程各自写实例描述。JSON 原子替换并刷盘；SQLite 使用 WAL、FULL 同步事务、启动完整性检查、版本拒绝、迁移前备份及事务迁移。 |
| IPC | Linux Unix 套接字校验同 UID；Windows 使用只允许本机、owner/SYSTEM DACL 的异步命名管道。v1 帧上限 64 KiB，随机挑战绑定双向 HMAC。调用者操作白名单、代际检查、客户端 4 秒/服务端 5 秒期限、2 个线程和默认 16 个排队连接。只能取消自己的活动请求，取消是协作式的。 |
| 资源边界 | 默认 32 个 HTTPS 连接、8 KiB 头/体、每连接一个请求、TLS/接收/写入各 3 秒。阻塞桥接上限 4 线程、32 任务、2 MiB 预留。默认单进程 RSS 512 MiB，监督者终止超限实例；Windows 另有 Job Object 内存限制，Linux 限制 256 个文件描述符。 |
| 凭据 | Argon2id v19、64 MiB、3 次迭代、1 lane、随机盐。随机会话令牌仅存 SHA-256 摘要；CLI 1 小时、浏览器 30 分钟。退出立即撤销，read 会话也可自行退出。失败登录预算持久化：每账户每分钟 5 次，全局 30 次；验证成功不消耗预算，也不清除已有失败记录。 |
| 浏览器 | `__Host-taucloud` Cookie 设置 Secure、HttpOnly、SameSite=Strict、Path=/。浏览器登录与写入检查精确 Origin，Cookie 写入额外检查 CSRF；拒绝跨域，不设置通配 CORS。浏览器令牌不能冒充 CLI Bearer，反之亦然。 |
| 停机 | 停止接收连接、有界等待活动连接、在 reactor 存活时取消并回收阻塞工作，最后停止 PACE。监督者先停 API，最后停身份服务。 |

M1 的信任边界是专用操作系统账户及私有状态目录。同账户代码可读 IPC 密钥，因此目前进程隔离提供故障隔离，不提供抵抗已被攻陷兄弟进程的沙箱。helper 没有特权操作；暴露不可信文件协议解析器或特权存储命令前，需要补齐更强的工作进程 OS 隔离。Linux RSS 限制是采样监督，不是 cgroup 硬限制；没有 CPU 配额。操作历史最多 4096 条，满后拒绝新操作。取消或超时不承诺撤销已经提交的修改。

应用错误使用 `{"error":{"code":"..."}}`；传输/解析错误可能直接断开或返回 PACE 的 HTTP 错误。结构化日志仅含时间、角色、事件及稳定错误码，不记录密码、令牌或原始请求体。各进程在 `logs/` 写 JSONL，每个角色按 1 MiB 轮转并保留一份旧日志，SCM 模式也可读取。TLS/IPC 密钥通过 OS 权限保护，并非加密保险库；测试不上传证书或本地密钥。

## 服务生命周期

Linux：调整 `packaging/taucloud.service`，创建专用 `taucloud` 账户，将可执行文件安装到 `/opt/taucloud`，以该账户初始化 `/var/lib/taucloud` 后再启用服务。`KillMode=process` 允许监督者崩溃后接管存活子进程；正常 SIGTERM 和 CLI 使用相同的优雅停止路径。提供了 unit，测试不会给用户宿主安装常驻服务。

Windows：`taucloud_supervisor.exe --state C:\taucloud-state --service` 实现服务名为 `tauCloud` 的 SCM 分发及 STOP/SHUTDOWN。部署时由管理员为服务配置专用账户和目录权限，正确引用可执行文件与状态路径。原生前台测试运行相同的监督者及清理逻辑；机器服务注册与账户配置属于部署步骤，自动测试不改动宿主 SCM。

确切源码摘要、命令与结果见 [M1 证据](evidence/m1/README.zh-CN.md)。已提供 GitHub CI；本地通过不等于已经运行托管 CI 或完成常驻 SCM/systemd 安装。
