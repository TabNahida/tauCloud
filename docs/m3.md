# M3 — WebDAV backend preview

[简体中文](m3.zh-CN.md) · [M2 setup and file API](m2.md) · [Evidence](evidence/m3/README.md)

M3 adds an independently supervised HTTPS WebDAV worker, persistent DAV properties and locks in each storage domain, protocol inventory, and offline metadata recovery. This is a local backend preview for the tested Linux/ext4 and Windows/NTFS hosts. It does not implement FTP/FTPS, SMB, NFS, Docker, disk administration, automatic updates or WebPanel.

## Start and use

Build with the pinned dependencies and M1 setup instructions, then run `python3 scripts/run_m3.py --compiler gcc` (Windows: `python scripts/run_m3.py --compiler msvc`; Clang: `--compiler clang --mode debug --sanitizers`). For independent conformance on Linux, install the OpenSSL/Expat development packages, run `python3 scripts/fetch_litmus.py`, then pass `--litmus build/litmus/installed/bin/litmus`. The archive SHA-256 is pinned in that script.

The runner creates disposable storage and never installs a service or touches real disks. `--large-mib 257` verifies a transfer larger than the 256 MiB hard worker allocation ceiling on release builds. This is not a claim of a transfer larger than host physical RAM.

After `taucloud_ctl --state <state> init`, stop the supervisor and add `"dav_port": 8444` to `config.json`. It must be distinct from the management port and at least 1024. Omitted/zero disables the listener. Start the supervisor normally; check `/api/v1/protocols` and `/api/v1/services`. Existing M2 state migrates file databases from schema 1 to 2, with `<worker>.pre-v2.db` backups. Do not downgrade these databases to M2.

Create users, storage roots and spaces through the [M2 API](m2.md). Create a DAV exposure with authenticated `POST /api/v1/shares`:

```json
{"id":"documents","space":"alice","exposures":{"webdav":"rw"}}
```

An administrator can change a share by sending the complete definition with `"update":true`; policy revocation reaches file workers before the response. `"r"` is read-only; an empty exposures object disables access through that share. Core API and WebDAV may share a writable space because both enforce the same DAV locks in its file worker. Other mixed writable protocols remain blocked. Configuring an exposure never implements or starts an unsupported protocol.

The DAV URL is `https://127.0.0.1:8444/dav/documents/`. Use an enrolled username/password over TLS or a scoped CLI Bearer token. Cookies and browser Origin requests are rejected. Trust the generated `tls-cert.pem` explicitly in the test/client; do not disable certificate checks for real data. The generated local certificate expires after 30 days. The listener is loopback-only; remote deployment, public PKI, reverse proxies and desktop auto-discovery are outside this preview.

```sh
curl --cacert <state>/tls-cert.pem --user alice --upload-file local.txt \
  https://127.0.0.1:8444/dav/documents/local.txt
curl --cacert <state>/tls-cert.pem --user alice -X PROPFIND -H 'Depth: 1' \
  https://127.0.0.1:8444/dav/documents/
```

## Protocol behavior and limits

The listener advertises DAV classes 1 and 2 after the recorded litmus 0.18 basic/copymove/props/locks/http run. The 105 executed cases pass; litmus skips its HTTP `Expect` case for HTTPS, so the Python acceptance suite tests authenticated and rejected `100-continue` separately. Passing this suite does not imply compatibility with every desktop client. See [client results](evidence/m3/README.md).

Supported methods: OPTIONS, GET, HEAD, PUT, MKCOL, DELETE, COPY, MOVE, PROPFIND, PROPPATCH, LOCK, UNLOCK. Persistent dead properties preserve namespaces, XML content and attributes. Property changes are atomic; protected-property failures return 403/424 multistatus. COPY copies properties; MOVE preserves them. DELETE handles bounded collection trees. Recursive copy/move/delete operations are journalled; publication reconciles after a worker restart. COPY is confined to one share/space and is limited to 16 MiB of file contents per request; cross-share/volume moves are rejected.

PUT stages data, reserves quota before body admission, and publishes on completion. Known-length and chunked uploads use bounded buffers; authentication, path checks, quota and lock preconditions precede `100 Continue`. Disconnects cancel DAV uploads. Cleanup can use an expired signed grant only to close that actor's handle or cancel its own unpublished DAV job; it cannot read or publish. Abandoned DAV stages expire after 15 seconds without stored progress, reclaimed on the next domain request, and are cancelled when the domain reattaches after restart. Core API resumable uploads retain their M2 behavior. Downloads stream and release handles on cancellation.

GET/HEAD expose ETag and Last-Modified; GET supports one byte/suffix range, 206/416 and If-Range. Multiple ranges are ignored and return the full representation. Conditional ETags use strong If-Match and weak If-None-Match comparison; date validators support IMF-fixdate. HTTP/1.1 only, one request per connection, `Connection: close`; no compression or HTTP/2. Duplicate headers, conflicting framing, unsupported transfer codings, malformed paths, DTDs/entities, invalid namespaces and excessive XML nesting fail closed.

| Budget | Limit |
| --- | --- |
| Connections / blocking work | 32 or lower configured connection limit; 4 executor threads, queue 32 |
| Headers / streaming chunk | 16 KiB, 64 fields / 64 KiB |
| PUT / XML body | 1 GiB (also quota-limited) / 64 KiB |
| TLS handshake / headers / I/O idle | 5 s each |
| XML / property edit | depth 32, 4096 nodes / 128 edits, 64 KiB stored properties per object |
| PROPFIND | Depth 0 or 1; omitted/infinity returns `propfind-finite-depth` 403 |
| Recursive mutation / directory listing | 256 objects; underlying native directory scan at most 4096 entries |
| Locks / duration | 256 per space; 1–3600 seconds |
| Retained jobs | 4096 per space; manual retention/recovery required at limit |

Exclusive/shared write locks support Depth 0/infinity, refresh, discovery, timeout and token/owner checks. Locks persist across process restarts until their absolute expiry; restore intentionally clears them. They protect both DAV and core API writers, including parent collection membership and destination replacement. An operating-system administrator/external process can bypass service locks and quota. Keep the M2 trusted-host and single-volume-root restrictions.

Paths are UTF-8 NFC, with Unicode case-fold collision rejection. Non-NFC spellings are rejected rather than silently renamed. Encoded separators, traversal, NUL/control bytes, Windows device names, trailing dots/spaces, alternate streams and `.tc-` names remain rejected. Components are at most 120 UTF-8 bytes and paths 1024 bytes. This is a portable subset, not every ext4/NTFS name. Filesystem objects are opened relative to pinned roots without following links/reparse points; stable IDs fence replacement.

## API and CLI coverage

`GET /api/v1/protocols` returns implementation/enablement, local binding, TLS and DAV classes. `/capabilities` reports M3 and `portable-utf8-nfc-v1`. Users, groups, memberships, roots, spaces, shares and grants use their existing GET/POST resource routes. Monitoring uses `GET /api/v1/monitoring`; services use GET `/services` and POST `/services/restart`. File jobs and cancellation use POST `/files/jobs` and `/files/cancel_job` with space/path. All are callable with `taucloud_ctl --state <state> call --path /api/v1/...`; POST JSON is read from stdin with `--method POST`. See [OpenAPI](openapi.json). Protocol listener port changes require a stopped config edit and restart, not an API runtime toggle.

## Metadata backup and restore

These are offline, local-owner CLI operations. Stop the entire supervisor first. Backup holds the supervisor and every worker ownership lock and refuses running services or unfinished file jobs. Cancel/complete uploads and resolve uncertain jobs before retrying.

```sh
taucloud_ctl --state <state> stop
taucloud_ctl --state <state> backup --output <new-backup-directory>
taucloud_ctl --state <new-state-directory> restore --input <backup-directory>
```

Backup uses SQLite snapshots, a versioned manifest and SHA-256 file checksums. It includes users/password verifiers, grants, spaces/shares, file object IDs, completed jobs, audit and DAV properties. Treat it as confidential: the directory is owner-only but is not encrypted. Copy it to separately encrypted, access-controlled backup storage. Checksums detect corruption, not malicious replacement; restore only trusted backups.

File contents, staging files, TLS private keys, IPC keys, CLI tokens and active sessions are not a file-data backup. Restore validates the package into a fresh private sibling directory and publishes it as a **new, absent** state path; it never overwrites an existing state. It generates new TLS/IPC identities, revokes sessions and clears DAV locks. Clients must re-login and re-trust the new certificate (or provision a separately managed TLS identity while stopped).

This preview restores metadata against the **same original native volumes, roots and object identities**. File data must remain consistent with the offline snapshot. Preserve original disks or a native filesystem snapshot separately. Copying files onto a replacement disk changes native IDs and is deliberately rejected; cross-host/object-ID remapping and a file-data restore importer are not implemented. Do not run old and restored state against the same roots simultaneously. Keep original state and a coordinated file-data backup until the restore drill has passed.

## Implementation decisions

See [ADR 0006](decisions/0006-webdav.md). The local HTTP adapter uses pinned PACE TLS streaming primitives directly; no unreviewed edits to the vendored PACE checkout or its buffered HTTP server were made. Runtime additions are pugixml 1.15 and utf8proc 2.11.3 (MIT), pinned with source hashes in `dependencies.lock.json`. Protocol references: [RFC 4918](https://www.rfc-editor.org/rfc/rfc4918.html), [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html); independent test tool: [litmus](https://notroj.github.io/litmus/).
