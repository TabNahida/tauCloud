# 文件域冷初始化后的重新授权

[English](file-authorization.md)

身份域签发的授权仍只有两秒有效期。文件域先验证签名和授权，再挂接空间；首次挂接可能执行内部日志恢复和目录扫描，因此请求的文件操作开始前，授权就可能过期。

API 核心文件操作、SMB 和 NFS 文件操作现在会在挂接完成后再次检查授权；NFS 同时完成内部初始化。只有这个边界的过期会返回 `grant_refresh_required`。取消和撤权仍直接失败。此时请求的数据操作尚未执行，但内部恢复或索引维护可能已经发生。后续检查仍返回普通 `lease_expired`，不能触发自动重试。

API、SMB、NFS 适配层收到此专用结果后，会向身份域重新授权，并最多重试一次。操作参数和变更请求 ID 保持一致；API 重命名重新验证源和目标授权。第二次授权被拒绝就停止执行。已经过期的入站授权、普通租约过期、写入结果不确定、传输错误及取消均不通过此机制重试。耗尽重试后，NFS 返回 DELAY/JUKEBOX，SMB 返回资源不足，API 使用现有服务错误响应。NFS 删除、重命名内的嵌套查询不会放大重试次数。SMB 清理操作保持原有规则，FTP/WebDAV 的初始化行为不变。

M2/M5/M7 核心测试在原生根目录打开处注入单次延时，确保初始验证通过后才跨越有效期，并验证重新授权前不会返回句柄或创建请求的对象。NFS 协议测试另外验证重新授权、稳定请求 ID、只执行一次、有界及嵌套重试、撤权、普通过期拒绝。延时钩子仅编译进测试程序。

此前 Windows M2 的一次 mkdir 耗时 4,575 毫秒，超过两秒授权期限（[失败证据](evidence/pre-m8/windows-m2-4a-failure.json)），但具体延迟阶段尚未确定。本次修复覆盖已复现的冷初始化边界，不能据此认定所有 Windows 超时都具有相同原因。

[本地 Clang ASan/UBSan 证据](evidence/pre-m8/grant-preparation-local.json)记录了 M2 87 项、M5 12,599 项、M7 1,550 项及 NFS 协议 1,146 项检查，以及 SMB 租约 42 组、NFS 15 组、API 10 组和 NFS 排队 2 组真实集成测试。本次改动的远程验收仍待完成。
