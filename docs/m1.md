# M1 backend foundation

[简体中文](m1.zh-CN.md) · [OpenAPI](openapi.json) · [Configuration schema](../packaging/config.schema.json)

M1 supplies a runnable local management backend: supervisor, HTTPS API, identity database and CLI. File, protocol, monitoring, updater, storage-admin and helper executables participate in supervision, but their later-milestone business operations return unavailable. No file-sharing protocol is advertised. M0 is accepted on functional evidence; TCP 445 is not an M1 prerequisite.

## Build and exercise

Requires Python 3, Git, xmake 3.1.1, and a C++20 compiler. Dependency versions, recipe commit and exported-source digests are in `dependencies.lock.json`. The project uses the verified local recipe export and does not update unrelated globally registered repositories.

```sh
python3 scripts/fetch_pace.py
python3 scripts/fetch_pace.py --dependency recipes
python3 scripts/run_m1.py --compiler gcc
# Alternative Linux compiler, with ASan/UBSan:
python3 scripts/run_m1.py --compiler clang --sanitizers
```

On Windows use `python` and `--compiler msvc`. `scripts/windows_m1.ps1` copies sources and verified dependencies into a disposable native NTFS checkout and selects the M0 reference VS 2026 toolset. CI also builds against the MSVC available on `windows-2025`; that runner is not a claim of an identical reference toolchain. No Node, frontend build, administrator privileges or real storage devices are needed for foreground acceptance.

Manual local use (Windows binaries have `.exe`):

```sh
BIN=build/linux/x86_64/debug
STATE=/tmp/taucloud-demo
"$BIN/taucloud_ctl" --state "$STATE" init --port 8443
"$BIN/taucloud_supervisor" --state "$STATE"
```

In another terminal, pass the password through standard input, never an argument. For example, pipe from a secret manager, or use a hidden shell prompt:

```sh
read -rs -p 'Admin password: ' TAUCLOUD_PASSWORD
printf '%s\n' "$TAUCLOUD_PASSWORD" | "$BIN/taucloud_ctl" --state "$STATE" bootstrap --username admin --password-stdin
printf '%s\n' "$TAUCLOUD_PASSWORD" | "$BIN/taucloud_ctl" --state "$STATE" login --username admin --password-stdin --scope admin
unset TAUCLOUD_PASSWORD
"$BIN/taucloud_ctl" --state "$STATE" whoami
"$BIN/taucloud_ctl" --state "$STATE" capabilities
"$BIN/taucloud_ctl" --state "$STATE" services
"$BIN/taucloud_ctl" --state "$STATE" restart --role file --request-id manual-restart-0001
"$BIN/taucloud_ctl" --state "$STATE" logout
"$BIN/taucloud_ctl" --state "$STATE" stop
```

Initialization creates a private directory, IPC secrets, a 10-minute one-use bootstrap token and a 30-day local TLS certificate. The password must be 12–1024 bytes. CLI login defaults to `read`; `admin` is explicit. A CLI token is saved privately in `cli-session.json`, never printed. `status`, `stop` and first-admin bootstrap require local state-directory access and use authenticated IPC. Other commands use HTTPS with certificate and hostname verification. There is no insecure TLS switch, remote listener, default account or password recovery command in M1. Replace the certificate/key while stopped before expiry; distribute the corresponding trust certificate to clients. Reinitialize a fresh state directory if its unused bootstrap token expires.

## Implemented contracts

| Area | M1 behavior |
| --- | --- |
| Process ownership | One OS lock per role. Children survive supervisor failure. Adoption checks executable, PID, birth identity, authenticated endpoint and generation. Linux termination uses pidfd; Windows verifies creation time on the process handle. |
| Recovery | Independent child restart with exponential 200 ms–5 s backoff; default maximum 5 deaths in 60 s. Restart intents are durably persisted before action. Repeated idempotency keys return the same target generation; conflicting roles are rejected. An unexpected death changes generation. |
| Storage ownership | Identity alone opens `identity.db`; supervisor alone writes `supervisor.json`. Each worker writes only its own instance descriptor. Atomic JSON replacement is flushed. SQLite uses WAL, FULL synchronous transactions, startup integrity checks, schema version rejection, backup before migration and transactional migrations. |
| IPC | Unix-domain sockets with same-UID check; Windows local-only overlapped named pipes with owner/SYSTEM DACL. Version 1 frames max 64 KiB; nonce-bound HMAC authenticates both directions. Caller/operation allowlist, generation checks, 4 s client/5 s server deadline, two workers and default 16 queued channels. Cancellation only affects the caller's own active request and is cooperative. |
| Resource limits | Default 32 HTTPS connections, 8 KiB headers/body, one request per connection, 3 s TLS/receive/write deadlines. Blocking bridge: 4 threads, 32 jobs, 2 MiB reservations. Default process RSS budget 512 MiB; supervisor fences an excess. Windows also uses a Job Object memory ceiling; Linux limits descriptors to 256. |
| Credentials | Argon2id v19, 64 MiB, 3 iterations, 1 lane; random salt. Random session tokens are stored as SHA-256 hashes. CLI lifetime 1 h; browser 30 min. Logout revokes immediately, including read-only sessions. Failed-login budgets persist: 5/account/minute and 30 globally/minute. Verified logins do not consume or reset prior failures. |
| Browser | `__Host-taucloud` cookie with Secure, HttpOnly, SameSite=Strict, Path=/; exact configured Origin for login/writes and CSRF token for cookie-authenticated writes. Cross-origin requests rejected; no wildcard CORS. Browser and CLI session kinds cannot be substituted. |
| Shutdown | Stop admission, let connections finish within a bound, cancel/join blocking work while the reactor is alive, then stop PACE. Supervisor stops API first and identity last. |

The M1 trust boundary is the dedicated OS account and private state directory. Same-account code can read the IPC key store and is therefore trusted; process separation currently provides failure isolation, not a sandbox against a compromised sibling. The helper has no privileged operations. Stronger per-worker OS isolation must precede exposing untrusted file protocol parsers or privileged storage commands. Linux RSS enforcement is sampled, not a cgroup hard limit; CPU quotas are not implemented. Operation history is bounded at 4096 entries and fails closed when full. Cancellation/deadlines do not promise rollback of a committed mutation.

Application failures use `{"error":{"code":"..."}}`; transport/parser failures can close the connection or return a PACE HTTP error. Structured logs contain time, role, event and stable code, with no raw credentials, tokens or request bodies. Each role writes JSONL under `logs/`, rotates at 1 MiB and retains one prior file, including when launched through SCM. TLS keys and IPC keys are protected by the OS account, not an encrypted vault. Certificates and local secrets are never uploaded by the tests.

## Service lifecycle

Linux: adapt `packaging/taucloud.service`, create the dedicated `taucloud` account, install all binaries under `/opt/taucloud`, and initialize `/var/lib/taucloud` as that account before enabling the unit. `KillMode=process` preserves workers for verified adoption when the supervisor crashes. Normal SIGTERM follows the same graceful-stop path as the CLI. The unit is supplied; tests do not install a persistent service on the user's host.

Windows: `taucloud_supervisor.exe --state C:\taucloud-state --service` implements SCM dispatch and STOP/SHUTDOWN handling for service name `tauCloud`. Register the service with a dedicated account that owns the initialized state directory and all binaries accessible. The binary path must quote executable/state paths. Foreground native tests exercise the same supervisor and teardown. Machine service registration and account provisioning are deployment steps; automated tests do not alter the host SCM.

Inspect [M1 evidence](evidence/m1/README.md) for exact tested source digests and commands. GitHub workflows are included; local passing results do not assert that hosted CI or persistent SCM/systemd installation has run.
