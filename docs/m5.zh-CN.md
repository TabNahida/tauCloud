# M5 — 强制签名的 SMB 2.1 后端预览

本页记录 M5 基线；当前方言及安全扩展见 [M6 指南](m6.zh-CN.md)。

[English](m5.md) · [基础部署](m1.zh-CN.md) · [文件服务](m2.zh-CN.md) · [验证记录](evidence/m5/README.md)

M5 新增独立受监督进程 `taucloud_smb`，以 C++20、PACE TCP/协程实现协议，继续复用身份服务和文件服务。Python、Samba、操作系统 SMB 服务都不是运行依赖。当前是有界回环预览；完整 Windows/Linux/macOS 客户端与 Samba torture 矩阵仍待完成，不能视为完整 SMB 合规认证。

## 配置与凭据

停止 supervisor，在已有 `config.json` 中合并 `"smb_port":4445`，然后重启。省略或设为 0 禁用监听。端口必须为 1024–65535，与管理、DAV、FTP 控制端口及已启用的 FTP 被动范围错开。仅监听 `127.0.0.1`。升级自动增加 SMB IPC 密钥；身份库从 3 迁移至 4，文件库从 2 迁移至 3，分别保留 `identity.pre-v4.db`、`file*.pre-v3.db`。

通过 M2 管理 API 创建独立可写空间及共享，例如：

```json
{"id":"documents","space":"alice-smb","exposures":{"smb":"rw"}}
```

`r` 表示只读。本地账户名须能忽略 ASCII 大小写后唯一识别。私人空间归属、团队授权仍然生效，管理员身份不自动获得文件访问权。SMB 不允许与其他协议混合写入同一空间。更新共享需提交完整定义及 `update:true`。

管理员用 admin 范围会话向 `POST /api/v1/smb/credentials` 单独登记已有且启用的本地账户：

```json
{"username":"alice","password":"a separate long SMB password"}
```

可通过 `taucloud_ctl --state <state> call --method POST --path /api/v1/smb/credentials` 从标准输入提交 JSON。真实密码不要放入命令参数。此操作不改变管理、FTP、DAV 密码。重新登记替换 SMB 凭据并撤销已有 SMB 会话；`{"username":"alice","enabled":false}` 删除凭据。浏览器写入仍校验 Origin/CSRF。响应不会返回 NT hash 或保险库密钥。

客户端必须支持显式指定端口、SMB 2.1 和签名，用户名可用 `TAUCLOUD\alice`，共享为 `\\127.0.0.1\documents`。Windows Explorer 常规 UNC 路径无法指定本预览的替代端口。标准 445 端口部署、远程监听、与系统 SMB 服务共存是独立工作；验收不会停止系统服务或修改防火墙。

## 认证与凭据保护

仅接受 NTLMv2：新鲜的 8 字节挑战、身份服务内 10 秒有效且单次使用的交换、时间戳及目标信息验证、强制 MIC，以及协商后的 NTLM 会话密钥交换。支持有界原始 NTLM/SPNEGO 封装。认证后的 SMB 报文必须使用 HMAC-SHA256 签名；复合请求全部分段先验签，再执行。重放及信用窗口违规会关闭连接。SMB1、guest/匿名、NTLMv1、Kerberos、SMB 2.0.2 和 SMB3 均未启用。SMB 2.1 签名提供完整性，**不提供内容加密**。

管理密码继续使用 Argon2id；SMB 单独需要等同密码能力的 NT hash。只有身份服务解密该值；SQLite 保存以账户名绑定的 AES-256-GCM 密文。独立 `smb-vault.json` 保存随机密钥：Linux 依赖私人服务目录及 0600 文件权限，Windows 额外使用当前用户 DPAPI 包装。Windows 服务必须保留原账户及配置文件。丢失密钥需重新登记；该保护不抵御本机管理员或服务账户被攻陷。MD4、HMAC、RC4 密钥交换与 AES-GCM 都由 OpenSSL 实现，不改变 TLS 的算法策略。

元数据备份不包含保险库密钥，并清除 SMB 凭据与会话；恢复后必须重新登记。有未完成删除意图时拒绝备份。备份仍按原契约包含管理密码校验值。身份限流保持每账户每分钟 5 次、全局每分钟 30 次尝试，包括成功认证；SMB 不使用密码会话缓存。

## 文件与 RPC 范围

实现协商、会话、树连接、CREATE/CLOSE、FLUSH、READ/WRITE、LOCK、目录查询、信息查询、SET_INFO 和 ECHO。事务/读/写载荷协商为最多 64 KiB。支持普通文件及目录的创建方式；不授予 oplock、lease 或 durable handle。FLUSH 和 write-through 刷新本地数据。普通写入直接可见，断开或失败可能留下部分文件；整文件原子发布仍使用 core/DAV/FTP 暂存上传接口。

文件服务统一检查双向读/写/删除共享模式、强制共享/独占字节锁、配额、访问掩码、对象身份和路径边界。锁向量整体成功或失败，解锁要求精确区间；仅支持 FAIL_IMMEDIATELY，不支持排队等待。每个目录句柄保留有界快照，支持重新开始、单项返回及 `*`、`?`、`*.*` 通配。线上的 UTF-16 名称转换为既有 UTF-8 NFC 可移植路径，不允许 ADS、链接、reparse 穿越及仅大小写不同的别名。

SET_INFO 支持 EOF/截断、重命名和删除状态。重命名限同一共享，更新打开句柄路径，可覆盖已关闭的普通文件。由于 Windows 固定父目录句柄的限制，两种宿主都明确拒绝移动含打开后代的目录。删除非递归，目录必须为空；待删除对象拒绝新打开，最后一个句柄关闭后删除。持久化意图与本地对象身份保证重启后不会误删替换对象。待删除子树禁止重命名，共享根禁止删除或移动。

信息查询支持 basic/standard/internal/EA/access/name/position/mode/alignment/all/network-open/attribute-tag 和默认无名数据流信息；目录类 1、2、3、12、37、38；文件系统卷、空间、设备、属性信息。属性采用保守的 directory/archive 投影。创建、访问和变更时间目前使用观测到的修改时间，不承诺独立的原生时间语义。基本属性/时间写入、扩展属性、安全描述符读写、持久 Windows ACL、POSIX ACL 透传、变更通知、硬链接和备用流不支持；不宣告持久 ACL 能力，不会对未实施的修改返回成功。

`IPC$` 仅暴露认证后的 `srvsvc`：MS-SRVS v3 的 NDR32 bind、NetrShareEnum level 1 及有界分页。每个返回共享均再次检查当前 SMB 授权；管理员列表也不会泄漏不可访问的私人共享。支持命名管道 READ/WRITE 和 FSCTL_PIPE_TRANSCEIVE。不提供匿名 IPC、NDR64、分片/额外认证的 DCE PDU、通用 RPC endpoint mapper、SAMR 或 LSARPC。其他 IOCTL 明确拒绝。

## 撤销、恢复及上限

每次文件操作重新取得短期身份授权；禁用用户、删除凭据、改变共享或策略会撤销访问。过期或被撤销的签名授权仅可清理原有句柄，重命名后也适用，不能读取或写入。策略推送关闭文件服务句柄；已接受的删除意图作为已提交操作继续完成。

SMB 进程持有独占进程锁后，才在各文件工作进程中回收旧 SMB 句柄及待删除记录。协议重启不重启其他服务；文件进程重启使旧句柄失效，客户端需重连。不承诺 durable reconnect 或透明故障切换。原生重命名是原子的，随后索引更新前崩溃由扫描协调；部分写入沿用核心不确定操作处理。

| 资源 | 上限 |
| --- | --- |
| 连接 / 阻塞执行器 | min(配置值,32) / 4 线程、队列 32 |
| TCP 帧 / 复合请求 | 1 MiB / 16 段 |
| 信用 / 执行顺序 | 最多 64 的有界窗口；单连接顺序执行 |
| 会话 / 树 / 打开对象 | 每连接 1 个认证会话、16 棵树、64 个对象 |
| 文件服务 | 每工作进程 128 个句柄、256 把锁 |
| 目录快照 | 1024 项、256 KiB 序列化元数据 |
| 认证 / 帧体 / 响应写入 | 10 秒 / 5 秒 / 5 秒 |
| 认证后空闲 / 内部会话 | 60 秒 / 1 小时 |
| NTLM 待处理交换 / 令牌 | 64 / 16 KiB |
| RPC 共享 / presentation context | 64 / 4 |

不宣告 multi-channel、SMB 加密、DFS、压缩、POSIX 扩展、异步通知或 durable handle。超出范围明确失败。宿主外部写入仍可能绕过服务配额/锁，见 M2。

## 复现

```sh
python3 -m venv .deps/smbprotocol-venv
.deps/smbprotocol-venv/bin/python -m pip install -r tests/smb-requirements.txt
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler gcc --large-mib 17
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler clang --mode debug --sanitizers
```

Windows 在虚拟环境安装相同依赖后运行 `scripts/run_m5.py --compiler msvc`，或用 `scripts/windows_m5.ps1` 从 WSL 创建临时 NTFS 副本。包含 M1–M5 回归，可通过 `--litmus` 增加 M3 验证。数据、监听及进程均为一次性。具体客户端、宿主及未验收项见[验证记录](evidence/m5/README.md)。协议参考与实现取舍见[英文版](m5.md)和 [ADR 0008](decisions/0008-smb-profile.zh-CN.md)。
