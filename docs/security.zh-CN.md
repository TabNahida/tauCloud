# 安全、平台与集成

[English](security.md) · [文档](README.zh-CN.md)

状态：建议要求。以下是实施与发布门槛，不代表已经具备的保护。

## 1. 信任边界与默认行为

防护对象包括未认证网络对端、试图访问其他空间的已认证用户、畸形协议输入、被攻陷的插件和意外宿主配置变更。宿主管理员和内核属于可信边界：tauCloud 无法对抗掌控机器或磁盘的管理员。

初始仅在回环地址提供管理服务，全部文件协议关闭。本地初始化命令通过一次性、有有效期的机制建立首个管理员，不提供默认凭据。启用网络监听器必须显式指定绑定地址与访问策略。远程管理、WebDAV 和正常 FTP 配置使用 TLS。SMB 使用自身协议安全机制，不人为包一层自定义 TLS 协议。

管理会话应短期有效且可撤销；浏览器 cookie 使用 secure/HttpOnly/SameSite，配合 CSRF 防护、受限 CORS 和显式可信代理配置。CLI/API token 具有作用域并可撤销。加入登录限速、请求限制和审计。外网访问、MFA、OIDC 与账户恢复需要独立设计；初期不自动打开路由端口或建立公共中继。

更改授权或禁用用户必须使授权缓存失效，并跨进程触发已定义的会话与句柄撤销。推送撤销并收集确认；工作进程不可达时以有界租约到期兜底，具体规则见架构。测试已打开句柄和在途写入，不能只测试新登录。在协议允许的边界尽快终止后续访问，说明撤销生效范围，不承诺撤回已经发送或写入的字节。

## 2. 跨协议凭据

| 用途 | 建议保存或验证方式 |
| --- | --- |
| Web/API、WebDAV、FTP/FTPS 密码 | 由维护中的库提供带盐 Argon2id，校准参数并支持重新哈希 |
| SMB 本地账户 | 独立的协议凭据注册或提供者；NTLMv2 所需的密码等价材料单独保护 |
| NFS AUTH_SYS | 显式导出级 UID/GID 映射、root squash 和可信客户端策略 |
| 后续 Kerberos | GSSAPI/SSPI 提供者集成与受保护的服务凭据 |

应用密码验证值无法转换为所有协议要求的凭据。SMB 注册可瞬时使用密码派生必要材料，但不能为便利保留明文。SMB 秘密单独保存，加密密钥位于元数据数据库之外，平台支持时使用宿主保护。文档说明密码等价材料泄露可能在没有明文密码时仍允许认证。

协议凭据撤销、密码轮换和用户禁用必须一致。不能静默将管理 bearer token 当作文件协议密码。NFS AUTH_SYS 的信任模型不同，不能包装成密码认证的用户隔离。

备份需区分公开配置、密码验证值和可解密秘密。宣称可移植恢复前，先定义密钥备份恢复或重新注册流程。日志和错误响应中隐藏密码、token、密钥及敏感路径。

## 3. 文件系统安全与一致性

使用句柄相对遍历，并按平台检查符号链接、junction、reparse point 与挂载变化。初期拒绝托管命名空间中用户创建的链接与特殊文件，除非显式实现了安全功能。导入已有根目录时扫描并报告不支持的对象，不能悄悄跟随。

规范化路径本身不能避免检查与使用之间的竞态。测试并发重命名、链接替换和根目录替换。验证 Unicode 解码、大小写碰撞、Windows 保留名与备用数据流语法。不能静默修改用户文件名来适应另一平台，应返回明确兼容错误。

原生文件操作使用经过设计的权限。受限服务账户访问已注册根目录，狭窄的辅助服务执行已批准的提权操作。认证、应用授权与操作系统执行权限分开。完整的逐用户 impersonation 是后续能力，必须分别进行平台验证。

宿主程序直接写入托管根目录时会绕过 tauCloud 权限、配额和锁。尽可能检测变化并核对索引与记账，但不承诺通用跨进程锁或备份一致性。基于快照的一致性需要已支持的原生快照适配器，否则备份必须明确其一致性等级。

## 4. Windows 与 Linux 能力矩阵

两种系统都是后端的一等目标。初始测试候选是 Ubuntu 24.04 LTS x86-64/ext4 与 Windows 11 x86-64/NTFS；M0 固定仍在支持周期内的 Windows 构建及具体编译器、SDK 版本。其他发行版、Windows Server、文件系统和 ARM64 通过验证后再加入。

| 能力 | Linux 计划 | Windows 计划 | 契约 |
| --- | --- | --- | --- |
| 服务生命周期 | systemd 适配；开发时前台运行 | Service Control Manager 适配；开发时控制台运行 | 正确启停和可恢复升级 |
| 原生协议服务 | PACE 与文件系统适配 | PACE 与文件系统适配 | 分别验证相同的已声明协议语义 |
| 文件与路径 | 句柄相对 POSIX 操作 | Win32/NT 句柄和 reparse point 检查 | 不假设路径与 ACL 行为相同 |
| CPU/内存/网络 | procfs/sysfs 与系统计数器 | Windows API 与性能计数器 | 包含单位、采样周期和新鲜度 |
| 磁盘清单与健康 | sysfs、块设备 API；可选 smartctl 适配 | Storage API/IOCTL；可选 smartctl 适配 | 区分权限、硬件和传输限制 |
| 硬配额 | 特定文件系统的配额适配 | 特定文件系统的配额适配 | 只声明验证过的模式 |
| 硬盘/RAID 管理 | Linux MD 与经过验证的卷/文件系统适配 | Storage Spaces 与经过验证的卷/文件系统适配 | M8b；原生能力和显式操作计划 |
| 快照 | 后续文件系统适配 | 后续 VSS 适配 | 独立后续特性 |
| 提权操作 | 受限辅助服务与最小权限 | 受限 Windows 服务与 ACL 保护的 IPC | 无任意 Shell 或用户提供的命令执行 |
| Docker 传输 | Unix-domain socket 或已批准 TLS 端点 | 命名管道或已批准 TLS 端点 | 需要正在运行的兼容 Engine |

标准协议端口可能与已有服务冲突，尤其是 Windows 原生 SMB。M0 必须在可丢弃宿主上验证 Windows SMB 监听部署方案。不承诺能在 TCP 445 上透明共存：替代端口可能要求特定客户端，独立地址也可能与通配监听冲突。需要管理员重配宿主服务时，应明确列为部署前提。

## 5. 监控与宿主管理

先提供只读清单：CPU 利用率、内存、网络吞吐、运行时间、文件系统容量、磁盘身份、可用的温度与健康数据，以及服务状态。区分物理磁盘、分区、卷、挂载和逻辑空间。优先使用稳定磁盘 ID，设备名称可能随重启变化。

每个样本包含时间、单位、来源、采集错误与新鲜度。USB 桥、RAID 控制器、虚拟磁盘和权限不足可能使 SMART/NVMe 信息不可读。报告 `unavailable`、`permission_denied` 或 `stale`，不能显示零温度或虚假健康。磁盘健康指标是观测值，不保证设备不会故障。

采集器具有超时、有界并发、可配置保留期和退避。健康规则涵盖容量阈值、连续采集失败、磁盘异常和协议故障。告警去重，通知连接器作为可选插件。管理变更审计与高流量指标、采样访问日志分开。

硬盘/RAID 管理纳入 M8b：拓扑、导入创建、替换重建、检查与受支持扩容；格式化、分区和挂载变更必须有显式计划。操作要求原生提供者验证、稳定设备 ID、管理员确认和恢复记录。保护系统盘与在用磁盘，安全条件未知时拒绝。见[运维设计](operations.zh-CN.md)。插件不能仅凭通用监控权限获得这些操作。

## 6. 特权辅助服务

通过经过认证的本地 IPC 定义类型化、白名单化请求：Linux 使用验证对端身份的 Unix-domain socket，Windows 使用 ACL 保护的命名管道。按已注册资源验证路径，并在辅助服务端重新检查权限。不接受任意可执行文件名、Shell 字符串或原始文件系统控制命令。

返回结构化错误，审计操作者、操作、目标和结果，设置超时与限速。面向网络的解析留在非特权 API/协议工作进程。辅助服务独立验证调用方身份、限定作用域的授权与已批准计划；进程分离本身不是安全边界。如果平台要求监听器本身提权，应说明并最小化这一例外，不能仍将其描述为完全最小权限。

## 7. 插件系统

使用独立工作进程和版本化、有界消息协议。清单声明 ID、版本、兼容宿主 API 范围、可执行文件或包摘要、入口、配置结构和请求权限。初始能力可包括发布指标、定时任务、受限文件服务调用以及已批准的外部集成。默认无权限。

监督器负责安装、显式启停、健康检查、崩溃退避、升级、回滚和卸载。除非另行请求，卸载保留用户数据。权限增加时，产品流程需要显式批准。验证包路径和来源；签名证明作者身份，不证明行为安全。

进程隔离提供故障隔离，不自动等于安全沙箱。发布不可信插件支持前，需通过操作系统限制文件访问、网络、子进程、凭据和资源。如果宿主尚未实现这些限制，将插件标为仅可运行可信代码，并禁止不可信安装。首个插件里程碑不承诺公开市场与热加载。

第一方协议仍是构建期组件，按协议家族部署在独立工作进程。不能允许插件通过申请所有托管存储的原始访问来绕过文件服务策略。

## 8. Docker 集成

第一方集成使用版本化 Docker Engine HTTP API，协商受支持范围。先提供引擎信息和容器、镜像、卷、网络清单，再提供统计、日志和显式生命周期动作。分别定义创建、重建与删除行为；Compose 导入、终端和任意 exec 是后续功能。[Docker Engine API](https://docs.docker.com/reference/api/engine/)

Docker 访问可能带来广泛宿主控制权。socket、管道或客户端凭据保留在专门集成边界内，变更操作仅对已授权管理员开放。不提供 Docker 通用 HTTP 代理。优先本地 socket/管道或双向认证 TLS，绝不自动暴露未认证 TCP 端点。[Docker daemon 访问](https://docs.docker.com/engine/security/protect-access/)

PACE TCP/HTTP 不自动提供 Unix-domain socket、Windows 命名管道、Docker hijacked stream 或异步流式客户端。M0/M8 需选择并验证平台传输适配器；先完成清单与生命周期 API，再处理交互流。

在 Windows 上区分 Windows 容器引擎和运行于 VM/WSL2 的 Linux 容器引擎。路径、bind mount、资源指标和文件系统访问属于实际引擎宿主。不能假设 Windows 路径能在 Linux 引擎内直接使用。引擎缺失时正常禁用集成，tauCloud 不自动安装或重配 Docker。

## 9. 恢复与发布依据

在线组件升级纳入 M8c，使用签名制品、并排暂存、受影响工作进程排空、健康检查与受约束回滚。兼容与恢复门槛见[运维设计](operations.zh-CN.md)。提供配置验证、各服务迁移前数据库备份、元数据恢复、卸载保留用户数据以及明确的升级回滚限制。恢复元数据不等于恢复文件内容。测试上传、授权更新、迁移和协议状态变更期间的重启，并拒绝不兼容的 schema 降级。

对外开放服务之前，完成威胁模型评审、解析器 fuzz、特权边界测试、凭据与秘密处理评审、真实客户端互操作以及崩溃恢复验证。记录依赖版本与许可证。这些属于交付自研文件协议服务器的必要工作，并不意味着清单能消除所有缺陷。
