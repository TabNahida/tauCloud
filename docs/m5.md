# M5 — Signed SMB 2.1 backend preview

This page records the M5 baseline. The current security/dialect extensions are in the [M6 guide](m6.md).

[简体中文](m5.zh-CN.md) · [Setup](m1.md) · [File authority](m2.md) · [Evidence](evidence/m5/README.md)

M5 adds the independently supervised `taucloud_smb` process, implemented in C++20 over PACE TCP/coroutines. It uses the existing identity and file services; Python, Samba and operating-system SMB servers are not runtime dependencies. This is a bounded loopback profile. The full Windows/Linux/macOS and Samba torture acceptance matrix remains open; exact results and exclusions are recorded separately.

## Configuration and credentials

Stop the supervisor, merge `"smb_port":4445` into the initialized `config.json`, and restart. Zero/omitted disables the listener. Ports must be 1024–65535, distinct from management, DAV and FTP control ports and an enabled FTP passive range. Bind address remains `127.0.0.1`. Existing state gains the SMB IPC key automatically. Identity schema 3 migrates to 4 with `identity.pre-v4.db`; file schema 2 migrates to 3 with `file*.pre-v3.db` backups.

Create a separate writable space and share using the M2 management API, for example:

```json
{"id":"documents","space":"alice-smb","exposures":{"smb":"rw"}}
```

`r` exposes read-only access. Local account names must be unambiguous ignoring ASCII case. Private ownership and team grants still apply; administrator status alone does not grant file access. SMB remains excluded from mixed writable protocol combinations. Updating a share requires the complete definition and `update:true`.

An administrator with an admin-scoped management session separately enrolls each existing enabled local account with `POST /api/v1/smb/credentials`:

```json
{"username":"alice","password":"a separate long SMB password"}
```

Send the JSON on standard input with `taucloud_ctl --state <state> call --method POST --path /api/v1/smb/credentials`. Do not put real passwords in command arguments. This does not change the management/FTP/DAV password. Re-enrollment replaces the SMB secret and invalidates existing SMB sessions. `{"username":"alice","enabled":false}` removes it. Browser writes retain Origin/CSRF checks. Responses never return hashes or vault keys.

Use a client with an explicit port option, signed SMB 2.1, local username `TAUCLOUD\alice`, and share `\\127.0.0.1\documents`. The test client is pinned in `tests/smb-requirements.txt`. Windows Explorer's ordinary UNC path does not express this alternative port. Standard-port deployment, remote binding and coexistence with the host's SMB service remain separate work: this implementation does not stop system services, modify firewall rules or claim port-445 acceptance.

## Authentication and confidentiality

Only NTLMv2 is accepted, with a fresh 8-byte challenge, 10-second one-use identity-service exchange, timestamp/target-info validation, mandatory MIC, and optional negotiated NTLM session-key exchange. Raw NTLM and SPNEGO envelopes are bounded. Every authenticated SMB packet is signed with HMAC-SHA256; all segments of a compound are checked before any mutation. Replay/credit-window violations close the connection. SMB1, guest/anonymous, NTLMv1, Kerberos, SMB2.0.2 and SMB3 are not enabled. SMB 2.1 signing provides integrity, **not encryption**.

SMB requires a password-equivalent NT hash, unlike the management Argon2id verifier. Only identity decrypts the hash. SQLite stores AES-256-GCM ciphertext bound to the account name. `smb-vault.json` holds a separate random key: Linux protects it with the private service state directory and mode 0600; Windows additionally wraps it with user-scoped DPAPI. The Windows service must retain its account/profile. Losing the key requires re-enrollment. Local administrators/service-account compromise are outside this at-rest boundary. OpenSSL supplies MD4, HMAC, RC4 key exchange and AES-GCM; legacy NTLM primitives do not change TLS provider policy.

Metadata backups omit the vault key and scrub enrolled SMB credentials and sessions; restore requires re-enrollment. Backups with unfinished delete intents are refused. Normal management password hashes remain included under the existing backup contract. Login limits remain 5 attempts/account/minute and 30 globally/minute, including successful authentication; SMB exchanges do not use a password-session cache.

## File and RPC profile

Supported operations: NEGOTIATE, SESSION_SETUP, LOGOFF, TREE_CONNECT/DISCONNECT, CREATE, CLOSE, FLUSH, READ, WRITE, LOCK, QUERY_DIRECTORY, QUERY_INFO, SET_INFO and ECHO. The negotiated maximum transaction/read/write payload is 64 KiB. CREATE supports ordinary file/directory dispositions and declines caching/durable contexts; no oplock, lease or durable-handle grant is issued. FLUSH and write-through requests flush native file data. Regular writes are immediately visible; they are not staged uploads. A failed/disconnected writer may leave a partial file. Whole-file atomic replacement remains the core/DAV/FTP staged-upload contract.

The file authority enforces bidirectional read/write/delete share modes, mandatory shared/exclusive byte-range locks, quota, access masks, object identity and path confinement. LOCK vectors are atomic; exact-range unlock is supported. Locks require FAIL_IMMEDIATELY; queued blocking locks are not supported. Directory enumeration is snapshotted per open, with restart/single-entry and bounded wildcard matching (`*`, `?`, `*.*`). Names use UTF-16 on the wire and the existing portable UTF-8 NFC rules internally; no ADS, links, reparse traversal or case-only aliases.

SET_INFO supports EOF/truncate, rename and delete disposition. Rename stays within one share, updates live handle paths, and can replace a closed regular file. Moving a directory with open descendants is explicitly rejected on both hosts because pinned Windows parent handles prohibit that move. Delete is nonrecursive and requires an empty directory. Pending deletion denies new opens and executes after the final close. Native object identity plus a durable intent protects restart recovery from deleting a replacement object. Pending-delete subtrees cannot be renamed. Share roots cannot be deleted or moved.

File metadata queries cover basic/standard/internal/EA/access/name/position/mode/alignment/all/network-open/attribute-tag and the unnamed data stream; directory classes 1, 2, 3, 12, 37 and 38; filesystem volume, size/full-size, device and attribute information. File attributes are the conservative directory/archive projection. Creation/access/change fields currently use the observed modification time; they are not distinct native timestamp promises. Basic-attribute/timestamp writes, extended attributes, security descriptor queries/updates, persistent Windows ACLs, POSIX ACL passthrough, change notification, hardlinks and alternate streams are unsupported. No persistent-ACL filesystem capability is advertised, and unsupported mutations fail explicitly. Policy remains the access authority on both hosts.

`IPC$` exposes only authenticated `srvsvc`: bounded DCE/RPC bind to MS-SRVS v3 with NDR32, and NetrShareEnum level 1, including bounded resume pagination. Each returned share must pass current SMB authorization; private and non-SMB shares do not leak through an administrator listing. Named-pipe READ/WRITE and FSCTL_PIPE_TRANSCEIVE are implemented. No anonymous IPC, NDR64, fragmented/authenticated DCE PDUs, general RPC endpoint mapper, SAMR, LSARPC or other administrative RPC interface is exposed. Unsupported IOCTLs fail; this is not a general Windows RPC server.

## Revocation, isolation and bounds

Each file operation obtains a fresh, short identity grant. Disabling the user, removing credentials, changing share rights or policy revokes access. Cleanup-only signed grants may close owned handles after expiry/revocation, including after a rename; they cannot authorize fresh data access. Policy push closes file-authority handles. Accepted deletion intents remain committed operations and may finish during revocation cleanup.

The SMB process ownership lock fences its predecessor before startup recovery reclaims SMB handles and pending deletions in all file workers. Sibling services and their handles survive a protocol restart. A file-worker restart makes old handles stale; clients reconnect. Durable reconnect and transparent failover are not claimed. A native rename is atomic; file-index scanning reconciles a crash before the subsequent index update. Partially failed writes retain the core's uncertain-operation behavior.

| Resource | Bound |
| --- | --- |
| Connections / blocking executor | min(configured, 32) / 4 threads, queue 32 |
| TCP frame / compound | 1 MiB / 16 segments |
| Credits / request execution | bounded window up to 64; sequential per connection |
| Session / tree / open | one authenticated session per connection; 16 trees; 64 opens |
| File authority | 128 handles and 256 locks per worker |
| Directory snapshot | 1024 entries and 256 KiB serialized metadata |
| Authentication / framed body / response write | 10 seconds / 5 seconds / 5 seconds |
| Authenticated idle / internal session | 60 seconds / 1 hour |
| NTLM pending exchanges / token | 64 / 16 KiB |
| RPC shares / presentation contexts | 64 / 4 |

No multi-channel, SMB encryption, DFS, compression, POSIX extensions, async notification or durable handles are advertised. Operations exceeding bounds fail explicitly. Host-side external writers can still bypass service quota/locks, as documented in M2.

## Reproduce

```sh
python3 -m venv .deps/smbprotocol-venv
.deps/smbprotocol-venv/bin/python -m pip install -r tests/smb-requirements.txt
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler gcc --large-mib 17
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler clang --mode debug --sanitizers
```

On Windows, use the same pinned requirements in a virtual environment and `scripts/run_m5.py --compiler msvc`, or `scripts/windows_m5.ps1` for a disposable NTFS checkout from WSL. The runner includes M1–M5 regression; optional `--litmus` exercises M3. Data and listeners are disposable. See the [evidence](evidence/m5/README.md) for the tested subset and outstanding client matrix.
