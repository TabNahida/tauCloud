This page records the M5 baseline. The current security/dialect extensions are in the [M6 guide](m6.md).

[简体中文](m5.zh-CN.md) · [Setup](m1.md) · [File authority](m2.md) · [Evidence](evidence/m5/README.md)

M5 adds the independently supervised `taucloud_smb` process, implemented in C++20 over PACE TCP/coroutines. It uses the existing identity and file services; Python, Samba and operating-system SMB servers are not runtime dependencies. This is a bounded loopback profile. The selected Windows/Linux/macOS client and applicable Samba matrix now passes: 60 torture selectors / 76 cases, with exclusions mapped in [the applicability report](smb-torture-coverage.md) and fixed commits in [the acceptance record](evidence/pre-m8/README.md). This is not full Windows-server feature equivalence.

## Configuration and credentials

Stop the supervisor, merge `"smb_port":4445` into the initialized `config.json`, and restart. Zero/omitted disables the listener. Ports must be 1024–65535, distinct from management, DAV and FTP control ports and an enabled FTP passive range. Bind address remains `127.0.0.1`. Existing state gains the SMB IPC key automatically. Identity schema 3 migrates to 4 with `identity.pre-v4.db`; file schema 2 migrates to 3 with `file*.pre-v3.db` backups.

Create a separate writable space and share using the M2 management API, for example:

```json
{"id":"documents","space":"alice-smb","exposures":{"smb":"rw"}}
```

`r` exposes read-only access. Local account names must be unambiguous ignoring ASCII case. Private ownership and team grants still apply; administrator status alone does not grant file access. SMB remains excluded from mixed writable protocol combinations. Updating a share requires the complete definition and `update:true`.

An administrator with an admin-scoped management session separately enrolls each existing enabled local account with `POST /api/v1/smb/credentials`:

```json
{"username":"alice","password":"a separate long SMB password"}
```

Send the JSON on standard input with `taucloud_ctl --state <state> call --method POST --path /api/v1/smb/credentials`. Do not put real passwords in command arguments. This does not change the management/FTP/DAV password. Re-enrollment replaces the SMB secret and invalidates existing SMB sessions. `{"username":"alice","enabled":false}` removes it. Browser writes retain Origin/CSRF checks. Responses never return hashes or vault keys.

Use a client with an explicit port option, signed SMB 2.1, local username `TAUCLOUD\alice`, and share `\\127.0.0.1\documents`. The test client is pinned in `tests/smb-requirements.txt`. Windows Explorer's ordinary UNC path does not express this alternative port. Standard-port deployment, remote binding and coexistence with the host's SMB service remain separate work: this implementation does not stop system services, modify firewall rules or claim port-445 acceptance.

## Authentication and confidentiality

Only NTLMv2 is accepted, with a fresh 8-byte challenge, 10-second one-use identity-service exchange, at most five minutes of response clock skew and exact echoed target-info validation, mandatory MIC, and optional negotiated NTLM session-key exchange. Raw NTLM and SPNEGO envelopes are bounded. Every authenticated SMB packet is signed with HMAC-SHA256; all segments of a compound are checked before any mutation. Replay/credit-window violations close the connection. SMB1, guest/anonymous, NTLMv1, Kerberos, SMB2.0.2 and SMB3 are not enabled. SMB 2.1 signing provides integrity, **not encryption**.

SMB requires a password-equivalent NT hash, unlike the management Argon2id verifier. Only identity decrypts the hash. SQLite stores AES-256-GCM ciphertext bound to the account name. `smb-vault.json` holds a separate random key: Linux protects it with the private service state directory and mode 0600; Windows additionally wraps it with user-scoped DPAPI. The Windows service must retain its account/profile. Losing the key requires re-enrollment. Local administrators/service-account compromise are outside this at-rest boundary. OpenSSL supplies MD4, HMAC, RC4 key exchange and AES-GCM; legacy NTLM primitives do not change TLS provider policy.

Metadata backups omit the vault key and scrub enrolled SMB credentials and sessions; restore requires re-enrollment. Backups with unfinished delete intents are refused. Normal management password hashes remain included under the existing backup contract. Failed-login budgets remain 5/account/minute and 30 globally/minute; verified logins do not consume the budget or clear prior failures; SMB exchanges do not use a password-session cache.

## File and RPC profile

Supported operations: NEGOTIATE, SESSION_SETUP, LOGOFF, TREE_CONNECT/DISCONNECT, CREATE, CLOSE, FLUSH, READ, WRITE, LOCK, QUERY_DIRECTORY, QUERY_INFO, SET_INFO and ECHO. The negotiated maximum transaction/read/write payload is 64 KiB. CREATE supports ordinary file/directory dispositions and declines caching/durable contexts; no oplock, lease or durable-handle grant is issued. FLUSH and write-through requests flush native file data. Regular writes are immediately visible; they are not staged uploads. A failed/disconnected writer may leave a partial file. Whole-file atomic replacement remains the core/DAV/FTP staged-upload contract.

The file authority enforces bidirectional read/write/delete share modes, mandatory shared/exclusive byte-range locks, quota, access masks, object identity and path confinement. Lock acquisition vectors are atomic. Unlock vectors commit each successful exact-range unlock in order, stopping at the first error. Zero-length locks and the final uint64 byte are supported; shared locks may stack on the same open. Contended single-range requests without FAIL_IMMEDIATELY enter a bounded FIFO queue in the file authority. Disjoint ranges and compatible readers proceed; later conflicting readers cannot starve a queued writer. The reactor sends STATUS_PENDING with a nonzero AsyncId, continues reading requests, and sends one signed/encrypted final response without granting credits twice. CANCEL matches AsyncId or MessageId and returns STATUS_CANCELLED for the target only. Closing an open abandons its ungranted ranges with STATUS_RANGE_NOT_LOCKED; tree/session teardown, disconnect, credential revocation and SMB recovery remove waiters. A cooperative dispatcher gate keeps retries, cancellation, cleanup and socket writes ordered; final completions in LOCK/CLOSE compounds follow the interim response. Retries refresh authorization every poll (20 ms nominal interval, subject to bounded RPC scheduling). Directory enumeration preserves per-open cookies while refreshing metadata and suppressing removed/replaced entries, with restart/index/single-entry and bounded wildcard matching (`*`, `?`, `*.*`). Names use UTF-16 on the wire and the existing portable UTF-8 NFC rules internally; no ADS, links, reparse traversal or case-only aliases.

SET_INFO supports basic timestamps/DOS attributes, extended attributes, EOF/truncate, rename and delete disposition. Rename stays within one share, updates live handle paths, and can replace a closed regular file. Moving a directory with open descendants is explicitly rejected on both hosts because pinned Windows parent handles prohibit that move. Delete is nonrecursive and requires an empty directory. Pending deletion denies new opens and executes after the final close. Native object identity plus a durable intent protects restart recovery from deleting a replacement object. Pending-delete subtrees cannot be renamed. Share roots cannot be deleted or moved.

File metadata queries cover basic/standard/internal/EA/access/name/position/mode/alignment/all/network-open/attribute-tag and the unnamed data stream; directory classes 1, 2, 3, 12, 37 and 38; filesystem volume, size/full-size, device and attribute information. DOS readonly/hidden/system/archive/temporary/offline/not-content-indexed attributes persist by native incarnation, including rename and restart. FileBasicInformation carries distinct creation/access/write/change times; access/write updates reach native handles, while portable creation/change projections preserve native incarnation identity. Explicit timestamps and -1 freeze automatic updates for that handle; -2 re-enables them. Current native access/write conversion accepts Unix-epoch through INT64 nanoseconds; the full wire date range remains open. Extended attributes support bounded ASCII names and binary values through ExtA CREATE, full query and SET_INFO, case-insensitive updates and empty-value deletion; per-open cursor, restart, single-entry and indexed queries return only complete entries with buffer overflow/retry semantics. Selected-name FILE_GET_EA_INFORMATION queries preserve request order, match case-insensitively, ignore index/restart flags and do not advance the scan cursor. Absent names have empty values. Non-ASCII EA names remain open. EAs are bounded to 256 names and 65,531 aggregate bytes (the FileEaInformation size) per file. EA SET atomically updates archive/change time, respects per-open change-time freezing, and rolls back an oversized update. Invalid names and inconsistent entry chains return their distinct standard status codes. FileAllocationInformation now reserves native storage without extending EOF, uses native cluster rounding on shrink, and reports native allocation size. Quota charges the greater of logical EOF and requested reservation bytes, so later writes within the reservation are not charged twice; this is a logical service quota, not a physical-block quota. The logical quota reservation persists across restart even when the host filesystem trims physical preallocation on close (as NTFS may do); native QUERY_INFO reports that trimming, and allocation SET/shrink or deletion releases the logical reservation. It does not guarantee physical space retention after close. Reservations persist in file schema 5; schema 4 upgrades retain a `.pre-v5.db` backup. Failed or interrupted allocation conservatively retains the higher reservation until a successful allocation retry/shrink or deletion. FileModeInformation is per open; WRITE_THROUGH flushes before acknowledging writes, SEQUENTIAL_ONLY is a hint, and synchronous CREATE flags are ignored as required by SMB2. AlSi CREATE contexts reserve storage for new/overwritten regular files, leaving EOF at zero; ordinary existing opens and directories ignore the requested allocation. Invalid initial EA aggregates and quota failures are rejected before namespace/data mutation. Failed native allocation during a new CREATE removes that file after checking its identity and releases its quota. Overwrites check native capacity before truncation but remain non-atomic: a later truncation/flush/final allocation failure can leave a partial overwrite. The native unbuffered-I/O contract remains open. Security descriptors/ACLs, short names, streams, links and notifications remain unfinished. No persistent-ACL capability is advertised. See [expanded compatibility work](../TODO.md) and [metadata evidence](evidence/pre-m8/metadata-expansion-local.json) and [allocation/mode regression](evidence/pre-m8/allocation-expansion-local.json).

`IPC$` exposes only authenticated `srvsvc`: bounded DCE/RPC bind to MS-SRVS v3 with NDR32, and NetrShareEnum level 1, including bounded resume pagination. Each returned share must pass current SMB authorization; private and non-SMB shares do not leak through an administrator listing. Named-pipe READ/WRITE and FSCTL_PIPE_TRANSCEIVE are implemented. No anonymous IPC, NDR64, fragmented/authenticated DCE PDUs, general RPC endpoint mapper, SAMR, LSARPC or other administrative RPC interface is exposed. Unsupported IOCTLs fail; this is not a general Windows RPC server.

## Revocation, isolation and bounds

Each file operation obtains a fresh, short identity grant. Disabling the user, removing credentials, changing share rights or policy revokes access. Cleanup-only signed grants may close owned handles after expiry/revocation, including after a rename; they cannot authorize fresh data access. Policy push closes file-authority handles. Accepted deletion intents remain committed operations and may finish during revocation cleanup.

The SMB process ownership lock fences its predecessor before startup recovery reclaims SMB handles and pending deletions in all file workers. Sibling services and their handles survive a protocol restart. A file-worker restart makes old handles stale; clients reconnect. Durable reconnect and transparent failover are not claimed. A native rename is atomic; file-index scanning reconciles a crash before the subsequent index update. Partially failed writes retain the core's uncertain-operation behavior.

| Resource | Bound |
| --- | --- |
| Pending SMB locks | 16 per connection / 256 per file authority; one range per blocking request |
| Connections / blocking executor | min(configured, 32) / 4 threads, queue 32 |
| TCP frame / compound | 1 MiB / 16 segments |
| Credits / request execution | up to 8192 unspent credits; coordinated commands and lock retries |
| Session / tree / open | one authenticated session per connection; 16 trees; 64 opens |
| File authority | 128 handles and 256 locks per worker |
| Directory snapshot | 1024 entries and 256 KiB serialized metadata |
| Authentication / framed body / response write | 10 seconds / 5 seconds / 5 seconds |
| Authenticated idle / internal session | 60 seconds (pending locks keep the connection alive) / 1 hour |
| NTLM pending exchanges / token | 64 / 16 KiB |
| RPC shares / presentation contexts | 64 / 4 |

No multi-channel, DFS, compression, POSIX extensions, async notification or durable handles are advertised. SMB3 encryption is provided by the M6 extensions. Operations exceeding bounds fail explicitly. Host-side external writers can still bypass service quota/locks, as documented in M2.

## Reproduce

```sh
python3 -m venv .deps/smbprotocol-venv
.deps/smbprotocol-venv/bin/python -m pip install -r tests/smb-requirements.txt
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler gcc --large-mib 17
.deps/smbprotocol-venv/bin/python scripts/run_m5.py --compiler clang --mode debug --sanitizers
```

On Windows, use the same pinned requirements in a virtual environment and `scripts/run_m5.py --compiler msvc`, or `scripts/windows_m5.ps1` for a disposable NTFS checkout from WSL. The runner includes M1–M5 regression; optional `--litmus` exercises M3. Data and listeners are disposable. See the [evidence](evidence/m5/README.md) for the tested subset and outstanding client matrix.

Protocol references: [MS-SMB2 CREATE](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/e8fb45c1-a03d-44ca-b7ae-47385cfd7997), [MS-NLMP response/MIC validation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/34a9417d-7cc0-43b0-b61c-1f19740df66f), [MS-NLMP client MIC behavior](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/c0250a97-2940-40c7-82fb-20d208c71e96).

Native-client correction: the NTLMv2 response timestamp may come from the client clock (including Heimdal second precision). It is checked against server time within five minutes, not required to equal the challenge timestamp byte-for-byte. The echoed target-info timestamp, one-use 10-second challenge, NT proof and transcript MIC are still validated. Regression probes recompute valid proof/MIC for positive/negative clock skew and require rejection beyond the window. See [MS-NLMP server response checking](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-nlmp/34a9417d-7cc0-43b0-b61c-1f19740df66f).

SMB share names are matched without case sensitivity while retaining canonical policy IDs. Case-colliding SMB publications are rejected; existing ambiguous SMB records fail closed. Non-SMB exposures do not shadow an SMB share, and their protocol naming rules are unchanged. Missing SMB shares return STATUS_BAD_NETWORK_NAME.

SMB credits use a bounded minimum-one/maximum-8192 policy; NEGOTIATE no longer grants 32 when only one was requested. Requests for an unknown session return STATUS_USER_SESSION_DELETED without executing them or borrowing the valid session authority. The valid session remains usable; malformed framing, replay and invalid signatures for a known session still disconnect. All known-session signatures in a compound are checked before side effects.

Credit/session references: [MS-SMB2 credit grants](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/2e366edb-b006-47e7-aa94-ef6f71043ced) and [session validation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/b495e2da-8711-4772-b292-453be0394b49).

Standard FILE_ALL_ACCESS and generic/maximum access map to the application grant; DELETE_CHILD/WRITE_DAC/WRITE_OWNER requests still require a writable grant. Accepting these rights does not enable unsupported persistent security-descriptor mutations. FILE_EXECUTE permits reads without changing the returned granted-access mask. Metadata-only opens do not constrain data sharing. Directory READ returns INVALID_DEVICE_REQUEST, and file position queries track the last successful I/O. The original Samba read, sharing, lock-range, directory deletion-between-pages and 8191-write credit tests now have passing local evidence.

CREATE QFid replies expose the same stable object identifier as FileInternalInformation and a stable native volume identifier. Compound inheritance applies only to related requests; failed CREATE inherits its status, whereas a failed WRITE does not prevent a later valid READ/CLOSE. Sessionless ECHO remains valid after LOGOFF. Missing-session errors preserve the request SIGNED flag with a zero signature, without using another session key. See [local contract evidence](evidence/pre-m8/smb-nfs-contract-local.json).

Metadata behavior is checked against [MS-FSCC FileBasicInformation](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/16023025-8a78-492f-8b96-c873b042ac50), [MS-FSA basic information handling](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fsa/a36513b4-73c8-4888-ad29-8f3a196567e8), and [MS-SMB2 ExtA handling](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/1bd91aea-18d3-468a-92b8-c6ad247761cd). The remaining limits above are not standards-conformance passes.

CREATE allocation and EA selection follow [MS-SMB2 AlSi](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/3f343618-01b0-4aaf-b8a3-b270f9a6d334), [native CREATE allocation semantics](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntifs/nf-ntifs-ntcreatefile), [EA query selection](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/d64e0451-64a2-425a-848e-52a7dddab7b9) and [FILE_GET_EA_INFORMATION](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-fscc/79dc1ea1-158c-4b24-b0e1-8c16c7e2af6b).

MxAc CREATE responses report maximal access under current application policy and DOS readonly restrictions, independently of the requested open access and cached tree write permissions. Optional timestamps compare against ChangeTime and return STATUS_NONE_MAPPED/zero when unchanged. Multiple response contexts (MxAc and QFid) are chained with aligned offsets. This follows [MS-SMB2 maximal-access processing](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-smb2/828a4d2d-0c9b-4c1c-8d2b-cc474172baa5); persistent Windows ACL evaluation remains unfinished.

The Full SMB/NFS expansion adds `tests/smb_blocking_locks.py`: four signed/encrypted dialects, fairness, cancellation, close/disconnect/revocation, compounds, limits and concurrent CANCEL/CLOSE versus unlock. `m5_core` now checks authority queue ownership, immutable retry ranges and cleanup. The unmodified Samba `lock.async`, `lock.cancel`, `lock.cancel-tdis` and `lock.cancel-logoff` cases join the executable regression selection. This completes a blocking-lock implementation increment; durable/replay locks, leases and full SMB/NFS compatibility remain separate unfinished gates. Fixed-source remote evidence is recorded in the [acceptance index](evidence/pre-m8/README.md).

At `03ca0f4`, [GCC, Clang ASan/UBSan and Windows MSVC acceptance](evidence/pre-m8/smb-blocking-03ca0f4-remote.json) all pass: 113 SMB core checks and 27/25/25 blocking-lock groups respectively. The GCC-only timing checks hold a lock for 65 seconds, deliver a fragmented encrypted request across the old idle deadline, and verify normal idle expiry afterward. Both Linux jobs also pass the four unmodified Samba async/cancel cases. Full M5/M7 compatibility remains open.
